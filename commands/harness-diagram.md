이 명령은 다이어그램을 **직접 그리지 않는다.** `diagram-design` 스킬 같은 외부 도구를 부르되,
그 앞뒤에 **하네스 규약을 주입**하는 어댑터다. 상류 스킬을 직접 호출하면 산출물 경로도,
inline SVG 제약도, 생성물 지위도, artifact 기록 의무도 하나도 적용되지 않는다.
`harness-codex-review`가 `codex exec`에 대해 하는 일과 같은 역할이다.

이 하네스는 다이어그램 스킬을 **소유하지도 번들하지도 않는다.** 마켓플레이스에 커밋 sha로 핀을 건
**동반 플러그인**으로 등재만 되어 있으며(README "동반 플러그인" 절), 설치는 **선택 사항**이다.
없어도 하네스는 정상 동작한다.

핵심 제약:

- **옵트인 계약의 정본은 `commands/harness-task.md`의 "spec/plan 다이어그램 옵트인" 절이다.**
  질문 시점(신규 생성 1회), plan 체크박스가 곧 상태라는 규칙, 건너뛴 단계를 지우지 않고 닫는 형식,
  산출물 경로와 inline SVG 제약, 기록 의무는 모두 거기에 적혀 있다. 이 문서는 그것을 **복제하지 않고**
  참조하며, 그 절이 다루지 않는 **실행**만 다룬다.
- **task를 임의로 만들지 않는다.** 활성 task가 없으면 그 사실을 보고하고 멈춘다.
- **도구가 없다고 실패시키지 않는다.** probe → degrade → record.
- **손으로 대신 그리지 않는다.** 도구가 없을 때 인라인 SVG를 직접 작성해 채우면 옵트인의 의미가 사라진다.

Raw slash-command 인수:
`$ARGUMENTS`

인수 해석: `--force`는 plan에 다이어그램 단계가 없어도(= 옵트아웃했거나 애초에 묻지 않은 task)
확인 질문 없이 진행한다. 나머지 토큰은 이번 다이어그램에서 특히 드러내고 싶은 focus 문구로
상류 스킬에 그대로 전달한다.

## 실행 절차

1. **활성 task 확인** — `.harness/active.json`이 가리키는 task와 그 디렉터리 `docs/<user>/<name>/`를
   확인한다. 활성 task가 없으면 산출물을 놓을 곳이 없다는 사실을 보고하고 멈춘다.

2. **옵트인 상태 확인** — `<name>-plan.md`에 다이어그램 단계가 있는지 본다.
   - 있으면 그대로 진행한다.
   - 없으면 이 task는 옵트아웃 상태다. `AskUserQuestion`으로 한 번 확인하고, 사용자가 진행을
     택하면 `commands/harness-task.md` 2번의 형식으로 plan에 단계를 **먼저 추가**한 뒤 진행한다.

   `--force`는 **질문만** 건너뛴다 — plan 단계 추가는 건너뛰지 않는다. 산출물은 있는데 plan에는
   그 단계가 없는 상태를 만들면 "plan.md가 곧 상태"라는 계약이 깨지기 때문이다.

   다른 하네스 커맨드(예: `/harness-ship`)가 이미 사용자에게 물어보고 이 어댑터에 위임하는
   경우에는 `--force`로 호출한다. 한 번의 사용자 의사에 두 번 묻지 않는다.

3. **입력 수집** — `<name>-spec.md`(요구사항·Ontology·경계)와 `<name>-plan.md`(단계)를 읽는다.
   다이어그램은 spec의 모호성을 드러내는 도구이므로, 그리기 전에 **무엇을 드러내려는지**를 한 줄로
   정한다: 구성요소 관계인가, 상태 전이인가, 단계 흐름인가. 정하지 못하면 그리지 말고 사용자에게 묻는다.

4. **Probe** — 다이어그램 스킬(`/diagram-design:diagram-design` 등)이 이 세션에 노출되는지 확인한다.
   설치 명령을 단정해 안내하지 않는다 — 해당 플러그인이 이 머신에 설치·활성화되어 있는지 확인하도록
   안내한다. 설치 경로가 필요하면 README "동반 플러그인" 절을 가리킨다.

5. **Degrade** — 스킬이 없거나 호출이 실패하면 **이 명령을 실패로 만들지 않는다.** 다이어그램만
   건너뛰고 7번(기록)으로 간다. plan의 단계는 지우지 말고 `commands/harness-task.md` 4번의 형식으로 닫는다.

6. **생성** — 스킬이 있으면 호출하되, 프롬프트에 아래 하네스 제약을 **명시적으로 실어** 보낸다.
   상류 스킬은 하네스 규약을 모른다:
   - 출력 파일: `docs/<user>/<name>/<name>-diagram.html` (활성 task 기준, 파일 하나)
   - 형식: **자립형 inline SVG HTML**. 런타임 JS 다이어그램(mermaid 등) 금지 — `docs/`는 Obsidian
     볼트에서 열리고 Obsidian은 script를 제거하므로 볼트에서 렌더되지 않는다.
   - 외부 자산 참조 금지(CDN 스크립트·원격 이미지·외부 폰트). 한 파일로 열려야 한다.
   - **기본값이 아니라 요구사항이다.** `commands/harness-task.md` 5번이 이 형식을 조건 없이 요구한다.
     뷰어가 script를 실행하는 것이 확실한 프로젝트에서만 예외가 성립하며(`commands/harness-ship.md`
     6번과 같은 예외), 그때는 **어느 뷰어에서 확인했는지와 판단 근거를 artifact에 남긴다.** 근거를
     남기지 않는 예외는 없다.

   이미 파일이 있으면 새로 만들지 말고 갱신한다. 만들었으면 plan의 해당 단계를 `- [x]`로 닫는다. 산출물은 `<name>-meta.json`·`<name>-context.md`와
   마찬가지로 **SSOT 4파일이 아닌 생성물**이며, 없어도 task는 유효하다.

7. **기록** — 실행했든 건너뛰었든 `<name>-artifact.md`에 날짜와 함께 한 줄 남긴다.
   기록하지 않으면 나중에 "묻지 않은 것"과 "묻고 건너뛴 것"을 구분할 수 없다.

   ```markdown
   - 다이어그램: docs/chad/auth-redesign/auth-redesign-diagram.html 생성 (2026-08-21)
   - 다이어그램: 미실행 — 도구 없음 (2026-08-21)
   ```

8. **보고** — 산출물 경로(또는 미실행 사유), 무엇을 드러낸 다이어그램인지, plan 단계 처리 결과를
   한 화면으로 보고하고 멈춘다.

## 예시

```bash
# 활성 task와 산출물 경로 확인
cat .harness/active.json
ls docs/chad/auth-redesign/
```

task 생성 시점의 옵트인 질문·plan 단계 추가는 `harness-team task <name>` 절차(`/harness-task`)가
담당한다. 이 명령은 그 뒤 아무 때나 실행해 산출물을 만들거나 갱신한다.
