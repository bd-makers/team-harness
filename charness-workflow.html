🛠 Public Skills

Claude Code: /charness:<skill>  |  Codex: $charness:<skill>
1 · Shape the Work
아이디어를 구체적인 구현 계약으로 발전시키는 단계
gather SHAPE

Slack 스레드, Notion 페이지, Google Docs, GitHub 콘텐츠, 임의 URL 등 외부 소스를 일회성 요약이 아닌 영속적인 로컬 지식 자산으로 변환합니다. 이미 존재하는 자산은 새로 만들지 않고 소스 ID가 일치하면 인플레이스 업데이트합니다. 결과 범위는 실제 요청에 맞게 한정됩니다.

언제: 외부 정보를 세션 간에 유지되는 지식으로 보존하고 싶을 때
ideation SHAPE

제품·시스템·워크플로우 개념이 아직 형성 중일 때, 대화를 통해 아이디어를 발전시킵니다. 검증된 사실과 가정을 분리하고, 수요·현상 유지·wedge·moat를 초기에 검증합니다. 에이전트·API·CLI·인터페이스 선택을 1급 설계 제약으로 다룹니다. 외부 맥락이 필요하면 gather로 자동 라우팅됩니다.

언제: 요청이 아직 형태가 없고 목표는 모호한 개념을 구체화하는 것일 때
spec SHAPE

개념을 살아있는 구현 계약서로 전환합니다. ideation 아티팩트나 기존 설계 문서를 현재 빌드 계약으로 정제하고, 지금 고정할 사항과 구현 중에 탐색할 사항을 결정합니다. 테스트 가능한 성공 기준을 정의하며, impl이 새로운 사실을 발견하면 계약을 동기화합니다.

언제: 재발견 없이 구현이 진행될 수 있을 만큼 빌드 계약을 명확히 해야 할 때
2 · Build & Repair
계약서를 코드로 전환하고, 버그를 제거하며, 변경 전 위험을 검토하는 단계
impl BUILD

작업을 코드·설정·테스트·운영자 대상 아티팩트로 전환합니다. 현재 구현 계약이 있으면 소비하고, 없으면 인라인으로 작은 정직한 계약을 자동으로 만듭니다. 가장 작은 의미있는 슬라이스를 구현하고 공격적으로 검증합니다. 현실이 계약을 바꾸면 계약을 동기화합니다.

언제: 계약서를 실제 코드로 옮기는 작업을 시작할 때
debug BUILD

버그·오류·예상치 못한 동작을 조사합니다. 반증 가능한 가설 없이 수정으로 건너뛰지 않는 훈련된 근본 원인 워크플로우를 따릅니다. 향후 세션이 학습 내용을 상속할 수 있도록 영속적인 디버그 아티팩트를 보존합니다.

언제: 잘못된 동작을 이해하고 해결하는 것이 목표일 때
critique BUILD

비자명한 설계 결정, 코드 변경, 릴리즈, 이름 변경, 삭제, 스펙, 워크플로우 변경에 대해 변경이 확정되기 전에 사전 비판을 수행합니다. 다양한 실패 각도를 탐색한 후, 실제 blocker와 과도한 걱정을 분리하는 반론 패스를 실행합니다.

언제: 중요한 변경 전에 독립적인 검토가 필요할 때
3 · Raise Quality
레포의 품질 수준을 높이고 작업 패턴을 개선하는 단계
quality QUALITY

레포의 현재 품질 수준을 이해하고 개선합니다. 기존 게이트를 감지하고 실행하며, 개념 무결성·테스트 신뢰도·보안 상태를 점검합니다. 단순히 누락된 것을 불평하는 대신 구체적인 다음 게이트를 제안합니다. 하나의 버그나 고립된 테스트가 아닌, 전반적인 품질 자세를 다룹니다.

언제: 레포 전체 품질 상태를 점검하거나 다음 품질 기준을 설정할 때
retro QUALITY

의미있는 작업 단위 완료 후 회고를 수행합니다. 무슨 일이 있었는지, 어떤 낭비가 발생했는지, 어떤 결정이 중요했는지, 어떤 전문가 관점이나 직접적 반사실이 다음 행동을 바꿨을지, 어떤 워크플로우·기능·메모리 개선이 다음 세션을 더 낫게 만들지를 검토합니다. 컨텍스트에서 자동으로 session 또는 weekly 모드를 선택합니다.

언제: 의미있는 작업 단위가 완료됐거나 사용자가 명시적으로 회고를 요청할 때
4 · Communicate Across Boundaries
인간과 에이전트 경계를 넘어 맥락과 작업을 전달하는 단계
narrative COMMUNICATE

레포의 소스 오브 트루스 문서와 현재 제품·프로젝트 스토리를 함께 정렬합니다. 먼저 영속적인 narrative를 다듬은 뒤, 압축된 handoff 아티팩트가 도움이 될 때 청중 중립적인 brief 스켈레톤을 도출합니다.

언제: 레포 문서와 실제 제품 스토리를 다시 정렬할 때
announcement COMMUNICATE

릴리즈 노트 스타일 요약이나 채팅용 업데이트 등 인간 대상 레포 변경 커뮤니케이션을 작성하고 전달합니다. 초안 가치가 먼저이며, 전달 방식·청중·생략 정책은 어댑터가 담당합니다.

언제: 최근 작업에 대한 외부 공개용 커뮤니케이션이 필요할 때
handoff COMMUNICATE

다음 세션이 컨텍스트를 재파생하지 않고 바로 이어받을 수 있도록 준비합니다. handoff를 짧고, 최신 상태이며, 운영적으로 유용하게 유지합니다. handoff 트리거에 언급된 워크플로우를 계속하라는 지시로 pickup을 처리합니다.

언제: 다음 세션을 준비하거나 handoff 아티팩트를 업데이트할 때
hitl COMMUNICATE

자동 검토로 충분하지 않을 때, 의도적인 인간 판단을 제한된 검토 루프에 삽입합니다. 검토 상태를 재개 가능하고, 청크 단위로 유지하며, 하나의 런타임을 하드코딩하지 않고 어댑터로 처리합니다. Human-In-The-Loop 패턴의 구조화된 구현입니다.

언제: 인터랙티브 검토, 승인 기반 변경, 단계별 인간 확인이 필요할 때
issue COMMUNICATE

현재 컨텍스트에서 GitHub 이슈를 파일링하거나 종단간 해결합니다. 이슈 생성 시 해결책 제안 전에 관찰된 문제를 먼저 보고합니다. 이슈 해결은 GitHub를 진실의 소스로 취급하고, 버그 클래스 이슈의 경우 수정 설계 전에 인과 관계 검토를 실행합니다.

언제: 에이전트가 GitHub 이슈를 파일링하거나 해결하게 하고 싶을 때
5 · Operate the Harness
charness 자체를 설치·확장·관리하는 메타 단계
setup OPERATE

레포의 초기 운영 표면을 생성하거나 정규화합니다. 그린필드 레포에는 최소한의 ideation에서 README, AGENTS.md, CLAUDE.md 심링크 정책, 로드맵, 운영자 수용 문서를 부트스트랩합니다. 부분적으로 초기화된 레포는 품질 검토나 깊은 제품 ideation이 이미 완료됐다고 가장하지 않고 동일한 표면을 재정렬합니다.

언제: 레포에 처음 charness를 도입하거나 운영 표면을 수리·정규화할 때
find-skills OPERATE

어떤 스킬, 지원 기능, 통합이 특정 태스크를 처리해야 하는지 찾습니다. X skill, X 스킬, support/X, X integration과 같이 이름을 언급할 때 사용합니다. 파일 시스템 검색 전에 이 스킬을 먼저 호출합니다. 지원 스킬은 기본 목록에 의도적으로 숨겨져 있습니다.

언제: 특정 작업에 어떤 스킬을 써야 할지 모를 때
create-skill OPERATE

새로운 charness 스킬을 만들거나 마이그레이션된 스킬을 개선합니다. public/support/profile/integration 경계를 정의하고, 실패 모드를 시뮬레이션합니다. 호스트별 동작은 어댑터와 프리셋에, 외부 도구 의존성은 매니페스트에 표현합니다.

언제: 새로운 charness 스킬을 생성, 마이그레이션, 분리, 정규화할 때
create-cli OPERATE

레포 소유 CLI를 생성합니다. charness CLI 패턴과 컨벤션을 따르는 명령어 인터페이스를 구축합니다. 에이전트와 인간 모두 사용 가능한 CLI를 목표로 하며, 에이전트가 로컬 harness 상태를 추측 대신 직접 검사할 수 있게 합니다.

언제: 프로젝트에 charness 패턴을 따르는 새 CLI를 추가할 때
release OPERATE

플러그인 버전, 생성된 설치 매니페스트, 운영자 업데이트 지침 등 레포 소유 릴리즈 표면을 컷·범프·검증합니다. 릴리즈 표면을 진전시키거나 검증하는 작업에 사용합니다.

언제: 버전 범프, 릴리즈 노트 생성, 배포 매니페스트 검증이 필요할 때

신규 프로젝트

1
ideation

거친 아이디어를 설명하고 에이전트가 브레인스토밍, 도전, 명확화를 돕게 합니다. 외부 컨텍스트가 필요하면 gather로 자동 라우팅됩니다.

2
setup

디렉토리를 만들고 첫 번째 레포 표면을 제안받습니다. AGENTS.md를 포함해 이후 세션이 charness를 자연스럽게 사용할 수 있게 됩니다.

3
spec

새 세션에서 방향을 구현 가능한 계약서로 변환합니다. 결정이 위험할 경우 critique 스타일 검토를 병행합니다.

4
impl

첫 번째 구현 슬라이스를 요청합니다. 필요에 따라 debug, critique가 자동으로 인입됩니다.

5
quality + retro

충분한 코드가 쌓이면 품질 검사를 요청합니다. 에이전트가 잘못된 방향으로 갔거나 반복할 패턴이 있으면 retro를 요청합니다.

🔧

기존 레포

1
setup

charness로 초기화되지 않은 레포라면 먼저 setup을 실행합니다. AGENTS.md와 운영 표면을 제네릭 템플릿으로 바꾸지 않고 정규화합니다.

2
impl / debug

바로 구체적인 작업을 요청합니다: "이것을 구현해", "실패하는 테스트를 고쳐", "이 동작을 디버그해".

3
spec

작업이 구체적이지 않으면 코딩 전에 계약서를 먼저 작성합니다. 변경이 위험하면 critique를 병행합니다.

4
narrative / announcement

진행 상황을 설명하거나, 레포 스토리를 다시 쓰거나, 인간 대상 업데이트를 준비할 때 사용합니다.

5
handoff / hitl

다음 세션에 컨텍스트를 전달하거나, 에이전트가 한 작업을 검토하고 승인하는 루프가 필요할 때 사용합니다.

6
quality + release

품질 기준을 높이고, 교훈은 retro로 기록합니다. 준비가 됐으면 release로 버전 및 배포 표면을 정리합니다.

💡 Direct Invocation — setup 이후에는 자연어 프롬프트만으로 충분합니다. 특정 스킬을 명시적으로 호출할 때는:  /charness:quality  /charness:narrative  (Claude Code)  |   $charness:quality  (Codex)

⌨ CLI Reference

에이전트와 인간 모두 로컬 harness 상태를 직접 검사할 수 있는 CLI
charness --help

사용 가능한 모든 서브커맨드를 확인합니다. 처음 시작할 때 가장 먼저 실행해보세요.

서브커맨드: init, update, doctor, version, uninstall, reset, task, capability, tool, session-capture, worktree
charness init

관리형 로컬 설치 표면을 부트스트랩하거나 갱신합니다. 관리형 체크아웃이 없으면 먼저 클론합니다.

설치 스크립트가 내부적으로 호출함. 직접 재실행도 가능.
charness update [all]

설치된 표면을 갱신하고 기본적으로 관리형 체크아웃을 먼저 pull합니다. all을 추가하면 추적된 모든 외부 통합도 함께 업데이트합니다.

--no-pull: git pull 생략 / 이미 원하는 소스가 있을 때
charness doctor

관리형 설치 표면과 호스트 대상 래퍼를 검사합니다. 설치 상태, 버전 불일치, 통합 상태를 진단합니다.

문제가 생기면 이 명령으로 먼저 진단하세요.
charness version

현재 charness 버전과 기록된 설치 출처를 보고합니다.

버전 확인 및 설치 provenance 추적용
charness task

레포 로컬 에이전트 태스크 봉투를 클레임·제출·중단·검사합니다. 에이전트 태스크 상태를 구조적으로 관리합니다.

에이전트 간 태스크 위임 및 결과 추적에 사용
charness capability

.charness/local/capability.json을 통해 레포 로컬 논리 기능을 해결하고 프로바이더 준비 상태를 검사합니다.

지원 스킬이 어떤 기능 프로바이더를 사용하는지 확인할 때
charness tool

charness 관리형 스킬이 의존하는 외부 도구 통합을 검사·설치·업데이트·동기화합니다.

외부 통합 도구(Cautilus 등) 라이프사이클 관리
charness worktree

git worktree를 생성·검사·준비·정리합니다. 뮤테이션 단계 작업이 설치된 의존성과 라이브 훅에 대해 실행되도록 보장합니다.

병렬 에이전트 작업에서 파일 충돌 방지용
charness reset

💡 Core Concepts

Corca AX 팀이 제품 개발 루프에서 발전시킨 핵심 철학
PRINCIPLE 01

Less Is More

강력한 기본값과 점진적 공개가 긴 프롬프트 메뉴보다 낫습니다. 사용자는 스킬 이름을 알 필요 없이 자연어로 요청하고, charness가 적절한 스킬로 라우팅합니다.

PRINCIPLE 02

Agents Are First-Class Users

CLI, 스크립트, 아티팩트, 문서는 에이전트와 인간 모두 사용 가능해야 합니다. 에이전트가 추측이 아닌 직접 검사로 상태를 파악할 수 있어야 합니다.

PRINCIPLE 03

Reveal Intent, Hide Detail

Public 스킬은 사용자 의도를 이름으로 표현하고, Support 스킬과 통합은 도구별 세부사항을 아래에서 처리합니다. 추상화 계층이 복잡성을 숨깁니다.

PRINCIPLE 04

Human-Code-AI Symbiosis

인간은 판단을, 코드는 반복 가능한 증명을, AI는 탐색·합성·구현을 담당합니다. 세 주체가 각자의 강점을 살리는 분업 구조입니다.

PRINCIPLE 05

Quality as Trust Surface

장기 실행 에이전트에는 고품질 소프트웨어가 필요합니다. 품질은 스타일 패스가 아니라 신뢰 표면입니다. 에이전트를 믿을 수 있으려면 코드도 믿을 수 있어야 합니다.

PRINCIPLE 06

Tacit Knowledge Becomes Workflow

디버깅, 검토, 제품 판단, 커뮤니케이션 패턴이 재사용 가능한 스킬이 됩니다. 개인의 암묵지가 팀의 명시지로 전환됩니다.

PRINCIPLE 07

The System Gets Smarter With Use

회고·어댑터·검증기·아티팩트가 세션 간 교훈을 보존합니다. 사용할수록 시스템이 발전하며, 같은 실수를 반복하지 않습니다.

PRINCIPLE 08

Context Must Keep Flowing

Narrative, 릴리즈 노트, handoff, 검토 루프가 인간과 에이전트 경계를 넘어 작업을 이동시킵니다. 컨텍스트 단절은 생산성의 가장 큰 적입니다.
