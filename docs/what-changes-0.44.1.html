하위 디렉터리에 설치해도
done 가드와 훅이 같은 판정을 합니다

git은 경로를 저장소 루트 기준으로 내고, 하네스는 설치 디렉터리 기준으로 비교했습니다. 모노레포 패키지처럼 하위 디렉터리에 설치하면 둘이 영영 맞지 않아 handoff 제외·0.44.0의 체크박스 면제·post-commit sweep 판정이 듣지 않았습니다. 0.44.0 노트에 한계로 적었던 항목을 고쳤습니다.

왜 patch인가 — 잘못 동작하던 것을 고쳤다

계약은 그대로이고, 하위 디렉터리 설치본이 루트 설치본과 다르게 판정하던 결함만 고쳤습니다. 루트 설치본은 동작이 바뀌지 않습니다.

지점하위 디렉터리 설치본의 이전 동작틀린 방향
done 가드 — handoff 제외훅이 쓴 handoff만 dirty여도 "커밋되지 않은 변경"으로 차단막는 쪽
done 가드 — 체크박스 면제(0.44.0)면제가 듣지 않아 종결 커밋이 다시 둘로 갈림막는 쪽
post-commit — sweep 판정handoff만 담은 sweep 커밋에도 매번 항목 기록(churn)기록하는 쪽

바뀐 것

Fixed · 경로 기준

비교 집합을 저장소 루트 기준으로 올린다

원인
git status --porcelain·diff-tree는 저장소 루트 기준 경로를 내는데, handoff·plan 경로는 targetDir 기준이었습니다.
지금
git rev-parse --show-prefix로 설치 디렉터리의 루트 기준 접두를 읽어 세 비교 지점에 붙입니다. git이 직접 계산하므로 symlink·realpath 차이를 타지 않고, 비ASCII·공백 경로도 원문 바이트로 맞습니다.
유지
가드가 보는 dirty 범위는 좁히지 않았습니다 — 설치 디렉터리 밖의 미커밋 변경도 종전대로 막습니다(회귀 테스트로 고정). 접두를 읽지 못하면 빈 접두, 곧 종전 동작입니다.
Docs

한계 문장 제거

이전
commands/harness-task.md "머지 후 종결"이 "경로 대조는 targetDir가 저장소 루트라고 가정한다"를 한계로 적었습니다.
지금
하위 디렉터리 설치본에서도 같다고 적습니다. 발행된 what-changes-0.44.0.html은 그 시점의 기록이라 고치지 않았습니다.
