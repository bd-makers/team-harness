왜 patch인가 — 에이전트 행동 표면의 수정

MAINTAINING.md의 크기 기준에서 ① 에이전트 행동 표면(commands/*.md)의 수정은 patch입니다. 문서지만 에이전트가 그대로 실행하므로, 고칠 대상은 사람의 이해가 아니라 기계의 동작입니다. 새 명령·플래그·가드는 없고 제거된 것도 없습니다.

/harness-interview — 통과를 선언했으면 질문하지 않는다

Fixed · #155

비차단 질문도 질문이다

전
"모든 차원이 pass면 질문 없이 6번으로 간다"만 있어, pass를 선언한 뒤 "통과를 막지 않는" 참고 질문을 덧붙였습니다.
후
차원 사이의 모순이나 정의되지 않은 경우가 보이면 그 차원을 pass로 두지 않고 fail로 고쳐 3번에서 묻습니다. 통과를 선언한 뒤에는 질문을 덧붙이지 않습니다.
Why

채점표가 질문의 조준경

이유
pass 뒤의 질문은 채점표가 잡지 못한 구멍이 있다는 신호인데, 판정은 pass로 남아 체크박스 갱신과 어긋납니다. 질문할 근거가 있으면 판정부터 바꿔야 합니다.

/harness-contrarian — 대화형은 채점하지 않는다

Fixed · #155

외부 엔진 스키마가 새지 않게

전
같은 문서 아래쪽의 외부 엔진 모드 루브릭(A1–A4 id·BLOCKER/MAJOR/MINOR·pass/fail)이 대화형 응답에도 쓰였고, 반론마다 대안 설계를 미리 붙였습니다.
후
대화형 3번은 반론을 각도 이름과 근거(spec/plan 인용)로 제시하고 응답을 받습니다. 대안 설계는 사용자가 반론을 받아들인 뒤 4번에서 제안합니다.
Note · 범위

외부 엔진 모드는 그대로

불변
엔진 인수를 준 외부 검증자 모드의 루브릭과 D6 finding 스키마는 바뀌지 않았습니다.

/harness-simplifier — 템플릿에 없는 산출물을 전제하지 않는다

Fixed · #155

바뀔 파일은 spec·plan이 지목한다

전
1단계가 "plan.md와 변경 예정 파일 목록을 읽는다"였는데, task 템플릿에는 그런 절이 없어 "파일 단위로는 검토하지 못했다"고 보고했습니다.
후
plan.md와 spec.md를 읽고, 바뀔 파일·모듈은 spec ## 범위 (In / Out)의 In과 plan 단계가 지목한 것으로 봅니다. 지목된 파일이 이미 있으면 그 파일도 읽습니다. 외부 엔진 모드의 리뷰 대상 문구도 같이 맞췄습니다.
