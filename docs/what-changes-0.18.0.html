/harness-spec — 빈 spec에서 시작하지 않는다

대부분의 재작업은 코드 능력이 아니라 입력 모호성에서 발생합니다. 그런데 지금까지 spec.md는 빈 템플릿에서 손으로 시작해야 했습니다.

Added

/harness-spec — 3소스 spec 초안 생성 (writer)

변경
활성 task의 <name>-spec.md 초안을 3소스에서 생성합니다: ① Confluence(PRD·spec·policy) ② Figma(wireframe·design-spec) ③ task 이름 기반 생성형 인터뷰(Goal/Constraint/Success/Ontology, 한 번에 질문 하나). 소스 접근은 MCP 우선 + 수동 붙여넣기 폴백이고, 프로젝트별 소스 기본 위치는 첫 실행 시 lazy로 입력받아 .harness/config.json의 specSources에 저장합니다(task별 구체 URL은 실행 시 입력). Codex 래퍼 skills/harness-spec/ 동봉.
왜
Ambiguity 게이트는 spec이 이미 쓰여 있어야 작동합니다. 소스가 흩어져 있으면(위키의 PRD, Figma의 화면, 머릿속의 제약) spec 작성 자체가 병목이 되고, 원문을 통째로 붙여넣으면 spec이 덤프장이 됩니다.
그래서
초안은 기존 taskSpecTemplate 골격을 유지하고 요구사항별 출처를 표기하며, 원문 덤프 대신 요약+링크만 남깁니다. 기존 spec이 있으면 merge(기본)/replace/cancel을 묻고, 알 수 없는 절(Boundary contracts 등)은 보존합니다. 소스 실패·충돌은 skip/인터뷰 전환/중단으로 명시 처리하고 (unresolved)로 양쪽을 보존합니다.
Contract

writer는 자기 초안을 채점하지 않는다

변경
자가진단 체크박스는 근거 있는 항목만 체크하는 초안 자기 평가로 한정하고, 체크 상태와 무관하게 항상 /harness-interview(validator)로 인계합니다. 전항목 체크 시 plan으로 바로 넘어가던 경로는 외부 리뷰(P1)에서 지적받아 제거했습니다.
왜
writer가 게이트 통과까지 선언하면 역할 분리가 무너집니다 — 자기가 쓴 초안을 자기가 채점해 통과시키는 경로는 게이트를 장식으로 만듭니다.
그래서
최종 게이트 판정(가중합 ≥ 0.8)과 통과 근거의 Ontology 기록은 validator 몫으로 남습니다. harness-task 생성 안내와 CLAUDE.md Ambiguity 게이트 불릿이 이 순서(빈 spec이면 /harness-spec → 막히면 /harness-interview)를 가리킵니다.

handoff EOF 빈 줄 — 파일이 아니라 생성기를 고쳤다

post-commit 훅이 갱신하는 handoff 파일 끝에 빈 줄이 남아 매 커밋 git diff --check에 걸렸습니다.

Fixed

runHandoffAuto append 포맷의 여분 개행 제거

변경
handoff 항목 끝의 여분 개행을 생성기 포맷에서 제거하고 기존 handoff 꼬리를 정리했습니다. 항목 구분은 다음 항목의 선행 개행이 담당합니다.
왜
파일만 고치면 다음 커밋에서 훅이 다시 빈 줄을 붙여 재발합니다. 재발하는 결함은 산출물이 아니라 생성기의 것입니다.
그래서
설치본에는 이 릴리스의 캐시 동기화부터 반영됩니다 — 그 전 버전 설치본에서는 커밋 시 수동 꼬리 트림이 여전히 필요했습니다. 고친 코드는 배달까지가 수정입니다.

옛 리뷰 이름 제거 — 0.19.0으로 이월

전환 창 연장: /harness-codex-review·/harness-codex-adversarial-review(커맨드 2 + 스킬 2)의 포워딩은 0.18.x 동안 유지됩니다. 전역 CLAUDE.md·팀 워크플로우의 옛 이름 참조를 /harness-review·/harness-adversarial-review로 아직 못 바꿨다면 이 창 안에 바꾸세요 — 제거는 0.19.0에서 수행합니다.
Deprecated

"다음 마이너에서 제거"를 한 마이너 미뤘다

변경
0.17.0은 옛 이름 4개를 다음 마이너에서 제거한다고 예고했지만, 이번 마이너는 /harness-spec 인도가 목적이라 제거를 싣지 않았습니다. 제거 시점은 0.19.0으로 명시 이월합니다.
왜
제거의 선행 조건 — 팀원 머신 전역 CLAUDE.md의 새 이름 전환 — 이 아직 완료되지 않았습니다. 참조가 남은 채 제거하면 실패가 아니라 무반응으로 조용히 깨집니다.
그래서
약속을 조용히 흘리는 대신 CHANGELOG에 이월 사실과 사유를 기록했습니다. 전환 창 동안 옛 이름 호출은 동작이 같습니다.

이번 릴리스가 택한 방향

쓰는 자는 판정하지 않는다

초안을 만드는 writer와 게이트를 판정하는 validator를 한 커맨드에 합치면, 자기 채점 경로가 생기는 순간 게이트는 장식이 됩니다. /harness-spec은 근거 표기까지만 하고, 통과 선언은 언제나 /harness-interview가 합니다.

재발하는 결함은 산출물이 아니라 생성기의 것이다

handoff 꼬리의 빈 줄은 파일을 백 번 고쳐도 다음 커밋에 재발합니다. 0.17.0의 교훈(고친 코드는 배달까지가 수정이다)에 이어, 이번에는 생성기 자체를 고치고 캐시 동기화로 설치본까지 배달했습니다.
