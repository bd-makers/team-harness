Team Harness Workflow

한 task가 태어나서 닫히기까지의 팀 워크플로우를 다섯 가지 형태로 그렸다. 각 다이어그램은 같은 워크플로우를 다른 질문으로 자른다.

기준 v0.23.0 5가지 형태 정본: AGENTS.md · commands/* D2 · D4 · D5 · D6
어떤 형태를 볼까
다이어그램마다 대답하는 질문이 다르다. 질문에 맞는 형태로 이동한다.

1 · 플로우차트

"한 task는 어떤 길을 지나가나?" — 세션 시작부터 done까지의 전체 여정과 분기.

2 · 역할 스윔레인

"누가 무엇을 하나?" — 작성자와 리뷰어의 분리(D2), 단일 스레드 쓰기(D4).

3 · 시퀀스

"시간 순서로 누가 누구를 부르나?" — 사용자·Claude·CLI·훅·리뷰어의 상호작용.

4 · 상태 다이어그램

"task는 어떤 상태를 오가고, 무엇이 전이를 막나?" — 게이트와 done 가드.

5 · gitGraph

"병렬 작업은 어떻게 충돌 없이 합쳐지나?" — worktree 격리와 PR 병합(D5).

4 · 상태 다이어그램 — 전이와 가드
task가 오가는 상태와, 전이를 막는 게이트. 파일 생성 내부는 harness-overview의 Task Lifecycle이 정본이다.

5 · gitGraph — 병렬 worktree 경로 (D5)
격리된 브랜치·worktree에서 병렬로 작업하고 PR로 병합한다. task SSOT는 각 디렉터리에 격리되므로 충돌하지 않는다.

정본: docs/decisions.md D5 · AGENTS.md §task 단위 관리 (집계 파일은 생성물)
왜 충돌하지 않나: task SSOT 4파일은 docs/<user>/<name>/에 격리되고, 집계 파일(docs/task_summary.md · <user>-task.md)은 어느 브랜치도 직접 쓰지 않는다 — 병합이 끝난 기본 브랜치에서 harness-team summary --write로만 갱신한다.
