그래서

함께 바뀐 동작 하나: React Native 전용 rules 4종은 이제 감지된 stack이 RN 계열일 때만 설치됩니다. 예전에는 --stack을 명시하지 않으면 Node·Python 프로젝트에도 Expo 규칙이 들어갔습니다. 그 결과 비-RN 프로젝트에는 .cursor/rules 미러가 생기지 않습니다 — 미러할 규칙이 없기 때문입니다.

block-dangerous-git.sh 우회와 protect-files.sh 오탐

변경

왜
“-C 우회를 닫자”는 보고된 케이스 하나를 고치는 일이 아니라 “subcommand 앞에 어떤 토큰이 올 수 있나”라는 문법 전체를 다루는 일이었습니다. 케이스만 고친 첫 판은 git --no-pager reset --hard에 곧바로 뚫렸습니다. 반대로 protect-files는 .env 부분 문자열 매치라 .envrc·src/dev.env.md·android/build.gradle 편집을 막고 있었습니다.

이 릴리스가 남기는 것

위임 결과는 표본 검증이 실제로 잡는다

4개 서브에이전트의 발견 19건을 메인 세션이 직접 재현했고 전부 일치했습니다. 하지만 그 확인이 있어야 “추정”으로 온 merge 데이터 손실 건을 확정으로 올릴 수 있었습니다. 산문 결론이 아니라 path:line을 받게 한 프롬프트 형식이 이를 가능하게 했습니다 — 위임이 컨텍스트를 아끼는 이유는 원증거를 부모로 되돌리지 않기 때문이고, 바로 그래서 부모는 표본을 직접 봐야 합니다.

휴리스틱을 고칠 때는 보고된 케이스가 아니라 문법 전체를 테스트한다

git -C 우회를 닫으며 값 있는 전역 옵션만 열거했더니, 리뷰어가 값 없는 옵션(--no-pager)과 공백 분리 값(--work-tree x)으로 곧바로 뚫었습니다. “어떤 토큰이 subcommand 앞에 올 수 있나”를 먼저 적고 그 목록으로 매트릭스를 만들었어야 했습니다. 개수 검사도 마찬가지입니다 — 마커 begin/end 개수, 체크박스 개수 둘 다 순서·스왑으로 뚫렸습니다. 개수 검사는 구조 검사가 아닙니다.

“우선은 제거”는 멤버 표면 전체를 뜻한다

스캐폴드·역할표·doctor·gitignore·ITEMS·리뷰 엔진 체인·매니페스트·문서·다이어그램까지 한 표면이라도 남기면 규범과 실체가 다시 어긋납니다. 지울 계획을 세울 때 plan에 적을 것은 지울 대상이 아니라 그 대상을 이름으로 부르는 모든 곳입니다 — 0.21.0 옛 리뷰 이름 제거에서 배운 규칙이 여기서도 맞았습니다.
