README의 member 식별 규칙은 --member를 최우선으로 적었지만 task는 .harness/config.json의 user를 먼저 봤습니다. 그래서 config user와 다른 member의 task를 가리킬 방법이 없었고, 한 머신에 두 정체성이 있으면 task <name>이 별개 스캐폴드를 만들었습니다. 우선순위를 문서대로 고치고, 같은 사고를 막는 가드를 붙입니다.

Fixed · CLI

--member 우선순위

이전
task가 cfg.user || --member 순서로 member를 정해, config에 user가 있으면 --member가 무시됐습니다.
지금
--member → config user → git config user.name → $USER 순서입니다. README 식별 규칙에 빠져 있던 config 단계도 적었습니다.
효과
config user=chad인 checkout에서도 task <name> --member hslee로 hslee의 task를 바로 활성화합니다.
Guard · CLI

추론 member의 이름 충돌

이전
다른 member에 같은 이름의 task가 있어도 추론한 member로 새 스캐폴드를 만들었습니다.
지금
--member 없이 실행했고 다른 member에 같은 이름의 task(spec 마커)가 있으면 exit 1로 멈추고 아무것도 쓰지 않습니다. --member <그 member>를 안내합니다.
탈출구
같은 이름으로 따로 만들려면 --member를 명시하세요. 공백이 든 member(config user로만 생김)는 플래그로 가리킬 수 없어 config user 설정을 안내합니다.
