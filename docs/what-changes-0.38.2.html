amend는 없는 커밋을
가리키는 기록을 남겼습니다

0.38.2는 git commit --amend가 post-commit 훅을 다시 돌려 만들던 고아 항목을 없앱니다 — 같은 논리 커밋에 항목이 둘 남고, 첫 항목의 sha는 amend가 밀어낸 존재하지 않는 커밋이었습니다. 이제 amend면 마지막 항목을 교체합니다. 다만 교체는 amend가 실제로 밀어낸 항목에만 합니다 — 그 경계를 잘못 잡으면 진짜 기록이 사라집니다.

두 조건이 모두 참일 때만 교체합니다

Fixed

① reflog 주제가 commit (amend)

실측
git reflog -1 --format=%gs HEAD는 commit: … · commit (initial): … · merge <b>: … · checkout: … · rebase (finish): …와 모두 구분됩니다. 병합의 amend도 commit (amend): …입니다.
Fixed

② 그 항목이 HEAD@{1}과 같다

왜 동일성인가
HEAD@{1}은 amend 직전의 HEAD, 즉 amend가 밀어낸 바로 그 커밋입니다. 항목 헤딩의 short sha와 접두 대조합니다.
조건 ①만으로는 부족
훅이 직전 커밋을 건너뛰었다면(0.38.1의 sweep 침묵) 마지막 항목은 더 이전의 진짜 커밋입니다. 지우면 안 됩니다.
Rejected

"이력에 없다"로는 판정하지 않습니다

왜
브랜치 전환·rebase 뒤 amend하면 다른 브랜치에 살아 있는 커밋의 항목도 "조상이 아니"어서 지워집니다. 0.38.1이 기각해 followups에 적어 둔 휴리스틱의 변형입니다.
덤
동일성 대조는 변경 없는 --amend --no-edit가 같은 OID를 만드는 경우(조상 판정이면 중복이 남는다)도 함께 해결합니다.

기각해 둔 휴리스틱이 구현에서 되살아났습니다

codex 3회. 첫 구현의 조건 ②가 바로 그 "조상 판정"이었고, P1으로 잡혔습니다.

발견판별조치
P1 조상 판정이라 브랜치 전환 뒤 amend에서 살아 있는 커밋의 항목을 지운다진짜 — 0.38.1이 기각한 그 휴리스틱HEAD@{1} 동일성 대조. 회귀 테스트 고정(옛 판정으로 되돌리면 실패)
P2 merge-base의 정상 exit 1과 실행 오류를 구분 못 함진짜동일성 대조로 전환하며 함께 소멸 — 실패는 append
P2 같은 OID amend는 교체를 건너뛰어 중복이 남음진짜같은 전환으로 함께 해결
P3 교체 경로가 항목 사이 빈 줄을 잃음진짜개행 하나로 정규화 + 두 경로의 구분자를 비교하는 테스트
P2·P3 문서·주석 4곳이 폐기된 조건을 설명진짜커맨드 문서 · 소스 주석 · plan · 테스트 주석 정정

같은 실수가 네 자리에서 나왔습니다. 조건을 한 번 뒤집었는데 그 조건을 설명하는 자리는 여섯이었습니다 (구현 · 소스 주석 · 커맨드 문서 · spec · plan · 테스트 주석). 설계를 바꿀 때는 그 설계를 말하는 자리 전체를 먼저 세야 합니다.
