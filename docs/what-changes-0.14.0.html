새 기능

리뷰어와 작성자의 분리는 하네스의 리뷰 프로토콜이 요구하는 것인데, 정작 그 리뷰를 부를 방법이 세션 기억에만 있었습니다.

Codex review

Codex 외부 리뷰를 하네스 커맨드로 노출

변경
/harness-codex-review와 적대적 변형인 /harness-codex-adversarial-review를 추가했습니다. 두 커맨드는 codex exec --sandbox read-only를 직접 실행하고, 인수(--base <ref>·focus)를 해석하며, base가 없으면 origin/main → main으로 물러납니다. 커맨드가 절차 SSOT이고 같은 이름의 스킬이 Codex 표면 래퍼입니다.
왜
openai-codex 플러그인의 /codex:review·/codex:adversarial-review는 disable-model-invocation이라 모델이 호출할 수 없습니다. 실무는 codex exec 직접 실행에 의존했지만, 그 절차가 문서화된 커맨드 없이 세션마다 재구성되고 있었습니다.
그래서
다른 플러그인의 노출 정책과 무관하게 리뷰를 부를 수 있고, 발견 검증 의무와 artifact ## Reviews 기록 의무가 절차에 포함되어 "기록 없는 리뷰"가 남지 않습니다.

회귀 방어

0.13이 고친 설치 안내는 문서였기 때문에, 같은 결함이 다시 들어와도 아무 테스트도 울지 않는 상태였습니다.

Regression guard

복구 명령과 skip 분기를 테스트로 고정

변경
doctor의 복구 명령을 모듈 스코프로 추출하고, npm 공개 저장소를 가리키는 설치 형태(npm i/install, -g/--global, 따옴표 유무)가 doctor 출력과 README 어디에도 없음을 어써션합니다. plugin-dev 저장소의 n/a skip 분기와 실제 bin --help 검증도 함께 고정했습니다.
왜
0.13의 404 안내가 통과한 이유는 검증이 문서를 읽어서 확인하고 실행하지 않았기 때문입니다. 통과만 확인하는 테스트는 같은 종류의 결함을 다시 놓칩니다.
그래서
네 가지 mutation(복구 명령 되돌리기·README에 404 형태 추가·skip 분기 제거·help 문구 변경)이 전부 실패로 잡히는 것을 확인했습니다. checkHookCli의 타임아웃도 같은 작업을 하는 checkSelfCli와 5초로 맞췄습니다.

이번 릴리스가 택한 방향

두 변경이 같은 원칙으로 수렴합니다: 의존은 계약에만 걸고, 검증은 깨뜨려서 확인한다.

타 플러그인 내부가 아니라 CLI 계약에 의존

Codex 리뷰를 부르기 위해 openai-codex 플러그인의 스크립트를 호출하지 않고, AGENTS.md 역할표가 정의한 codex exec --sandbox read-only만 사용합니다. 상대 플러그인의 노출 정책이 바뀌어도 하네스 커맨드는 영향을 받지 않습니다.

통과가 아니라 실패로 검증

새 테스트의 기준을 "통과하는가"가 아니라 "의도적으로 깨뜨렸을 때 실패하는가"로 잡았습니다. 이번 릴리스의 리뷰에서도 같은 방식으로 지적 네 건을 코드에 대조해 진짜 결함과 오탐을 갈랐습니다.
