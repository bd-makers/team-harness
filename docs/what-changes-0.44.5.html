바뀐 것

Fixed · #116

summary --write가 detached HEAD를 오류로 보지 않는다

원인
git branch --show-current는 detached HEAD에서 빈 문자열을 냅니다. 이 빈 출력을 git 실패와 같은 error로 분류해, origin/main에 detach한 워커 워크트리의 종결이 매번 막혔습니다 — 같은 커밋에 임시 브랜치를 만들어 우회했습니다(#114·#115 종결).
지금
detached는 별도 상태이고 비-기본 브랜치와 같은 판정(isSyncedWithDefault)을 받습니다. HEAD가 origin/HEAD가 가리키는 기본 브랜치와 정확히 같은 커밋이면 통과합니다. 거부 메시지는 (현재: detached HEAD)로 나옵니다.
유지
다른 커밋에 detach했거나 origin/HEAD가 없으면 종전처럼 거부합니다. git 자체 실패는 계속 fail-closed이고, --force 동작과 done 가드(브랜치를 조회하지 않음)는 그대로입니다.
Docs · #117

시뮬레이션 워크스루 현행화 + 표지 가드 등록

원인
docs/harness-workflow-simulation.html 본문이 0.40.0 기준이라 0.44.3의 버전 표지 가드에서 명시 제외돼 있었습니다.
지금
0.40.1~0.44.4 CHANGELOG를 시나리오별로 대조해 워크스루를 고쳤습니다 — user handoff는 워크트리 로컬, handoff는 다음 작업 커밋에, 머지 후 종결은 커밋 하나, --member 우선, 관리 절은 init이 렌더, init --stack 고정 등. 표지 셋(hero·🆕 배너·footer)이 이제 npm run docs:check의 대조 대상입니다.
메인테이너
MAINTAINING.md 릴리스 5단계에 이 문서의 표지 3곳 갱신을 추가했습니다. 본문 산문은 여전히 사람이 현행화합니다.

플러그인 갱신만

왜
바뀐 것은 CLI 동작(src/)과 읽을거리 문서뿐이고, 둘 다 플러그인 채널로만 옵니다. templates/·관리 절이 그대로라 프로젝트에서 init·migrate를 다시 돌릴 필요가 없습니다.
어떻게
/plugin marketplace update(또는 clone에서 git pull). harness-team --version이 0.44.5이면 됩니다.
Optional

임시 브랜치 우회를 걷어낸다

무엇
detached 워크트리에서 종결하려고 같은 커밋에 임시 브랜치를 만들던 절차가 있다면 더 필요 없습니다. git fetch origin 뒤 git checkout --detach origin/main 상태에서 harness-team summary --write가 바로 통과합니다.
주의
origin/HEAD가 설정되지 않은 clone은 여전히 거부됩니다 — git remote set-head origin --auto로 한 번 설정합니다.
