"부모 세션의 인증을 상속한다"는
환경에 따라 다릅니다

0.38.4는 harness-review.md가 무조건으로 적어 둔 인증 주장을 고칩니다. 중첩 claude -p가 부모 세션의 로그인을 상속하는지는 환경에 따라 다릅니다 — 원격 컨테이너에서는 상속했고(0.37.0 dogfood 리뷰가 그 경로), 데스크톱 앱 세션에서는 상속하지 않습니다. 에이전트가 이 문장을 믿고 claude 엔진을 고르면 리뷰가 실패합니다.

두 문서가 서로 반대를 말하고 있었고, 둘 다 무조건이었습니다

표면적혀 있던 것실측
commands/harness-review.md"부모 세션의 인증을 상속한다 (2026-08-21 실측 검증)"환경 의존 — 데스크톱 앱 세션에서는 exit 1, Failed to authenticate: OAuth session expired and could not be refreshed
tests/sim/agentloop.mjs"nested claude -p is NOT logged in (credential isolation)"결론은 맞지만 사유가 틀렸다 — 자격이 아예 없는 게 아니라 갱신하지 못하는 store에 닿는다

가드는 이미 덮고 있었습니다. 인증 실패는 exit 1이므로 harness-team review claude는 그 실행을 증거로 기록하지 않습니다 — "실패한 실행은 아무것도 쓰지 않는다"(0.37.0)가 이 경우를 포함합니다. 그래서 이번 릴리스에 코드 변경은 없습니다. 틀린 것은 사람과 에이전트가 읽는 문장뿐이었고, 그 문장 때문에 엔진 선택이 틀어집니다.

고친 것

Fixed

엔진 문서에 환경 의존과 대안

무엇
두 환경의 실측을 함께 적고, 상속되지 않는 환경에서는 codex 엔진을 쓰거나 CLAUDE_CODE_OAUTH_TOKEN을 넘기라고 명시했습니다.
왜 patch인가
이 문서는 에이전트가 그대로 실행하는 표면입니다(0.16.1 선례와 같은 모양).
Fixed

sim 헤더의 사유

무엇
agentloop.mjs·skilltest.mjs의 "credential isolation" 표현을 실측 메시지로 바꾸고 환경 의존을 명시했습니다.
토큰 경로
유지합니다 — 코드는 이미 if (token) … else ambient login으로 조건부이고, 상속되지 않는 환경에서는 그것이 유일한 길입니다. followups가 열어 뒀던 "토큰 경로 제거" 선택지는 실측이 기각했습니다.

소비자가 할 일

None

코드는 바뀌지 않았습니다

왜
인증 실패는 이미 exit 1로 걸러집니다. 플러그인 갱신만 하면 됩니다.
알아두실 것
harness-team review claude가 인증으로 실패하면 그것은 버그가 아니라 환경입니다 — codex 엔진을 쓰거나 토큰을 넘기세요.
