왜 patch인가 — 잘못 풀리던 경로를 고쳤다

설정 파일 형식과 계약은 그대로이고, 워크트리에서 메인 체크아웃과 다른 경로를 내던 결함만 고쳤습니다. 메인 체크아웃·git이 아닌 디렉터리는 결과 문자열까지 같습니다.

지점워크트리에서의 이전 동작영향
backup.json {parent,name} 해석 — loadBackupDir·resolveBackupDir워크트리 부모 기준으로 풀려 .claude/worktrees/harness-backup/<name>doctor ✗, backup·clone·symlink·delete·upgrade·migrate가 틀린 경로
자동 탐지 ../harness-backup/<이름>워크트리 이름으로 찾음있는 백업 폴더를 못 찾음
init — backup.json이 없을 때워크트리 이름을 name으로 저장커밋되면 모든 체크아웃이 틀린 이름을 물려받음

바뀐 것

Fixed · 경로 기준

백업 경로를 메인 체크아웃 기준으로 푼다

원인
세 지점 모두 설치 디렉터리(targetDir)를 기준으로 삼았고, 워크트리에서 그것은 메인 체크아웃이 아닙니다. --show-toplevel도 워크트리에서는 그 워크트리를 돌려줍니다.
지금
git rev-parse --git-common-dir의 부모(= 메인 체크아웃)에 --show-prefix를 붙인 경로를 기준으로 삼습니다. 하위 디렉터리 설치본도 메인 체크아웃의 같은 상대 위치로 갑니다. 두 벌이던 {parent,name} 해석은 한 함수로 모았습니다.
유지
메인 체크아웃·git이 아닌 디렉터리는 종전과 같은 문자열을 냅니다. {dir} 설정과 symlink 역추적은 바뀌지 않았습니다.
Guard

메인 체크아웃을 특정할 수 없으면 종전 동작

무엇
.git이라는 이름의 bare 저장소에 붙은 워크트리, core.worktree로 작업 트리를 딴 곳에 둔 저장소, submodule은 부모가 체크아웃이 아니므로 targetDir 그대로 둡니다 — 부모가 실제 그 저장소의 작업 트리인지 git에 직접 묻습니다.
격리
git 훅 안에서 설정되는 GIT_DIR 등 저장소 선택 환경변수는 떼고 부릅니다. 남기면 git이 대상 디렉터리 대신 그 저장소를 답합니다(리뷰에서 재현, 회귀 테스트로 고정).
