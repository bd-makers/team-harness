무엇

흔적이 없으면
status: warning(exit 0)과 함께 next_actions가 bootstrap 명령(npm ci·uv sync --locked 등)을 넘깁니다. 설치는 하지 않습니다.
관측일 뿐
흔적이 있다고 lockfile과 일치한다는 뜻은 아닙니다. 판정하지 않는 경우: lockfile 없음, 의존성 0개 npm lockfile, poetry(venv가 저장소 밖), bun.lockb, npm lockfileVersion 1, workspace별 설치. 알려진 오탐: npm 의존성이 전부 현재 OS에서 빠지는 optional이면 설치 뒤에도 absent입니다.

Q5 런타임 축은 만들지 않는다

무엇
"선언 런타임 대 실제 런타임" 대조는 no-go입니다. 파일 읽기만으로 대상 저장소의 실제 런타임을 관측할 수 없습니다 — 하네스의 process.version은 대상의 것이 아니고, 대상에서 node --version을 띄우는 것은 실행입니다.
다시 여는 조건
런타임 버전 불일치가 원인인 environment 실패가 반복될 때. 출발점은 task env-runtime-q5 spec에 있습니다.
규칙은 프리셋 데이터에만 있습니다(D11). 빈칸 후보는 env.declare, 설치 흔적은 env.installTrace에 있고, 조건 평가기 holds()에 JSON 키(중첩 가능)가 비어 있지 않은지 보는 nonEmptyKey: [file, ...keys]가 더해졌습니다. Python requirements.txt는 해시·pip-compile·uv 생성 헤더가 있을 때만 lockfile로 셉니다.

lockfile을 지키는 bootstrap 명령 · pm 감지

Added · #163

AGENTS.md ## 명령의 bootstrap 줄

무엇
종전 관리 절은 install: npm install처럼 lockfile을 무시하는 명령만 적었습니다. 이제 감지한 pm의 lockfile로 npm ci·pnpm install --frozen-lockfile·yarn install --immutable(berry)·yarn install --frozen-lockfile(classic)·bun install --frozen-lockfile·uv sync --locked·poetry install을 렌더하고, 모르면 (configure)로 둡니다.
bun.lockb
frozen 플래그가 그 파일을 검증하지 않고 bun.lock으로 바꾸므로 (configure)입니다. stack 요약에도 bootstrap: 축이 붙습니다. install 줄과 settings allowlist는 그대로입니다.
Fixed · #163 · Changed · #166

Python pm 감지 · JS pm 판정의 프리셋 이전

Python
pyproject.toml만 보면 pm=pip, install=인수 없는 pip install(실행되지 않음)이었습니다. 이제 uv.lock이면 uv·uv sync, poetry.lock이면 poetry·poetry install, 그 외 pip·(configure)입니다.
JS
lockfile→pm 판정(pnpm → yarn → bun)이 코드에서 templates/presets/node.json의 env.packageManager로 옮겨졌습니다. 파싱된 package.json이면 npm이라는 기본값은 코드에 남습니다. 감지 결과·관리 절·게이트 fingerprint는 그대로입니다.
드리프트
uv·poetry 저장소에서 커밋 게이트를 확정해 둔 경우 다음 doctor가 "패키지 매니저 pip → uv(poetry)"를 한 번 보고합니다. harness-team gate suggest로 다시 확정하면 사라집니다.

done — 무엇을 확인했는지 적고, tests는 기본 optional

Added · #159

보장 범위 한 줄

무엇
done: <task> 다음 줄에 보장 범위 — 확인: … | 확인 안 함: …을 찍습니다. 확인에는 실제로 돈 가드만, 꺼진 증거는 선언값과 함께(테스트 파일 변경(tests: optional)) 적고, 테스트 실행 결과·리뷰 내용은 언제나 확인 안 함에 둡니다.
커밋 게이트
통과하면 stdout systemMessage로 gates.json 선언 몇 개를 실행했는지와 "이 머신 환경 기준, 선언 밖 검사는 없음"을 알립니다. 종전 통과 줄은 stderr라 exit 0 훅에서 보이지 않았습니다. 판정·exit code는 그대로이고, 커밋마다 화면에 한 줄이 늘어납니다.
Changed · #158 · #160

tests 증거 기본값 required → optional

무엇
spec에 ## Done evidence를 선언하지 않은 task는 이제 소스만 바뀌어도, 기존 테스트 파일을 지워도 done이 막지 않습니다.
왜
종전 기본값은 D11("강제는 PR의 task 문서 하나뿐")에 없는 두 번째 강제였고, 엄격도를 하네스 기본값으로 올리면 팀원의 자유도가 떨어집니다.
종전 동작
spec에 { "version": 1, "tests": "required" }를 선언합니다. skip은 optional과 같은 뜻으로 계속 받습니다. 0.51.0의 "기존 테스트 삭제 차단"도 required일 때만 돕니다.
