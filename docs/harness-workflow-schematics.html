Team Harness · Workflow Schematics · 2026-08

하나의 워크플로우, 다섯 단면

한 task가 태어나서 닫히기까지 — 같은 팀 하네스 워크플로우를 게이트(플로우차트), 역할(스윔레인), 시간(시퀀스), 상태(스테이트 머신), 축적(플라이휠)의 다섯 관점으로 자른다. 정본은 AGENTS.md와 commands/harness-*.md.

01 · Flowchart — 게이트

task는 세 개의 게이트를 지난다

활성 task 판정, spec Ambiguity 자가진단, plan 완주 판정. 게이트 사이의 보강 반복은 점선 루프로 접었다.

02 · Swimlane — 역할

쓰기는 한 레인, 반박은 다른 레인

쓰기는 Claude 레인의 단일 스레드(D4). 리뷰어 레인은 read-only로 루브릭 반박만 돌려보낸다(D2·D6) — 가장 결합이 큰 핸드오프라 코랄로 강조했다.

쓰기 권한이 레인 하나에만 있다는 것 — 이 그림이 하려는 말은 그게 전부다.

03 · Sequence — 시간

atomic step 하나가 닫히기까지

전체 여정은 01이 담당한다 — 여기서는 구현 루프 한 바퀴와 리뷰 왕복만 클로즈업했다. 루프 프레임 안이 plan의 atomic step마다 반복되는 구간이다.

04 · State machine — 상태와 가드

done은 상태가 아니라 판정이다

Active를 벗어나는 모든 전이에는 조건이 붙는다. 특히 Done으로 가는 전이는 firstActivatedAt 이후의 증거와 plan 전량 닫힘을 가드가 대조한 뒤에만 열린다.

05 · Loop — 축적

모든 패스가 SSOT를 두껍게 한다

여섯 단계는 시계 방향으로 돌고, 매 단계가 점선 스포크로 task SSOT 4파일에 상태를 적어 넣는다 — plan 체크, handoff 인계, artifact의 결과와 학습. 이 축적이 있어서 다음 세션이 이어달릴 수 있다.

허브는 일곱 번째 단계가 아니다 — 여섯 단계가 쌓아 올리는 공유 기록이다.

Gates

게이트가 막는 것

  • Ambiguity 게이트 — 모호한 spec으로 구현에 진입하는 것
  • boundary check — 계약과 어긋난 plan 체크박스 완료
  • done 가드 — 증거 없는 완료 선언 (firstActivatedAt 이후 대조)

Roles

역할 경계

  • D2 — 작성자(drive)와 리뷰어(read-only)를 분리한다
  • D4 — 같은 워킹트리 쓰기는 단일 스레드
  • D5 — 격리 worktree의 병렬은 허용·권장, 병합은 PR로

Record

SSOT에 쌓이는 것

  • spec — 요구사항과 설계 결정
  • plan — 진행 상태 (체크박스)
  • handoff — 세션 인계 (훅이 자동 갱신)
  • artifact — 결과 · 학습 · 리뷰 기록
