0.17.0은 두 갈래의 minor 릴리스입니다. 리뷰 커맨드를 엔진 중립으로 재편해 어느 머신에서든 리뷰 경로를 보장했고, jq가 없는 머신에서 보안 훅 4개가 조용히 무력화되던 fail-open을 수정해 기존 설치본까지 배달했습니다. task 라이프사이클에는 /harness-ship과 다이어그램 옵트인이 더해졌습니다.

리뷰 커맨드 — 이름에서 엔진을 뺐다

엔진(codex·claude·gemini·custom)과 프레이밍(통상/적대적)은 직교합니다. 기존 이름은 엔진을 커맨드명에 박아 두 축을 곱하고 있었습니다.

전환 필요: 전역 CLAUDE.md·팀 워크플로우에서 /harness-codex-review·/harness-codex-adversarial-review 참조를 새 이름으로 바꾸세요. 옛 이름은 이번 마이너 동안만 포워딩으로 유지되고 다음 마이너에서 제거됩니다.

Added

/harness-review · /harness-adversarial-review

변경
리뷰 커맨드 표면을 엔진 중립 2커맨드로 재편했습니다. 엔진은 첫 위치 인자이고, 생략하면 probe 폴백 체인(codex → gemini → claude)이 첫 가용 엔진을 씁니다. 절차(scope → 실행 → 발견 검증 → artifact 기록 → 보고)는 harness-review.md가 한 번만 소유하고, adversarial은 프롬프트 프레이밍만 교체합니다. Codex 표면도 같은 체계입니다.
왜
엔진을 이름에 박으면 claude-only 팀원이 쓸 리뷰 경로가 없고, 엔진이 늘 때마다 커맨드가 프레이밍 수만큼 곱으로 늘어납니다.
그래서
claude는 Claude Code 환경에 항상 존재하므로 어느 머신에서든 리뷰어가 보장됩니다. claude 엔진은 claude -p --permission-mode plan(쓰기 차단·read-only git·인증 상속, 2026-08-21 실측)이되 컨텍스트 분리만 제공(vendor 분리 없음)합니다 — 체인의 마지막인 이유입니다. custom 엔진은 커밋 가능한 .harness/reviewers.json의 {prompt} 치환 계약(POSIX 단일 인용, 셸 주입 차단)이며 미설정이면 실패 없이 스키마 안내 후 종료합니다.
Deprecated

옛 이름 4개는 전환 창 — 다음 마이너에서 제거

변경
/harness-codex-review·/harness-codex-adversarial-review 커맨드 2개와 동명 스킬 2개를 새 커맨드를 엔진 codex로 수행하는 얇은 포워딩 문서로 교체하고, plugin.json 등재는 유지했습니다.
왜
전역 CLAUDE.md와 팀원 워크플로우에 남은 옛 이름 참조가 조용히 깨지는 것을 막기 위한 전환 창입니다. 참조가 남은 채 이름만 지우면 실패가 아니라 무반응이 됩니다.
그래서
1개 마이너 버전 유지 후 다음 마이너에서 4개를 제거합니다. 전환 창 동안 옛 이름 호출은 동작이 같습니다.

jq가 없으면 훅이 조용히 열려 있었다

통제된 PATH 실측: git push --force가 jq 있으면 exit 2(차단), 없으면 exit 0(허용). .env 편집도 마찬가지였습니다.

Security fix

훅 4개의 fail-open을 저정밀 폴백으로 수정

변경
auto-format·block-dangerous-git·pre-commit-check·protect-files가 jq 부재를 command -v로 감지해, grep 폴백으로 "key": "value" 문자열을 잘라내 같은 패턴·같은 판정으로 검사합니다. 추출은 tool_input 마커 이후로 스코프하고, 추출 실패 payload는 통과시키지 않습니다(fail-closed).
왜
jq가 없으면 TOOL_NAME이 빈 문자열이 되어 != "Bash" 분기로 빠지고 exit 0(허용) 했습니다. "jq 없으면 무조건 차단"은 답이 아닙니다 — 훅은 매 도구 호출마다 돌기 때문에 그건 어떤 bash 명령도 못 쓰는 상태입니다. payload 전체 스캔도 안 됩니다 — 모델이 쓴 설명 문구가 정규식을 완성시켜 안전한 명령을 차단합니다.
그래서
차단은 유지되고 정밀도만 떨어집니다. 잔여 한계는 숨기지 않고 핀했습니다 — 이스케이프를 일절 디코드하지 않으므로 값 속 문자 하나를 \uXXXX로 인코딩하면 폴백이 뚫립니다(테스트로 고정, 해법은 jq 설치). 차단 10종·허용 12종 매트릭스를 jq 있는/없는 PATH 양쪽에서 자동으로 돌립니다.
Delivery fix

수정이 기존 설치본에 도달하지 않고 있었다

변경
migrate의 refreshClaudeHooks를 훅 4개로 확장했습니다. 설치본이 과거 배포본과 바이트 동일(sha256 테이블)할 때만 confirm/--yes 후 최신 템플릿으로 갱신하고, 커스터마이즈된 훅은 절대 덮지 않고 안내만 합니다.
왜
훅 수정은 템플릿에만 실렸고 copyStaticAssets는 훅을 skipExisting으로 복사합니다 — init/apply 어느 쪽도 설치본을 갱신하지 않아, 실측으로 구버전 설치본은 여전히 fail-open이었습니다. 고친 코드가 배달되지 않으면 고친 게 아닙니다.
그래서
doctor도 정직해졌습니다 — 설치본 훅의 harness:jq-fallback 마커를 확인해, 폴백 없는 훅이 있으면 "조용히 무력화(fail-open), migrate 필요"로, 전부 있으면 저정밀 문구로 분기합니다. jq 표기는 optional → warning으로 승격했고(판정 정밀도를 좌우하므로), 경고에는 플랫폼별 설치 명령을 remedy로 함께 싣습니다.

task 라이프사이클 — done과 머지 사이

문서가 최신이어야 하는 시점은 리뷰어가 읽는 PR 시점인데, 라이프사이클은 done에서 끝나 그 사이가 비어 있었습니다.

Added

/harness-ship — PR/MR 직전 최종 갱신

변경
활성 task의 spec·plan·artifact를 코드 현실과 맞춘 뒤 "PR/MR 준비 완료" 보고에서 멈춥니다 — PR/MR 생성·푸시는 하지 않습니다. 새 CLI 서브커맨드는 없습니다(ship은 에이전트 판단 작업).
왜
done에 PR 단계를 끼우면 이 저장소의 릴리스 플로우(PR 없이 main 직접 범프 커밋 → 태그)가 깨집니다. 갭은 별도 커맨드로 메우고 기존 계약은 건드리지 않았습니다.
그래서
tests/ship-command.test.mjs가 ship을 안전하게 만드는 두 성질 — PR을 스스로 열지 않는다 / 다이어그램 도구에 하드 의존하지 않는다 — 과 AGENTS.md의 도구 중립성을 회귀로 고정합니다.
Added

다이어그램 옵트인 + /harness-diagram + 동반 플러그인

변경
신규 task 직후 다이어그램을 만들지 1회만 묻습니다. 전용 설정 키·상태 파일은 없습니다 — plan.md에 그 단계가 있는지가 곧 상태입니다. /harness-diagram은 별칭이 아니라 어댑터로, 산출물 경로·자립형 inline SVG·생성물(비-SSOT) 지위·artifact 기록 규약을 상류 호출에 싣습니다. diagram-design은 vendoring 없이 commit sha(0ab077f)로 핀한 동반 플러그인으로 등재했습니다.
왜
상류 스킬을 직접 부르면 하네스 규약이 하나도 적용되지 않습니다. 업스트림 최신(2.6.1)은 /doctor 같은 범용 슬래시 커맨드를 세션에 주입하고 major 2개 분량이 미검증이라, 실제 동작이 확인된 커밋을 핀했습니다 — "구조가 온전함"은 "검증됨"이 아닙니다.
그래서
계약은 probe → degrade → record — 도구 없는 머신에서는 실패시키지 않고 건너뛴 뒤 artifact에 "미실행" 한 줄을 남깁니다. 동반 항목 계약(40hex source.sha 핀, version 금지, 저작자 표기)은 회귀 테스트로 고정했습니다.

이번 릴리스가 택한 방향

이름은 계약이다

커맨드 이름에 구현(엔진)을 박으면 구현이 늘 때마다 표면이 곱으로 늘고, 그 구현이 없는 머신에서는 경로 자체가 사라집니다. 직교하는 축은 이름이 아니라 인자로 표현해야 합니다. 그리고 이름을 바꿀 때는 옛 이름이 조용히 죽지 않도록 전환 창을 둡니다.

고친 코드는 배달까지가 수정이다

fail-open 수정은 템플릿에 실렸지만 기존 설치본은 여전히 열려 있었습니다. 템플릿·설치본·문서(doctor의 안내)가 모두 같은 사실을 말할 때까지가 한 건의 수정입니다. 0.16.1의 교훈 — 침묵을 통과로 위장하지 말 것 — 의 연속입니다.
