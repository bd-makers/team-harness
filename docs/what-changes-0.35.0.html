트립와이어가 울려도
다음 세션은 아무 신호 없이 시작했습니다

0.35.0은 관측 판정(트립와이어)을 doctor와 SessionStart에 표면화합니다. 0.26.0부터 로거가 매 도구 호출을 기록하고 harness-team observe가 판정까지 했지만, 그 판정은 observe를 칠 생각이 난 사람만 봤습니다 — 선행 task가 "doctor 배선·SessionStart nudge"를 명시적으로 범위 제외한 채 미뤄 둔 결정입니다. 이제 발화하면 doctor는 경고 1건을, SessionStart는 한 줄을 덧붙입니다. 임계값·창·nudge·훅·템플릿은 한 글자도 바뀌지 않습니다. 함께 실린 수정 하나: doctor의 결정 로그 검사가 fenced code block 안의 헤딩을 절로 오인하던 것.

판정은 있었습니다 — 읽는 곳이 하나뿐이었습니다

로거(observe-tools.mjs)는 settings 훅 4곳에 배선돼 있고, 판정(트립와이어 2종·exit 1·루프백 nudge)도 구현·테스트돼 있었습니다. 없는 것은 표면화 — 판정을 명령을 따로 치지 않은 사람이 보게 되는 경로였습니다.

판정 하나, 표면 둘

핵심 결정은 판정 함수를 하나로 뽑아 세 호출자가 공유하는 것입니다. observe CLI·doctor·SessionStart가 evaluateObserveVerdict 하나를 부르므로 셋이 다른 답을 낼 수 없습니다.

리뷰가 잡은 것

외부 검증 — 두 리뷰, 일곱 지적, 전부 판별
