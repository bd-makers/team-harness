왜 minor인가 — task가 거부하는 경우가 하나 생겼다

명령·플래그·선언 키는 늘지 않았습니다. 다만 harness-team task <name>이 새로 거부하는 입력이 하나 생겼고(아래 "이름 재사용 거부"), 원장·원격 판정의 입력이 넓어졌습니다. 제거된 것은 없습니다. task 폴더 삭제(C2b)는 이번 릴리스에 없습니다 — 위키 컴파일(C1)이 소비자 저장소 1곳 이상에서 한 릴리스 이상 돈 뒤 착수합니다(2026-10-09 결정). C2b가 1.0 전 마지막 파괴적 변경입니다.

원장이 입력이 된다 — 폴더 없는 done task

원장 docs/task_summary.md는 여전히 summary --write가 렌더하는 결정론 생성물입니다. 다만 그 ✅ done 행은 이제 폴더가 없을 때의 입력도 됩니다. 원장 행 파서는 parseSummaryRows 하나로 모였습니다.

Changed · #137

summary --write가 폴더 없는 done 행을 이어받는다

원인
원장은 task 디렉터리를 스캔해서만 렌더됐습니다. 종결 뒤 폴더를 지우면 다음 렌더에서 그 task의 행(⚠️ 우회 표시 포함)이 통째로 사라졌습니다.
지금
커밋된 원장에 ✅ done이고 폴더가 없는 task는 상태·⚠️·생성일·Area 칸 그대로 이어받습니다. 사용자 인덱스의 완료 줄도 남습니다. 폴더 없는 🔄 open 행은 손으로 버린 task라 종전대로 빠집니다.
경계
원장 텍스트는 폴더 이름과 달리 /·..를 담을 수 있습니다. user·task가 task 생성과 같은 경로 규칙을 어기는 행은 이어받지 않습니다 — 저장소 밖에 인덱스 파일을 쓰지 않습니다.
migrate
원장 입력은 summary 렌더에만 씁니다. migrate가 같은 입력을 쓰면 meta를 새로 써서 지운 폴더를 되살리기 때문입니다 — migrate는 종전대로 폴더 있는 task만 봅니다.
Changed · #137

done-on-main nudge·list --remote 원장 폴백

원인
"이 task는 main에서 이미 종결됐다"는 판정이 origin/<default>의 <task>-meta.json만 읽었습니다. 폴더가 지워지면 nudge가 경고 없이 꺼지고, squash 머지 뒤 남은 브랜치의 그 task가 list --remote에 branch-only로 잘못 떴습니다.
지금
default ref에 meta도 spec 마커도 없으면 같은 커밋 원장의 ✅ done 행으로 판정합니다. 종결 시각은 그 디렉터리를 마지막으로 건드린 커밋 시각입니다. list --remote도 default ref 원장의 done 행을 "default에 있다"로 셉니다.
문구
원장 출처일 때만 nudge가 "새 이름으로 이어간다"고 안내합니다 — 종전 안내("main을 가져온 뒤 다시 연다")를 따르면 폴더가 지워진 main 위에서 아래 이름 가드에 막히기 때문입니다. meta 출처의 문구와 --json의 doneOnMain 모양은 그대로입니다(원장 출처에만 source: "ledger").
유지
fetch하지 않습니다 — 로컬 refs/remotes/*만, 2초 timeout, 어떤 실패도 "모른다"(nudge 없음). meta 없는 구 task라도 폴더가 main에 남아 있으면 폴백하지 않습니다.

종결된 task 이름의 재사용 거부

위키 컴파일 단락의 키(task=<user>/<task>)와 원장 행은 이름이 유일하다고 가정합니다. 폴더가 지워진 이름을 다시 쓰면 둘이 겹칩니다.

Changed · #137

task <name> — 원장에 done이고 폴더도 없을 때만 거부

조건
로컬 docs/task_summary.md에 <user>/<name>이 ✅ done이고 docs/<user>/<name>/이 없으면 만들지 않고 exit 1로 멈춥니다. 안내는 다른 이름으로 재실행, 원문은 git log -- docs/<user>/<name>입니다.
유지
폴더가 있으면 종전대로 다시 엽니다(reopened:) — 기존 reopen 흐름과 reopenedAt > closedAt 소음 끄기는 그대로입니다. 원격 원장은 보지 않습니다 — 그쪽은 nudge가 알립니다(생성은 막지 않음).
오늘
폴더를 지우는 장치가 아직 없으므로 이 거부는 손으로 폴더를 지운 경우에만 걸립니다.
