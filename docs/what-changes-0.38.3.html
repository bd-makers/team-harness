설치된 Codex 훅은
아무것도 주입하지 않았습니다

0.38.3은 init이 설치하던 Codex SessionStart 훅을 실제로 동작하게 만듭니다. 두 가지가 틀려 있었습니다 — Codex는 훅의 평문 stdout을 주입하지 않고, 훅이 돌려면 신뢰 두 겹이 필요한데 하네스는 파일 존재만 검사했습니다. 그래서 README는 "주입합니다"라고 적었고, 실제로는 2026-03부터 한 번도 주입되지 않았습니다.

봉투와 경고

Fixed

session-context --codex-hook

무엇
같은 텍스트를 {"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"…"}} 한 줄로 감쌉니다.
Claude는
불변 — Claude는 평문 stdout을 읽으므로 기본 출력은 그대로입니다. 봉투는 이 플래그일 때만.
Added

doctor: Codex hook trust

검사
CODEX_HOME ?? ~/.codex의 config.toml을 읽기만 해서 프로젝트 신뢰와 훅 소스 신뢰를 봅니다. 어느 쪽이 없는지까지 말합니다.
침묵하는 경우
codex 설정이 없으면(= codex를 안 쓰면) 조용합니다. 낡은 승인은 잡지 못합니다 — codex의 해시 계약이 공개돼 있지 않아 "없는 신뢰만" 잡습니다(코드에 명시).
Added

migrate: 옛 커맨드 업그레이드

왜 필요한가
init의 배열 union은 새 훅을 추가할 뿐이라 옛 훅이 죽은 채 남습니다. 제자리에서 플래그를 붙이는 경로가 이것뿐입니다.
보수적으로
출하한 적 있는 형태만 고칩니다(refreshClaudeHooks의 sha 테이블과 같은 원칙). 사용자가 쓴 훅은 건드리지 않습니다.

리뷰 3회 — P1 1건, P2 8건

발견무엇이 문제였나조치
P1 옛 커맨드를 healthy로 보고기존 설치 전부가 "괜찮다"고 보고되면서 실제로는 주입 안 함판정에 봉투 플래그 요구 + migrate 업그레이드 경로 신설
P2 신뢰 매칭이 느슨함경로 부분 문자열·주석 처리된 해시·같은 파일의 다른 훅이 경고를 숨김하네스 훅의 (group, hook) 위치로 정확한 키를 만들어 대조
P2 공존 시 옛 훅의 승인이 새 훅을 가림업그레이드 직후가 정확히 그 모양신뢰 키를 봉투를 내는 훅만으로 한정
P2 셸 문자열 3건echo "harness-team session-context"를 실행으로 오인 등 — 셸 파싱 없이는 일반해가 없음쓰기만 출하 형태 allowlist로 좁힘. 판정(경고)은 넓게 유지

리뷰 루프를 스스로 닫았습니다. 셸 문자열 공격 표면은 파싱 없이 끝이 없습니다. 3차까지의 발견을 전부 반영한 뒤, 어디서 왜 멈췄는지를 코드(allowlist)와 artifact에 적고 실제 동작 검증(codex 세션이 [harness] 줄을 인용)으로 마감했습니다.

소비자가 할 일

Action

Codex를 쓴다면 두 가지

① 훅 갱신
harness-team migrate — 옛 커맨드에 --codex-hook을 붙입니다(확인 후 적용, 멱등).
② 훅 승인
그 프로젝트에서 대화형 codex를 한 번 띄워 훅을 승인합니다. 하네스가 대신 줄 수 없습니다 — doctor가 승인 전까지 경고합니다.
None

Codex를 안 쓴다면 아무것도

왜
codex 설정이 없으면 새 경고는 침묵합니다. Claude 경로는 바이트 단위로 그대로입니다.
테스트
e2e 샌드박스에 CODEX_HOME 격리를 추가했습니다 — 개발 머신의 실제 ~/.codex가 테스트에 새어 들어오지 않습니다.
