학습이 규칙이 되는 길이 생겼습니다
— harness-team rules promote

0.27.0은 기능 하나와 그 주변 계약을 담습니다. harness-team retro는 활성 task artifact.md의 ## Learnings에 학습을 append만 했고, 그 학습을 .claude/rules로 올리는 코드 경로가 없었습니다 — 규칙 파일에는 유래도 날짜도 없었습니다(2026-09-05 외부 6층 플레이북 비교 분석의 권고 ②). 이제 사용자가 고른 Learnings 항목을 기계적으로 .claude/rules/<slug>.md로 복사하고, 유래 마커를 붙이고, cursor 미러를 다시 만들고, artifact 원 항목에는 승격 표기를 남깁니다. 어떤 학습을 규칙으로 굳힐지는 사람이 정합니다 — LLM이 스스로 승격하는 경로는 없습니다.

왜
PDF TABLE IX·§X.F의 ratchet — 반복되는 교정은 프롬프트 리마인더(약)가 아니라 규칙·센서(강)로 굳힌다 — 를 하네스가 실제로 실행할 수 있어야 했습니다. 이동이 아니라 복사인 이유는 artifact가 task SSOT라 done 가드와 retro 계약이 그 위에 서 있기 때문이고, 표기를 남기는 이유는 재승격을 거부할 근거가 필요해서입니다.
그래서

유래 마커와 doctor — 규칙에 "누가 언제"가 생겼다

승격된 규칙 본문 첫 줄에 <!-- harness:rule origin=<user>/<task> since=<YYYY-MM-DD> -->가 붙습니다. 규칙 템플릿 4종(navigation·state-management·styling·testing)에도 origin=harness-aijient-team/templates 마커가 들어갔고, harness-team doctor는 마커 없는 규칙을 rule provenance 경고로 나열합니다(warning, exit 영향 없음).

결정대안왜 이쪽인가
HTML 주석 마커frontmatter 키 origin/sinceClaude Code 공식 문서상 rules frontmatter의 공인 키는 paths뿐이고 임의 키 처리는 미명시. 반면 block-level HTML 주석은 컨텍스트 주입 전에 제거된다고 명시돼 있다. 기존 harness:mirror·harness:review·harness:section과 같은 관례라 파서도 같다. 마커는 splitRulePaths가 frontmatter만 벗기므로 cursor .mdc에도 그대로 실린다.
마커는 본문 첫 비공백 줄에서만 인정파일 어디서나본문이나 fenced 예시에 적힌 마커 문자열을 유래로 치면 doctor가 유래 없는 규칙을 놓친다(codex P2). 읽을 수 없는 파일(권한·dangling symlink)은 "유래 없음"과 처방이 달라 따로 나열한다(codex P3).
템플릿에 지금 스탬프템플릿은 예외 처리신규 설치가 곧바로 깨끗해진다. 대신 이전에 설치된 템플릿 사본에는 마커가 없어 doctor가 경고한다 — 브레인스토밍에서 수용한 트레이드오프이며, 경고문에 같은 형식의 마커 한 줄을 직접 추가하는 방법을 적었다.
미검증 가정 1건: Claude Code가 .claude/rules 파일의 block-level HTML 주석도 컨텍스트 주입 전에 제거한다는 것 — 문서는 "CLAUDE.md files"라고만 씁니다. 적용되지 않아도 마커 한 줄이 컨텍스트에 실릴 뿐 동작은 같습니다. 범위 밖으로 남긴 후속 후보: 주당 규칙 증가율 스코어카드, 규칙 중복·모순 검출, 승격 취소 명령.

외부 리뷰 — P1 하나, P2 넷, P3 둘, 일곱 반영 · shipcheck 두 번

codex read-only 리뷰(gpt-5.6-sol)가 브랜치 diff를 봤고, 일곱 발견을 모두 RED 테스트로 먼저 재현한 뒤 진짜 결함으로 판별해 반영했습니다. 이어서 같은 엔진의 shipcheck 검증자(S1~S5 루브릭)가 문서↔diff 정합을 두 번 반박했습니다.

이 릴리스가 남기는 것

"선언된 플래그는 읽힌다" 가드는 리터럴을 본다

tests/cli-args.test.mjs는 명령이 선언한 플래그를 그 모듈이 flags.<key> 또는 flags['<key>'] 리터럴로 읽는지 대조합니다. ctx.flags?.name 같은 optional chaining은 불일치라 GREEN이 한 번 깨졌습니다 — 값 플래그는 const flags = ctx.flags ?? {} 뒤 리터럴로 읽습니다.

없는 named export를 import하는 RED는 파일 전체가 죽는다

ESM은 link 단계에서 does not provide an export named …로 모듈 로드를 거부하므로 "기존 N건 pass + 신규 M건 fail" 모양이 나오지 않습니다. RED로는 유효하지만 plan에 그 모양을 미리 적으면 틀립니다 — shipcheck #2가 정확히 이 점을 잡았고, 그 때문에 개별 실패를 못 본 가드는 변이로 따로 확인해야 했습니다.

코드를 스플라이스하는 도구의 함정 셋

JavaScript String.prototype.replace의 문자열 치환은 $&·$`·$' 패턴을 해석해 치환문 안의 `$` 조각이 매치 앞 본문 전체를 삽입했고, macOS perl -0pi는 멀티바이트 문자에 양화사를 걸면 바이트 단위로 매칭돼 조용히 실패하며, zsh는 CLI="node bin/x.mjs"; $CLI를 단어 분리하지 않습니다. 함수 replacer·Python str.replace·셸 함수로 각각 피했고, 앵커 부재는 throw로 드러내게 했습니다.
