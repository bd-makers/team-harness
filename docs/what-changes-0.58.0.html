머지가 곧 종결

BREAKING · #194

종결 판정은 plan에서 계산한다

무엇
어떤 커밋에서 plan에 미완 - [ ]가 없고 - [x]가 하나 이상이면 그 task는 종결입니다. 유효한 done --force 우회 기록(forcedAt > reopenedAt)과 옛 meta status: done도 종결로 읽으므로, 기존 task의 판정은 바뀌지 않습니다. 판정은 src/task-closure.mjs 한 곳에 있고 summary·session-context·wiki·migrate·doctor·clean이 함께 씁니다.
왜
종결을 기록으로 남기면 구현 MR 뒤에 종결만을 위한 커밋과 MR이 매번 따라오고, 기록과 실제 plan 상태가 어긋날 수 있었습니다. 기본 브랜치의 plan 상태를 정본으로 두면 머지 하나로 끝나고, 어긋날 기록 자체가 없습니다.
done
done은 가드만 돌리고 추적 파일을 쓰지 않습니다. plan이 없는 task는 막습니다(plan이 없으면 머지해도 종결되지 않기 때문입니다). 새 흐름은 /harness-ship → plan의 "ship 완료" 체크 → done → 커밋 → MR → 머지입니다.
Changed · #194

pre-push가 done 가드를 미리 돈다

무엇
plan이 전부 체크된 task를 바꾸는 push에서 pr-check가 done 가드도 실행합니다. push하는 커밋이 HEAD이고 작업 트리가 깨끗할 때만 돌고, 그렇지 않으면 건너뛰었다는 note를 남깁니다.
왜
전부 체크된 plan이 머지되는 순간이 종결이므로, 가드를 돌릴 마지막 기회가 push입니다.
원장
docs/task_summary.md는 종결 절차에서 빠졌습니다. 머지마다 낡는 것이 정상이고, 기본 브랜치에서 필요할 때 summary --write로 한꺼번에 갱신합니다.

reopen — 머지 뒤 다시 연다

Added · #194

harness-team reopen <name> [--reason <text>]

무엇
meta에 reopenedAt을 쓰고 plan ## 단계 끝에 - [ ] 재개: <사유>를 넣어 판정을 open으로 되돌립니다. 종결되지 않았거나 없는 task면 아무것도 쓰지 않고 exit 1입니다. task <name>도 같은 조건이면 같은 전이를 합니다(출력 reopened:).
왜
종결이 머지로 정해지면, 머지 뒤 문제를 고칠 때 그 task를 다시 여는 정해진 방법이 필요합니다. 고친 내용은 새 MR로 들어갑니다.
조건
기본 브랜치와 작업 트리 둘 다에서 종결이고, 기본 브랜치의 종결이 마지막 reopenedAt보다 늦을 때만 다시 엽니다. 그래서 머지 전 리뷰 수정 라운드에서 이중으로 재개되지 않습니다.

pre-push pr-check 보강

Fixed · #195

fork main으로 가는 push도 검사

무엇
훅이 git이 준 push 원격($1)을 HARNESS_PUSH_REMOTE로 넘깁니다. 그 원격이 base 원격(origin)이 아닌 다른 설정된 원격으로 풀리면 기본 브랜치 push도 검사합니다. origin 기본 브랜치 push와 판정 근거가 없는 경우는 종전대로 건너뜁니다.
왜
이전에는 기본 브랜치 이름으로 가는 push를 원격과 상관없이 건너뛰었습니다. 그래서 fork의 main에서 PR을 여는 흐름에서는 문서 검사와 done 가드가 한 번도 돌지 않았고, 머지 = 종결 이후에는 가드 없는 종결로 이어집니다.
설치
init·sync는 옛 훅 블록이 릴리스 원문과 정확히 같을 때만 새 블록으로 바꾸고, 손댄 블록은 보존합니다. doctor는 옛 형식을 경고합니다.
Fixed · #197

원장만 바꾼 브랜치는 통과

무엇
diff가 전부 생성물 원장(docs/task_summary.md·docs/<user>/<user>-task.md)이면 ✓ pr-check <ref>: 생성물 원장만 변경 — task 문서 검사 대상 아님을 내고 통과합니다. 원장과 다른 파일이 섞이면 종전대로 판정합니다.
왜
원장 갱신 커밋만 담은 브랜치는 "task 문서가 없음"으로 막혔고, 보호 브랜치 저장소에서는 --no-verify 말고 길이 없었습니다.
경계
다른 파일을 원장 경로로 옮긴 커밋이 원장 전용으로 통과하지 않도록 --no-renames로 판정합니다.

migrate --adopt-reviews 후보 정정

Changed · #196

기본 브랜치에서 종결된 task는 후보가 아니다

무엇
기본 브랜치에서 이미 종결된 task를 채택 후보에서 뺍니다. 재개 MR이 머지되기 전인 task, 로컬 plan만 종결된 task, 기본 브랜치 ref를 모르는 경우는 종전대로 후보입니다. fetch하지 않습니다.
왜
종결된 task는 done 가드를 다시 지나지 않습니다. 후보로 보이던 "검증 마커 N개가 빠짐 → 리뷰 재실행 필요"는 실제로 치를 일이 없는 비용이었습니다.
