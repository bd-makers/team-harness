01 / 03 · 머지된 task를 위키로

"이 기능은 왜 이렇게 생겼나"를 task 폴더를 뒤지지 않고 위키 한 항목에서 읽는다

  • 화면/harness-wiki <user>/<task> · 머지 후 종결 절차
  • 제품S8 지식화 — 선택 단계

이전 문제

02 / 03 · 출처는 PR과 커밋

위키 단락마다 어느 PR·커밋에서 왔는지 남고, 확정할 수 없으면 추측하지 않고 멈춘다

  • 화면harness-team wiki sources --json · provenance · marker
  • 제품출처 마커 — 팀원이 무엇을 바꿨나
  • 소스src/commands/wiki.mjs · introducingCommit · prFromCommit · isShallowRepository

이전 문제

지식의 주소가 task 폴더 경로였다. C2에서 폴더를 지우면 그 경로는 끊긴다. PR 번호를 LLM이 손으로 적으면 추측이 섞이고 형식이 갈린다.

개선

first-parent 이력에서 task 폴더를 들여온 커밋을 찾아 Merge pull request #N·(#N)·GitLab !N을 읽는다. 작성자는 meta의 user. 얕은 클론이나 번호 없음은 막힘으로 돌려준다.

변경 후

03 / 03 · 다시 돌려도 한 번만

같은 task를 다시 컴파일해도 위키에 같은 단락이 두 번 생기지 않는다

이전 문제

무엇을 이미 위키에 옮겼는지 판정할 표식이 없다. 재실행하면 같은 내용이 또 쌓이고, 규칙 문서에 적힌 예시나 이름이 비슷한 task를 실제 기록으로 오인할 수 있다.

개선

단락 첫 줄의 harness:wiki 마커를 검색한다. task= 값이 정확히 같을 때만, 펜스 코드 블록 밖에서만 센다. 이미 있으면 멈추고, 재컴파일을 요청하면 그 단락만 교체한다.
