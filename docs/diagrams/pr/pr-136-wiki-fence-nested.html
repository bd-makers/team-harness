01 / 02 · 규칙 문서의 예시 마커

작성 규칙 문서가 마커 예시를 인용문·목록 안에 쓰면, 그 task는 컴파일되지 않고 "이미 컴파일됨"으로 멈췄다

  • 화면harness-team wiki sources <user>/<task> · /harness-wiki 의 compiled 판정
  • 제품C1 위키 컴파일 — 같은 task 재컴파일 방지(멱등 검색)
  • 소스src/commands/wiki.mjs · findCompiled → wikiMarkersIn

이전 문제

이미 컴파일된 위치를 찾을 때 펜스 안 예시 마커는 빼야 하는데, 줄머리 0–3칸 펜스만 펜스로 봤다. > ``` 인용문이나 깊은 목록 안 펜스의 예시 <!-- harness:wiki task=… --> 를 실제 마커로 세어 compiled 로 보고했다.

개선

인용 접두(> 반복)와 목록 표지를 벗긴 뒤 그 컨테이너의 내용 열 기준으로 펜스를 판정한다. 인용문·목록 안 펜스의 예시는 세지 않고, 펜스 밖 실제 마커(인용문 안 포함)는 그대로 센다.

02 / 02 · 펜스를 너무 넓게 보지 않기

펜스를 더 알아보되, 닫히지 않은 펜스가 뒤의 실제 마커를 삼켜 같은 task를 다시 컴파일하지 않게 한다

  • 화면harness-team wiki sources · compiled 판정
  • 제품재컴파일·단락 중복 방지 — 미인식(멈춤)보다 과인식(중복)이 나쁘다
  • 소스wikiMarkersIn · FENCE_OPEN_RE · FENCE_CLOSE_RE · 인용 깊이 · 목록 내용 열

이전 문제

펜스 상태 기계가 맨 위 펜스만 알았다. 인용문·목록 안에서는 여는 전이가 없어 예시 줄이 펜스 밖 내용으로 읽혔다. 단순히 들여쓰기 제한을 풀면 들여쓴 코드나 끝난 목록의 펜스가 열린 채 남아 실제 마커를 삼킨다.

개선

여는 펜스와 닫는 펜스 모두 컨테이너 내용 열에서 3칸 이내만 인정한다. 4칸 이상은 들여쓴 코드다. 인용문이 얕아지거나 목록 내용 열보다 내어 쓴 줄이 오면 그 안의 펜스는 강제로 끝나고, 그 줄은 펜스 밖에서 다시 판정한다.
