01 / 03 · 넘었는데 green

점검이 통과했다고 말하는데, 매 세션 실제로 들어가는 지시는 예산을 넘고 있었다.

  • 화면harness-team doctor 출력 · 마지막 N warning(s) 줄
  • 제품하네스 무결성 점검 · eager 계층 크기 예산
  • 소스src/commands/doctor.mjs · checkEagerTierSize

이전 문제

점검이 프로젝트 루트 두 파일만 셌다. 매 세션 함께 로드되는 나머지 두 소스는 세지 않아, 실제 합계가 예산을 넘어도 eager tier size 경고가 뜨지 않고 0 warning(s)로 끝났다. 사용자는 여유가 있다고 믿는다.

개선

매 세션 무조건 로드되는 네 소스를 모두 합산해 판정한다. 어느 파일에서 온 바이트인지 컨텍스트 윈도우는 구분하지 않으므로, 예산은 부분이 아니라 합계에 건다.

변경 후

02 / 03 · 주범을 짚는 경고

경고는 떴는데, 어느 파일을 줄여야 하는지도 건드려도 되는 파일인지도 알 수 없었다.

  • 화면harness-team doctor 출력 · ⚠️ eager tier size 줄
  • 제품경고 문구 · 조치 안내
  • 소스src/commands/doctor.mjs · 경고 문자열 조립부

이전 문제

합계 한 덩어리만 보여 주고, 처방은 프로젝트용 하나였다 — "절차를 lazy 정본으로 옮기세요". 전역 파일이 주범일 때 이 안내는 하네스가 건드려서는 안 되는, 프로젝트 밖 사용자 소유 파일을 향한다.

개선

파일별 바이트를 나열해 주범을 눈으로 짚게 하고, 전역은 해결된 실제 경로를 출력한다. 처방도 갈랐다 — 프로젝트에는 이관 안내, 전역에는 "읽기만 하며 조치는 사용자 판단"이라는 사실 보고.

변경 전

변경 후

03 / 03 · 넓히며 생기는 위험

측정 대상을 넓히면 같은 파일이 두 경로로 잡혀, 멀쩡한 프로젝트가 경고를 받을 수 있다.

  • 화면harness-team doctor 출력 · 경고 유무
  • 제품측정 정확도 · 오탐 방지 가드
  • 소스src/commands/doctor.mjs · globalClaudeMdPath · dedupe

이전 문제

대상을 넓히기만 하면 같은 파일을 두 번 세는 경로가 둘 생긴다 — 설정 홈 자체를 점검 대상으로 돌릴 때, 그리고 설정 홈 값이 절대경로가 아니라 현재 디렉터리 기준으로 풀릴 때. 둘 다 합계를 부풀려 없는 초과를 만든다.

개선

경로를 정규화해 같은 파일은 한 번만 세고, 절대경로가 아닌 설정 홈은 전역 항목 자체를 건너뛴다. 두 가드 모두 테스트로 고정했고, 가드를 빼면 실제로 실패하는 것까지 확인했다.
