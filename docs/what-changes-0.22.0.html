새로 생긴 것 — 두 개의 표

둘 다 “무엇이 있는지”가 아니라 “무엇을 안 해도 되는지”에 답하는 표입니다.

Added

벤더링되지 않은 스킬 — prerequisites.md §5

변경
조사 결론이 그대로 문서의 핵심이 됐습니다: 비번들은 diagram-design 하나뿐이고, 슬래시 커맨드 24종과 짝 스킬 + Codex 전용 스킬 2종(harness-team·harness-codex-sim)은 전부 플러그인 번들이라 따로 설치할 것이 없습니다.
왜
기존 문서는 외부 CLI 도구 5종만 능력 매트릭스로 다뤘습니다. “따로 설치할 스킬이 있나?”라는 질문에 답이 없었고, 답은 “설치 목록이 짧다”가 아니라 “나머지는 설치할 필요가 없다”입니다 — 그 사실 자체가 정보입니다.
그래서
doctor가 diagram-design을 검사하지 않는 이유도 적었습니다 — 다이어그램을 옵트아웃한 사용자에게는 부재가 오탐이기 때문입니다.
Added

전체 스킬 로스터 — simulation

변경
24 커맨드 + 커맨드 없는 스킬 2종을 배지 5종(기본 · 옵트인 · 조건부 · 페르소나 · 상황별)으로 분류한 표를 신설했습니다.
왜
설계의 핵심은 “옵트인”의 범위를 좁게 정의한 것입니다. 결정론 계약으로 선언된 옵트인은 셋뿐입니다 — 다이어그램 단계, ## Done evidence의 review·verify, ## Boundary contracts. “작은 버그엔 생략 가능”은 계약이 아니라 규범입니다.
그래서
둘을 같은 배지로 묶으면 표가 거짓말을 합니다 — 독자가 규범을 계약으로 오해하면 하지 않아도 될 것을 하거나, 반대로 강제되는 것을 건너뜁니다.

생성 문서라고 최신인 것은 아닙니다

이번 릴리스가 드러낸 구조적 사실입니다. harness-overview.html은 npm run docs:generate 산출물이고 docs:check가 CI에서 green이었는데도 v0.18.1을 표시하고 있었습니다.

자동 갱신되는 것은 인벤토리(커맨드 표)뿐이고, hero 배지 · 배너 산문 · footer는 템플릿 하드코딩입니다. “생성물이니까 정확하다”는 가정이 이 문서의 산문을 세 릴리스 동안 방치했습니다. 게다가 배너에는 “⚠️ 다음 릴리스 예고” 블록이 남아, 0.19.0에서 이미 출시된 Node 24와 firstActivatedAt을 아직 미래형으로 예고하고 있었습니다.

세 갈래 문서의 결합 강도가 그대로 낡은 정도로 나타났습니다.

가드가 걸린 축은 정확했고, 걸리지 않은 축만 틀렸습니다. 다만 이 문서들은 산문이라 결정론적 대조 대상을 만들기 어렵습니다 — 실효적인 대책은 릴리스 절차에서 문서 세대를 함께 확인하는 것이며, 그것은 이번 범위가 아니라 MAINTAINING.md 쪽 후속입니다.

이 릴리스가 남기는 것

세는 문장은 그 수를 부르는 모든 곳이 갱신 대상이다

가드 개수 하나가 네 문서 열 곳과 SVG 라벨 하나에 있었습니다. 0.21.0이 “지울 대상이 아니라 그 대상을 이름으로 부르는 모든 곳”을 계획에 적으라고 남겼는데, 이번 것은 그 규칙의 세기 버전입니다 — 숫자를 바꾸는 변경은 그 숫자를 말하는 모든 표면을 함께 세야 합니다.

아직 안 한 단계를 - [x]로 켜지 않는다

작업을 다 끝낸 뒤 task를 소급 생성하면서 plan을 완료 상태로 한 번에 썼습니다. 그런데 “외부 리뷰 실행 후 artifact에 기록”은 그 시점에 아직 하지 않은 단계였고, 커밋된 상태가 스스로에 대해 거짓말을 했습니다. codex 외부 리뷰가 정확히 그 지점을 P2로 집었고, done 가드도 독립적으로 같은 것을 막았습니다.

정방향(계획 → 실행)에서는 체크가 실행을 따라가지만, 역방향(실행 → 기록)에서는 “이미 다 했다”는 감각이 아직 안 한 단계까지 함께 켭니다. 소급 task의 고유한 함정입니다. task guide §8이 경고하는 “체크로 위장”을, 하필 그 문서를 고치면서 저질렀습니다.

다행히 강제 장치가 잡았습니다 — spec에 review: required를 선언해 뒀기 때문입니다. 선언이 없었으면 조용히 지나갔습니다. 결정론 가드와 D6 검증자가 독립적으로 같은 결론에 도달한 첫 사례입니다.

검증

npm test 453 pass / 0 fail, npm run docs:check 최신, harness-team doctor 전항목 통과. 두 가이드 HTML 태그 균형 검사 0건, 0.21.0 스냅샷 2종이 각각 현재 문서와 byte-identical. 별도 컨텍스트의 read-only codex 외부 리뷰는 P2 1건 — 수정 후 승인이었고, 그 P2는 재현해 확인한 진짜 결함이었습니다(위 참조). 그 외 유의미한 발견은 없었습니다.
