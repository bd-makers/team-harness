Added · #125

harness-team pr-check + git pre-push 훅

대상
active.json이 아니라 base...rev diff가 건드린 task 디렉터리입니다. 내용은 작업 트리가 아니라 커밋에서 읽습니다 — push·CI가 보는 것과 같습니다.
판정
task마다 spec·plan·handoff·artifact가 있고, 비어 있지 않으며, 템플릿 그대로가 아니어야 합니다. 실패면 exit 1. 같은 검사를 pre-push 훅·/harness-ship·원하는 팀의 CI가 돌립니다.
통과
기본 브랜치·태그·삭제·빈 원격 첫 push. PATH의 CLI가 없거나 pr-check를 모르는 구버전이면 fail-open입니다. 우회는 git 표준 git push --no-verify.
훅
기존 pre-push 훅(git-lfs 등)이 있으면 맨 위에 넣고 ref 목록(stdin)을 되돌려 줍니다 — 뒤의 기존 줄은 같은 입력을 읽습니다. 셸이 아닌 훅은 건너뜁니다. husky·lefthook은 README pr-check 절의 블록을 관리자 설정 맨 위에 넣습니다.
Added · #126

doctor pre-push hook (pr-check) 검사

원인
훅 관리자가 훅 파일을 다시 쓰면 블록이 조용히 사라지고, pre-push 훅이 없는 기존 설치본도 알 길이 없었습니다.
지금
git이 읽는 pre-push 훅에 블록이 없으면 warning과 harness-team sync 처방을 냅니다. 셸이 아닌 훅은 직접 호출을, core.hooksPath(관리자 소유)는 판정 없이 README 블록을 안내합니다.

커밋 게이트는 팀 파일, 언어 지식은 프리셋

훅 안의 언어별 분기(PM 추론·tsc/test·하드코딩 prettier)를 지우고, 팀이 커밋하는 .harness/gates.json 목록만 실행합니다.

Changed · #123

gate commit·gate format이 .harness/gates.json을 실행

원인
D11 — 언어·도구 지식은 코드가 아니라 프리셋 데이터로 둡니다. 훅에 박힌 명령은 팀이 바꿀 수도, 같은 목록을 공유할 수도 없었습니다.
지금
pre-commit-check.sh·auto-format.sh는 얇은 래퍼입니다. init이 스택 프리셋(node·python·generic)으로 목록을 제안하고 확인받아 기록하며, gate suggest로 다시 제안받습니다. doctor는 확정 시점의 지문과 달라지면 제안만 합니다.
차단
명령 exit 127과 깨진 gates.json은 설정 오류로 차단합니다. 파일이 없으면 통과 + 안내, CLI가 없으면 경고 후 통과, CLI가 gate를 모르는 구버전이면 차단입니다.
유지
--yes에서는 예전 훅에 없던 명령(node lint, python ruff·pytest)을 빼고 추가 제안으로만 보여 줍니다. prettier 의존성이 없으면 format은 제안되지 않습니다(예전 훅은 무조건 npx prettier).

Fixed · #128

post-commit도 기존 훅 맨 위에, 셸이 아닌 훅은 건너뜀

원인
post-commit은 기존 훅 끝에 붙었습니다. 앞선 exit·exec 뒤에서는 handoff가 조용히 안 돌았고(git-lfs 훅은 lfs가 없으면 exit 2), python·node 훅은 셸 줄 때문에 문법 오류로 죽었습니다.
지금
pre-push와 같은 경로입니다 — shebang 다음 맨 위에 넣고, 셸이 아닌 훅은 건드리지 않고 harness-team handoff 직접 호출을 안내합니다. 개행 없는 #!/bin/sh 한 줄짜리 훅에서 shebang이 깨지던 것도 고쳤습니다.
한계
이미 줄이 붙은 설치본은 고치지 않습니다. exit 뒤의 줄은 손으로 맨 위로 옮기고, 셸이 아닌 훅에 붙은 줄은 지운 뒤 그 훅에서 harness-team handoff를 부르세요.
Fixed · #129

빈 task 문서를 pr-check·done이 막는다

원인
두 가드는 "템플릿 그대로인가"(plan은 "미완 - [ ]가 남았는가")만 봐서 0바이트·공백뿐인 문서는 통과했습니다. 실례로 미완 단계를 남긴 plan이 0바이트로 커밋된 task가 있었습니다.
지금
pr-check는 <문서> 가 비어 있음으로 막고, done은 빈 plan·빈 artifact를 차단 사유로 냅니다. plan 파일이 아예 없을 때의 done 동작은 그대로입니다(부재는 pr-check가 막습니다).

소비자가 할 일

Do · 1

플러그인 갱신 — 팀원 전원

왜
새 명령·판정은 CLI 코드라 플러그인 채널로만 옵니다. migrate가 깐 새 훅 래퍼는 gate를 모르는 구버전 CLI에서 커밋을 막으므로, 한 사람이 아니라 팀 전체가 올려야 합니다.
어떻게
/plugin marketplace update(또는 clone에서 git pull). harness-team --version이 0.46.0이면 됩니다.
Do · 2

harness-team sync 한 번

왜
pre-push 훅은 init·sync만 설치합니다. migrate는 git 훅을 설치하지 않습니다. 돌리기 전까지 doctor가 pre-push hook (pr-check) 경고를 냅니다.
어떻게
각자의 clone에서 harness-team sync. git 훅은 커밋되지 않으므로 팀원마다 한 번씩입니다. husky·lefthook을 쓰면 README pr-check 절의 블록을 관리자 설정 맨 위에 넣고 커밋합니다.
Do · 3

harness-team migrate → .harness/gates.json 커밋

왜
stock 커밋 게이트 훅을 새 래퍼로 바꾸고, gates.json이 없으면 프리셋 제안을 확인받아 기록합니다(--yes면 이전 typecheck·test 동작만).
어떻게
기본 브랜치에서 한 사람이 harness-team migrate → 생긴 .harness/gates.json을 커밋합니다. workspace를 쓰던 저장소는 첫 doctor의 모양 single → … drift를 harness-team gate suggest로 확정합니다.
Do · 4 (선택)

관리 절 갱신과 제거 목록 확인

관리 절
AGENTS.md 결정 규범의 D7 줄 제거를 받으려면 harness-team init --yes. 받지 않아도 동작은 같습니다.
제거
harness-team backup|clone|symlink|delete|upgrade나 init 백업 플래그를 부르는 스크립트가 있다면 지우세요 — 알 수 없는 명령·플래그로 실패합니다.
