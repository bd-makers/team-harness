파일별 역할

chad-handoff.md — 세션 포인터

어떤 task가 활성인지 + 마지막 작업 메모. 상세 내용은 task별 handoff에 위임. post-commit hook이 자동 갱신.

[task]-handoff.md — task 컨텍스트

해당 task의 누적 작업 기록. commit마다 git diff 기반으로 자동 append. task 전환 후 재개 시 이 파일로 컨텍스트 복원.

[task]-plan.md — 체크리스트

단계별 완료 체크. post-commit hook이 완료 여부를 감지해 done 처리 여부를 Claude에게 알림.

[task]-artifact.md — 결과·학습

실행 결과와 학습/교정을 기록. done·retro 시 append. 종결 가드가 이 파일 작성 여부를 done의 전제 조건으로 검사.

확정 명령어 인터페이스

최소한의 명령어 — 나머지는 자동화 또는 AskUserQuestion

harness-team task <name>

task 생성 + 활성화. feature/fix 구분 없이 이름으로 식별. 이미 존재하면 활성화만.

harness-team list

전체 task 목록 + 현재 active task 표시. chad-task.md 기반.

harness-team done

수동 완료 트리거. 종결 가드(plan·artifact·커밋 검사) 통과 후 AskUserQuestion 확인 → 완료 처리. plan 완료 감지나 발화로도 트리거됨.

harness-team handoff

post-commit hook 전용 (.git/hooks/post-commit에서 자동 실행). git log/diff 기반으로 <name>-handoff.md와 <user>-handoff.md를 갱신.

제거된 명령어: new, feature/fix 구분, spec, plan, handoff(수동), switch — 모두 자동화 또는 자연어 인터페이스로 대체. 사용자가 기억해야 할 명령어는 task, list, done 세 가지뿐.
에이전트 구동 (--json, 0.8.0): Codex·OpenCode가 harness-team를 Bash로 호출할 때 --json을 주면 stdout이 구조화 observation 엔벨로프({status, summary, next_actions, artifacts, error}) 1개로 나와 다음 행동을 파싱할 수 있습니다. 사람용 출력은 그대로 — 상세는 overview 문서의 "CLI Observation 계약" 참조.
