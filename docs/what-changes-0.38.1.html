커밋할 때마다 트리가
다시 더러워졌습니다

0.38.1은 post-commit 훅이 만드는 끝나지 않는 churn을 고칩니다. 훅은 커밋 뒤에 핸드오프 두 파일을 쓰므로 커밋 직후 트리는 항상 dirty이고, 그 변경을 쓸어 담는 커밋이 다시 훅을 돌려 새 항목을 만듭니다 — 자기 자신을 먹이는 루프라 깨끗해지는 지점이 없었습니다. 이제 핸드오프 파일만 바꾼 커밋에는 훅이 아무것도 쓰지 않습니다. 함께 드러난 done 가드의 경로 파싱 결함 두 건도 고쳤습니다.

루프는 이렇게 돌았습니다

0.38.0까지0.38.1
작업 커밋 직후훅이 핸드오프 2파일을 씀 → dirty동일 — 여기까지는 정상이다
그 churn을 쓸어 담는 커밋훅이 또 항목을 씀 → 다시 dirty침묵 — 기록할 작업이 없다
결과트리가 깨끗해지는 지점이 없음sweep 커밋 한 번으로 끝

실제 비용. 0.38.0 릴리스에서 이 루프 때문에 post-commit 훅을 세 번 비켜 놓고 커밋해야 했습니다. 훅을 손으로 옮겼다 되돌리는 절차는 잊으면 훅이 사라진 채로 남는 종류의 조작입니다.

판정은 보수적입니다 — 건너뛰기보다 기록하는 쪽으로 틀립니다

Fixed

핸드오프만 바꾼 커밋 → 기록하지 않음

판정
경로가 하나 이상이고 전부 핸드오프 파일일 때만 건너뜁니다. 제외 경로 집합은 done 가드가 "훅 자신의 출력"으로 무시하는 것과 같은 함수(handoffRelPaths)에서 나옵니다.
기록하는 경우
병합 커밋(부모 2개 이상) · 빈 커밋 · git 실패 — 모두 종전대로 기록합니다.
Design

"경로가 비었다"로 판정하지 않습니다

실측
diff-tree --name-only는 병합 커밋에 아무 경로도 내지 않습니다. [].every()는 참이므로 순진한 구현은 병합을 조용히 누락시킵니다.
대응
부모 수를 먼저 세고, 둘 이상이면 판정 자체를 하지 않습니다.
Fixed

submodule 변경이 숨는 설정

증상
submodule.<name>.ignore=all이면 gitlink 변경이 diff-tree 출력에서 사라집니다 — submodule을 bump한 진짜 작업 커밋이 sweep으로 오인됩니다.
조치
--ignore-submodules=none. 수정을 빼면 실패하는 회귀 테스트로 고정했습니다.

done 가드가 함께 고쳐졌습니다

훅과 가드가 같은 경로 집합을 공유하게 되면서, 가드 쪽 파싱 결함 두 건이 드러났습니다. 둘 다 기존 결함입니다.

결함결과조치
비-ASCII 경로를 기본 --porcelain이 octal로 인용하는데 파서는 바깥 따옴표만 벗겼다비-ASCII user(= .harness/config.json의 config.user는 sanitize를 거치지 않는 자유 입력)에서 훅이 쓴 핸드오프가 제외 집합과 불일치 → "실제 dirty"로 계산돼 종결이 영구히 막힘--porcelain -z + NUL 파서
rename에서 목적지만 남겼다src/real.md -> docs/<u>/<u>-handoff.md 같은 staged rename이 핸드오프 제외에 통째로 삼켜져 원본의 삭제를 가드가 못 봄rename은 두 경로를 모두 반환

리뷰 — 오탐 판정이 두 번 뒤집혔습니다

codex 3회. 1차에서 오탐이라고 판정한 두 건이 2차에서 전부 진짜로 확인됐습니다. 기록해 둘 가치가 있는 실패입니다.

발견내 1차 판별실제
P2 submodule 변경이 숨을 수 있다오탐 — diff.ignoreSubmodules=all로 재현 안 됨진짜 — 실제 벡터는 submodule.<name>.ignore=all이었다. 다른 스위치로 실험했다
P2 octal escape로 경로가 어긋난다오탐 — member는 sanitize()가 거른다진짜 — config.user는 그 함수를 거치지 않는 두 번째 입력 경로다
P2 rename 원본 유실 · 테스트 변별력 없음진짜수정 — 양쪽 경로 반환 · 커밋이 두 경로를 담았음을 전제로 단언
P3 픽스처 실패가 pass로 기록됨진짜t.skip() — "검증하지 못했다"가 초록에 묻히지 않게

두 오탐 판정의 공통 모양: 내가 세운 불변식(설정 이름 · sanitize 경로) 안에서만 반증 실험을 돌렸습니다. 리뷰어가 지목한 것은 그 불변식 밖의 입력 경로였고, 그 경로로 재현하니 둘 다 재현됐습니다. 반박할 때는 상대가 지목한 정확한 설정·정확한 코드 경로로 실험해야 합니다.

소비자가 할 일

None

플러그인 갱신뿐입니다

왜
POST_COMMIT_HOOK 스크립트 텍스트는 바뀌지 않았습니다 — 수정은 runHandoffAuto 안이라 기존 설치는 플러그인 갱신만으로 고쳐집니다. init·migrate·훅 재설치가 필요 없습니다.
전역 CLI
훅은 PATH의 harness-team(= marketplace clone)을 부릅니다. clone을 갱신해야 새 동작이 실제로 적용됩니다.
Effect

이제 sweep 커밋 한 번으로 끝납니다

흐름
작업 커밋 → 훅이 핸드오프를 씀(dirty) → 그 변경만 커밋 → 훅 침묵, 트리 clean.
done 가드
핸드오프 제외는 그대로 필요합니다 — 작업 커밋 뒤에는 여전히 dirty이기 때문입니다. 바뀐 것은 그 dirt가 끝난다는 점입니다.
Known

--amend는 아직 중복 항목을 남깁니다

증상
amend는 훅을 다시 돌려 같은 논리 커밋에 두 번째 항목을 남기고, 첫 항목의 sha는 더 이상 존재하지 않습니다.
왜 미뤘나
정확한 판별자는 reflog입니다. ancestor+같은 부모 휴리스틱은 브랜치 전환과 구분하지 못해 진짜 항목을 지울 수 있어 쓰지 않았습니다.
