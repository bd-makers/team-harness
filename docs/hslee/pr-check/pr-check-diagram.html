pr-check — 하네스가 강제하는 유일한 검사

세 호출처가 같은 결정론적 검사를 부른다. 대상은 active.json이 아니라 base 대비 diff가 건드린 task이고, 내용은 작업 트리가 아니라 커밋에서 읽는다. 다이어그램은 권장이라 막지 않는다.

B. pre-push 훅 블록 — 기존 훅 맨 위에 들어간다

PLAN 대비 변화

리뷰 두 번이 바꾼 것

  • 훅 블록: 기존 훅 끝에 append → 맨 위 삽입 + stdin 되돌림 (git-lfs의 stdin 소비·exit 0·rc 덮어쓰기)
  • PR 다이어그램: 필수 + 생략 기록 → 권장 (생략 기록은 plan 옵트인 없으면 거부됨)
  • task 식별: spec 마커만 → <task>-* 문서 아무거나 (spec 빠진 task 누락 방지)
  • 빈 원격 첫 push: 차단 → 통과

강제 범위 · D11

막는 것은 4문서뿐

  • spec · plan · handoff · artifact가 rev에 있고 템플릿 그대로가 아님
  • 다이어그램은 안내만 (exit 0)
  • lint·tsc·리뷰는 "제공" — git pre-commit에 걸지 않음
