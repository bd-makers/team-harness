정확성 수정

증상을 덧대지 않고, 잘못된 판정을 만들던 문법과 파서의 원인을 닫았습니다.

Skilltest scorer

채점을 원문 정규식에서 코드 구조 판정으로 전환

변경
테스트 본문과 GWT/AAA 구획을 구문 단위로 판정하고, 문자열·템플릿·주석 내부 표식은 채점에서 제외했습니다. 이어서 따옴표 문자열이 실제 줄바꿈에서 끝나도록 문자열 건너뛰기를 바로잡았습니다.
왜
같은 원인의 오탐이 두 라운드에 걸쳐 다른 모습으로 나타났습니다. 개행에서 멈추지 않는 문자열 건너뛰기가 가짜 인용 구간을 만들어 정상 테스트를 조용히 실패시켰습니다.
그래서
문자열 속 가짜 마커가 통과·실패를 조작하지 못하고, 파서를 불신해 수동 판정으로 돌리던 우회 계층도 제거됐습니다.
Context grammar

Failure capsule의 제목·내용 문법을 함께 확정

변경
CommonMark에서 허용하는 하위 제목은 capsule 본문 범위에 남기되, 제목 줄 자체는 실질 내용으로 세지 않습니다. fenced code와 들여쓴 코드의 heading 유사 줄도 구분합니다.
왜
하위 제목이 본문인지 종결자인지 정해지지 않아 capsule 예산이 새고 있었습니다. 제목 깊이만 좁히면 빈 제목을 내용으로 세는 반대 방향의 오류가 생깁니다.
그래서
범위 판정과 내용 판정이 같은 문법을 사용해 빈 stub은 예산을 소비하지 않고, 실제 코드·설명은 누락되지 않습니다.

새 기능

모델의 기억이나 사후 리뷰에만 기대던 구간을 작은 상태와 결정론적 검사로 보강했습니다.

Task lifecycle

Task Context Card 생명주기와 세션 주입

변경
task마다 현재 atomic step, 제약, JIT 검색 단서, failure capsule을 담는 작은 *-context.md를 만들고 context init|check로 관리합니다. 유효한 카드만 SessionStart breadcrumb 뒤에 주입합니다.
왜
긴 task를 재개할 때 전체 SSOT를 다시 읽으면 비용이 크지만, 요약본을 새 정본으로 만들면 상태가 둘로 갈라집니다.
그래서
spec·plan·handoff·artifact는 계속 정본이고, 카드는 버릴 수 있는 working set으로만 동작합니다. 유효하지 않은 카드는 원문 대신 복구 안내를 냅니다.
Boundary contracts

생산자와 소비자 스키마를 동시에 검증

변경
spec에 선언된 생산자·소비자 JSON Schema의 필수 필드와 기본 type을 boundary check가 plan 단계 완료 전에 대조합니다.
왜
응답 래핑, 케이스 변환, 이름 불일치는 사후 리뷰나 한쪽 린터만으로 잡히지 않습니다. 양쪽 명세를 함께 봐야만 드러납니다.
그래서
모델의 추론이 아니라 결정론적 코드가 경계 불일치를 재현 가능하게 차단하고, 선언이 없는 task는 기존처럼 통과합니다.
Private observability

원문 없는 도구 호출 관측 기록

변경
도구 호출의 빈도, 소요 시간, 결과 크기와 제한 여부를 프로젝트 내부의 비공개 JSONL로 기록합니다. 식별자는 프로젝트별 HMAC 참조값만 남깁니다.
왜
관측이 없으면 성능 저하와 비용 급증의 원인을 짚을 수 없습니다. 반대로 원문을 저장하면 프롬프트·경로·자격증명이 로그로 샐 수 있습니다.
그래서
허용목록 메타데이터만 분석할 수 있고, 키를 안전하게 다루지 못하면 기록 자체를 건너뜁니다. 내용 유출 없이 병목을 찾을 수 있습니다.
Skill verification

에이전트 워크플로우를 실제 실행하는 L5 skilltest

변경
fixture 프로젝트에서 테스트 작성 스킬을 실제 에이전트 세션으로 구동하고, 생성된 테스트의 구조·실행 결과·production source 비파괴 여부를 채점합니다.
왜
기존 하네스는 설치된 scaffold와 CLI 흐름은 검증했지만, 자연어 스킬이 실제로 어떤 코드를 쓰는지는 보지 못했습니다.
그래서
스킬 프롬프트의 품질을 부작용으로 검증하고, 컴포넌트·통합 테스트 워크플로우도 각 테스트 경계에 맞춰 사용할 수 있습니다.

문서·유지보수

틀린 사본을 더 잘 갱신하는 대신, 사본을 없애거나 자동 생성 대상으로 바꿨습니다.

Drift guard

템플릿과 저장소 agent 문서의 managed section 대조

변경
apply가 실제 렌더하는 agent 파일 목록을 공유해 템플릿과 루트 적용본의 managed section 내용을 CI에서 비교합니다.
왜
템플릿만 고치고 적용본을 잊어 절이 조용히 사라진 사례가 있었습니다. 렌더 결과 테스트와 새 샌드박스 테스트는 이 저장소의 적용본 드리프트를 보지 못했습니다.
그래서
정본과 실제 dogfooding 문서가 어긋나면 릴리스 전에 실패하고, 검사 대상 목록 자체도 구현과 따로 복제되지 않습니다.
Release documentation

최신 변경 설명의 버전 드리프트를 릴리스 전에 차단

변경
릴리스 도구가 매니페스트 버전을 bump한 뒤 사람이 what-changes-latest-version.html을 검토·갱신하고 같은 내용을 what-changes-X.Y.Z.html에 남깁니다. Node 내장 테스트가 패키지 버전과 제목·요약, 스냅샷 존재, 두 파일의 완전한 일치를 검사합니다.
왜
latest라는 이름만으로는 이전 릴리스의 설명이 남아도 알기 어렵고, 스냅샷만 남기면 현재 문서의 갱신 누락을 막을 수 없습니다.
그래서
의도적으로 어긋난 버전 표기도 실패합니다. 사람이 작성한 변경 근거는 자동 생성하지 않은 채 최신 문서와 역사 기록을 함께 신뢰할 수 있습니다.
Single source

중복 인벤토리를 제거하고 정본 포인터로 축소

변경
README·개요 등에 복제돼 있던 명령·파일 목록을 제거하고 manifest, skill, source tree 같은 소유자를 가리키도록 바꿨습니다.
왜
같은 목록이 여러 곳에 있어 하나를 고쳐도 나머지가 계속 틀렸습니다. 사본을 유지하는 행위 자체가 결함의 원인이었습니다.
그래서
목록을 최신화하는 별도 작업이 줄고, 실제 지원 범위는 항상 해당 정본에서 확인하게 됩니다.
Generated docs

아키텍처 개요를 소스 기반 생성물로 전환

변경
Mermaid 원본, command frontmatter, manifest와 git 추적 소스에서 harness-overview.html을 생성합니다. 직접 편집 대신 docs:generate가 산출물을 갱신합니다.
왜
큰 inline SVG 한 줄에서 라벨을 손으로 고쳐야 했고 실제로 낡은 라벨이 남았습니다. 문서 표도 소스의 또 다른 사본이라 계속 틀어졌습니다.
그래서
다이어그램과 인벤토리의 리뷰 가능한 원본이 생기고, docs:check가 생성물 드리프트를 차단합니다.
Removal

고아 리포트 템플릿 제거

변경
아무 코드나 문서도 참조하지 않는 harness-sim 리포트 템플릿을 삭제했습니다.
왜
템플릿이 실제 출력과 맞지 않았고, 맞춰 고치면 실제 생성 로직과 별개로 손으로 유지할 사본이 하나 더 생깁니다.
그래서
사용되지 않는 계약처럼 보이는 파일이 사라지고, 실제 리포트 형식은 실행 코드와 스킬 절차에서만 결정됩니다.
Positioning

설정·상태 하네스와 단일 스레드 쓰기로 역할 정정

변경
프로젝트를 런타임 오케스트레이터가 아닌 설정·상태 하네스로 설명하고, OpenCode를 병렬 작성자가 아닌 순차 전환 드라이버로 명시했습니다.
왜
이 프로젝트가 직접 소유하지 않는 지휘·작업큐·격리 기능을 암시했고, 병렬 쓰기는 충돌과 신뢰성 위험을 키웁니다.
그래서
탐색용 격리 서브에이전트는 유지하면서, 코드 쓰기와 결정은 하나의 흐름으로 이어지는 실제 운영 모델과 문서가 일치합니다.

이번 릴리스가 택한 방향

기능들은 달라도 설계 결정은 같은 원칙으로 수렴합니다.

추측보다 결정론

구문 채점, context 검사, boundary 대조, docs drift 검사는 모델의 기억이나 사후 해석 대신 재현 가능한 코드가 판정합니다.

사본보다 정본

동적 명령 목록과 파일 인벤토리는 이 문서에 복제하지 않습니다. 지원 명령은 plugin manifest와 각 command·skill을, task 계약은 AGENTS.md를, 아키텍처 파일 목록은 생성된 overview와 그 소스를 참조합니다.
