Fixed · #157

인프로세스 드라이버만이면 docker 확인을 빼고 이유를 말한다

전
ORM이나 DB 드라이버가 하나라도 감지되면 "통합 테스트라면 docker info로 testcontainers 가용성을 직접 확인하세요"를 냈습니다.
후
감지된 드라이버가 전부 인프로세스면 "인프로세스 DB(better-sqlite3)라 testcontainers·docker 확인은 필요 없습니다"를 냅니다. 그 밖의 경우는 종전 문구 그대로입니다.
Why

같은 0단계의 문서와 CLI

이유
/harness-unittest·/harness-comptest·/harness-inttest의 0단계는 stack 출력을 그대로 읽습니다. 문서는 건너뛰라 하고 CLI는 확인하라 하면, 에이전트는 둘 중 더 구체적인 쪽을 따르기 쉽습니다.
감지 범위. 인프로세스로 아는 드라이버는 현재 감지 목록에 있는 better-sqlite3 하나입니다. 내장 node:sqlite는 의존성이 아니라 드라이버로 감지되지 않고, sql.js·pglite는 감지 목록에 없어 이 분기를 타지 않습니다 — 그런 프로젝트는 종전처럼 문서(/harness-inttest 0단계)의 판단을 따릅니다.
