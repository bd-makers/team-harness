Release note · 2026-09-19 · minor

산문으로 세 벌 들고 있던 절차가
명령 네 개가 됐습니다

0.40.0은 슬래시 커맨드 문서가 에이전트에게 "손으로 하라"고 적어 두던 절차 네 가지 — 스택 감지, 리뷰/ship 범위 판정, config.json 저장, 다이어그램 기록 — 를 harness-team 하위 명령으로 내립니다. 같은 절차가 세 문서에 세 벌로 복제돼 이미 드리프트가 나 있었고(단계 번호·예외 참조·문구), 판정이 없는 부분만 CLI가 소유하고 판단이 남는 부분은 산문에 그대로 둡니다. 함께 review가 base를 origin/main으로 하드코딩하던 결함을 고쳤습니다.

Fixed · task scope-resolve-cli

review가 base를 origin/main으로 하드코딩

무엇
기본 브랜치가 master·develop인 저장소에서 그 ref가 없으면 죽고, 동명의 낡은 로컬 브랜치가 있으면 엉뚱한 diff를 조용히 리뷰했다. 같은 저장소의 remote-task.mjs는 이미 올바르게 판정하고 있었다 — 취향 차이가 아니라 불일치였다.
이제
origin이 있으면 origin/HEAD → origin/main → origin/master 중 실재하는 것만, 하나도 없으면 로컬로 때우지 않고 에러. 로컬 main은 origin이 아예 없을 때만 base다. isSyncedWithDefault(summary --write 가드)의 무폴백은 의도적으로 통일하지 않았다 — 후보를 넓히면 낡은 origin/master tip에 선 브랜치까지 --write가 열린다.
