0.23.0은 Anthropic의 “The New Rules of Context Engineering for Claude 5 Generation Models” 검토 결과를 반영합니다. 검토에서 확인된 것: 하네스는 이미 점진적 공개(lazy 커맨드 문서·스킬)와 인터페이스로 가르치기(가드 실패 메시지)를 선취하고 있었습니다. 빠져 있던 것은 세 가지 — always-on 계층의 예산, auto-memory 시대의 학습 저장 경계, 상한 없는 주입 경로 하나였습니다. 이번 릴리스는 그 세 가지를 채우고, 발견 김에 무관한 배포 위생 결함 하나를 고칩니다.

그래서
의도적으로 하지 않은 것도 있습니다: 테스트 3형제(unittest·comptest·inttest)의 ~200줄 고정 파이프라인은 유지했습니다 — 블로그 스스로 “중요 영역에는 과제약 유지” 예외를 뒀고, 이들은 lazy 로드되는 결정론적 품질 게이트이기 때문입니다.

고친 결함

컨텍스트 엔지니어링 검토와는 별개로, 후속 작업 중 발견한 배포 위생 결함 하나입니다.

Fixed

copyStaticAssets의 stack 무관 rules 복사

변경
React Native 전용 rules 4종(navigation.md·state-management.md·styling.md·testing.md, Expo Router 등)이 --stack python|node|generic 프로젝트에도 무조건 복사됐습니다. 명시적 비-RN --stack에는 이 4종을 제외하고, RN 계열(react-native)과 --stack 미지정(자동감지 경로)에는 기존 동작을 유지합니다.
왜
paths: frontmatter 덕에 세션 시작 토큰 비용은 0이었으므로 성능 결함이 아니라 배포 위생 문제였습니다 — python·node·generic 프로젝트에 RN 가이드가 놓여 있는 것 자체가 잘못된 신호였습니다.
그래서
하위 호환을 위해 게이트는 명시 플래그에만 걸고 자동감지 결과로는 걸지 않습니다 — 스택을 못 정한 프로젝트가 갑자기 가이드를 잃는 회귀를 피했습니다.

이 릴리스가 남기는 것

측정되지 않는 계층은 관리되지 않는다

TCC 6 KiB 예산은 처음부터 있었습니다. 그런데 그보다 훨씬 자주, 훨씬 크게 로드되는 AGENTS.md + CLAUDE.md 계층에는 아무 숫자도 없었습니다. “중요하니까 항상 로드한다”는 판단과 “그래서 크기 제한이 없어도 된다”는 결론은 별개입니다. eager 계층이야말로 매 세션 비용을 내는 계층이라, 오히려 더 엄격하게 재야 했습니다.

과제약을 걷어내는 것과 장치를 걷어내는 것은 다르다

CLAUDE.md.hbs §4·§5·§6 압축은 서술을 줄였지 레버를 줄이지 않았습니다. 페르소나 호출 순서, 예외 조건, 복잡도 게이트는 그대로입니다. Anthropic의 관찰(시스템 프롬프트 80% 삭제 후 손실 없음)을 그대로 옮겨 적용하면 장치까지 걷어낼 위험이 있었는데, 이 저장소의 0.8.0 기록(“선언 레버 9개 중 실제 가동 1개”)이 어느 쪽이 실제로 안 지켜지고 있었는지 — 서술이었는지 장치였는지 — 구분하는 근거가 됐습니다. 테스트 3형제 파이프라인처럼 결정론적 품질 게이트는 압축 대상에서 아예 제외했습니다.

npm test 전체 스위트 통과, 새 doctor·session-context 테스트 포함. 별도 컨텍스트의 read-only codex 외부 리뷰 2회 — PR #64에서 P2(stat 예외 전파)·P3(tie-break user 누락) 각 1건을 확정해 반영했고, PR #65는 무발견이었습니다.
