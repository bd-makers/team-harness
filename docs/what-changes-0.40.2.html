왜 patch로 끊었나 — ① 표면이 잘못 동작했다

크기 기준표의 "① 표면의 수정(잘못 동작하던 것을 고침) = patch"입니다. 바뀐 것은 src/git-hooks.mjs — 플러그인 채널로 도달하는 ① 표면이고, 고친 것은 사람의 이해가 아니라 기계의 동작입니다.

표면상태판단
src/git-hooks.mjs (① 플러그인 채널) init·sync·migrate 세 커맨드가 모두 이 함수를 부른다. 훅이 안 깔리면 셋 다 조용히 반쪽이 된다 patch. 잘못 동작하던 것의 수정 — 계약이 바뀌지 않았다
templates/** 한 줄도 바뀌지 않음 init 재실행·migrate가 필요 없다
훅 스크립트 텍스트 불변 — 바뀐 것은 설치할 자리를 만드느냐뿐 stock fixture·sha 테이블 갱신 불필요

고친 것

Fixed · src

디렉터리 부재를 한 덩어리로 보던 것

무엇
훅 디렉터리가 없으면 무조건 skipping 한 줄을 찍고 돌아왔다. 그 한 줄은 init의 긴 출력에 묻히고, 커맨드는 exit 0으로 끝난다.
왜 틀렸나
부재는 두 경우이고 처방이 정반대다. core.hooksPath가 설정돼 있는데 없다면 그 디렉터리는 husky·lefthook 소유다 — 만들면 남의 매니저에 우리 훅을 밀어 넣는 것이라 건드리면 안 된다. core.hooksPath가 없는데 .git/hooks가 없다면 그건 git이 실제로 읽는 경로이고, 비어 있는 init.templateDir나 가지친 클론이면 정상적으로 생길 수 있다 — 우리가 만들 자리다.
어떻게
hasCustomHooksPath()로 git config --get core.hooksPath를 읽어 갈랐다. 설정돼 있으면 종전 그대로 안내만, 없으면 mkdir -p 후 설치한다. 판정 불가(git 실패)는 exit 1을 "미설정"으로 읽으므로 만드는 쪽으로 틀린다 — 훅이 하나 더 깔리는 것이 영영 안 깔리는 것보다 낫다.
Evidence

임시 디렉터리 60종이 못 잡고 실전 1회가 잡았다

어디서
bodoc4(2026-09-21). hs-style-pack install --mirror → harness-team init --yes가 전부 성공을 보고했는데 .git/hooks/post-commit이 없었다.
왜 테스트가 못 잡았나
테스트 픽스처는 git init으로 만들어져 항상 .git/hooks를 갖는다. 이 결함은 템플릿 없이 만들어진 저장소에서만 나타난다 — 야생에서만 나오는 종류다.
고정
tests/git-hooks.test.mjs에 hooks 디렉터리를 지운 저장소 케이스를 더했다(+12줄). 수정을 빼면 실패한다.
