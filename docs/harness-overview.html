CLI Observation 계약 (--json)

P2 (0.8.0) — drive 에이전트(Codex·OpenCode)가 harness-team CLI를 Bash로 호출하면 stdout이 곧 observation이 된다. 사람용 출력은 그대로 두고, --json으로 구조화 엔벨로프를 opt-in

동작 방식: drive 4커맨드(task · retro · release · doctor)에 --json을 주면 stdout에 단일 JSON 엔벨로프 1개만 출력하고 process.exitCode로 신호한다. 사람용 산문 출력은 바이트 동일하게 보존(기본). 헬퍼는 src/observation.mjs의 buildEnvelope · emitObservation.

엔벨로프 스키마 — harness/observation/v1

{
  "schema": "harness/observation/v1",
  "command": "doctor",
  "status": "success | warning | error",
  "summary": "사람이 읽는 한 줄 요약",
  "next_actions": ["에이전트가 다음에 할 행동"],
  "artifacts": ["생성·변경된 경로"],
  "error": null | { "root_cause", "safe_retry", "stop_condition" }
}

불변식: status === "error" ⟺ error !== null — 4커맨드 공통. 에이전트는 커맨드별 분기 없이 if (env.error) … 한 패턴으로 파싱한다. 계약은 "가장 약한 커맨드"만큼만 강하다.

doctor --json

표준 엔벨로프 + per-check checks:[{label, status, detail}]. status는 pass | fail | missing | optional. 에이전트가 누락 도구·파일을 직접 판단.

task / retro --json

created / activated / no-active / bad-name 분기마다 엔벨로프. 에러 경로도 root_cause + safe_retry + stop_condition로 정합.

release --json

success / dry-run / error 분기. artifacts에 bump된 매니페스트·캐시 경로. (release는 maintainer 액션 — 에이전트 비운전.)

범위: drive 4커맨드만 (파킹 문서 결정). src/observation.mjs 헬퍼가 제네릭이라 나머지 커맨드는 후속 opt-in 가능 (YAGNI). 파서 · human 포맷 무변경. baseline 71 → 84 테스트 pass.
Hooks

.claude/hooks/ — Claude Code 이벤트에 따라 자동 실행하는 보호·검증·포맷·관측 훅

동작 방식: Claude Code는 .claude/settings.json의 "hooks" 설정을 읽어 PreToolUse·PostToolUse·실패/권한거절·SessionStart 이벤트에 훅을 실행합니다. Exit code 2는 해당 도구 실행을 차단합니다.

보호·포맷·커밋 검증의 대표 순서 — 전체 이벤트 훅은 아래 settings.json 표를 참조

PreToolUse protect-files.sh

Edit · Write 도구 실행 전 보호 대상 경로를 차단한다.

  • 차단 패턴: .env, ios/Pods, android/build, node_modules/, .git/
  • 파일 경로가 패턴과 매칭되면 exit 2 → Claude가 수정 불가

PostToolUse auto-format.sh

Edit · Write 완료 후 Prettier로 자동 포맷.

  • 대상: .ts, .tsx, .js, .jsx, .json
  • npx prettier --write 실행 — 실패 시 무시(silent)

PreToolUse pre-commit-check.sh

Bash 도구에서 git commit 명령 감지 시 검증 실행.

  • pnpm tsc --noEmit — 타입 에러 시 차단
  • pnpm test --passWithNoTests — 테스트 실패 시 차단
  • timeout: 120초

전 이벤트 observe-tools.mjs

도구 시작·성공·실패·권한거절을 원문 없는 로컬 JSONL로 관측한다.

  • PreToolUse·PostToolUse·PostToolUseFailure·PermissionDenied는 모든 도구(*)에 적용
  • SessionStart에서는 정리만 수행하며, runner는 stdout이나 context를 출력하지 않음

도구 호출 관측 v1 — 프라이버시와 보존 계약

.harness/observability/v1/YYYY-MM-DD/ 아래에만 기록하며, 전체 디렉터리는 생성 시 자동 gitignore된다. 디렉터리는 0700, JSONL과 프로젝트별 HMAC 키는 0600으로 제한한다.

  • 레코드는 allowlist다: 세션·task·도구 호출·도구 이름은 HMAC 참조값만, 상태와 도구 분류는 고정 enum만, 그 밖에는 숫자/boolean 메타데이터와 선택적 안전 정수 usage만 남긴다.
  • 프롬프트, 경로, tool input/output, shell 명령, stdout/stderr/error, transcript·MCP raw ID와 credential은 절대 기록·전송하지 않는다. LLM·HTTP·외부 telemetry·cross-agent adapter·tool profile·dashboard·USD cost도 없다.
  • 입력/응답 JSON byte metadata는 1 MiB에서 포화하며 input_bytes_capped/response_bytes_capped boolean으로 표시한다. 이는 토큰이나 비용이 아니다.
  • 로그는 8 MiB 단위로 다음 suffix 파일에 회전하고, UTC 기준 14일을 지난 날짜 디렉터리는 SessionStart에서만 정리한다.
  • .harness가 프로젝트 밖을 가리키는 symlink면 기록하지 않고 경로 없는 안전한 stderr 안내만 남긴다.

Skills

.claude/skills/ — slash command 형태로 호출하는 워크플로우 가이드. SKILL.md가 컨텍스트에 주입됨

동작 방식: .claude/skills/<name>/SKILL.md는 /<name> slash command로 호출됩니다. disable-model-invocation: true로 선언된 경우 Claude가 직접 따르는 지침으로 동작합니다. harness-team task new와 연동되어 태스크 디렉토리를 자동 생성합니다.

🐛 /fix-bug

버그 수정 4단계 워크플로우

  • Phase 1: harness-team task <name> + <name>-spec.md 증상 기록
  • Phase 2: 코드 탐색 → 근본 원인 파악 → 최소 surgical fix
  • Phase 3: typecheck/lint/test + 수동 재현 확인
  • Phase 4: git commit → hook 자동 handoff → AskUserQuestion → harness-team done

✨ /new-feature

신규 기능 4단계 워크플로우

  • Phase 1: harness-team task <name> + <name>-spec.md 요구사항
  • Phase 2: 코드베이스 탐색 → <name>-plan.md 체크리스트
  • Phase 3: 단계별 구현 + plan 체크 갱신
  • Phase 4: 검증 + git commit → hook 자동 handoff → AskUserQuestion → harness-team done

✅ /verify

완료 선언 전 검증 체크리스트 실행. typecheck · lint · test · 수동 확인 · 코드 리뷰 기준 대조.

v0.6.0 변경: /handoff와 /plan skill은 제거됨 — handoff는 post-commit hook이 자동 처리하고, plan은 <name>-plan.md로 task 내에 통합됨.
