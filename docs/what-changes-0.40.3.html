왜 patch로 끊었나 — 기존 훅에 대한 증분

기준표만 보면 "① 표면의 새 가드 = minor"에 걸립니다. 그런데 크기는 변경의 종류가 아니라 파급 범위로 정한다는 단서가 있고, 직접 선례가 0.18.1입니다 — ### Added(done 가드 2종)를 담고도 patch였습니다. "기존 명령에 대한 증분이라 blast radius가 작다"는 판단이었고, 이 건은 기존 훅의 패턴 목록에 3줄이라 같은 모양입니다. 새 커맨드도, 이름 변경도, 계약 변경도 없습니다.

표면상태판단
templates/.claude/hooks/protect-files.sh (① 플러그인 채널) PROTECTED_PATTERNS에 3줄 추가. 판정 구조·경계 규약·저정밀 폴백은 그대로 patch. 기존 가드의 증분 — 0.18.1과 같은 자리
훅 배선·settings.json 한 줄도 바뀌지 않음 init 재실행 불필요
src/** 불변 CLI 동작 변화 없음

다만 이번에는 templates/가 바뀌었습니다 — 0.40.2와 다른 점입니다. 훅 스크립트 텍스트가 곧 배포물이므로, 이미 설치된 프로젝트는 플러그인 갱신만으로는 새 패턴을 받지 못합니다(아래 "소비자가 할 일").

더한 것

Added · templates

RN·iOS 빌드 비밀 3종

무엇
Fastfile(fastlane — 서명·배포 자격증명), figma-export.y(a)ml(디자인 토큰 파이프라인 토큰), *.xcconfig(빌드 설정·API 키). 기존 5종(.env*·ios/Pods·android/build·node_modules/·.git/)에 더해 8종이 됩니다.
왜 여기로 왔나
hs-style-pack이 같은 위치에 같은 파일명으로 자기 protect-files.sh를 깔고 있었습니다. 먼저 깐 쪽이 이깁니다 — bodoc4 실측에서는 하네스가 이겨 팩의 3종 보호가 한 번도 걸리지 않았습니다. 팩 0.10.0이 훅 이름에 style-pack- 접두를 붙여 그 충돌을 없앴고, 그러면 두 훅이 나란히 돌아 차단은 합집합이 됩니다. 남는 구멍은 팩을 안 쓰는 하네스 사용자뿐이라 이 셋을 하네스가 갖습니다.
경계
기존 5종과 같은 규약을 씁니다 — 이름만 닮은 파일은 통과해야 합니다. src/FastfileGenerator.ts, docs/Fastfile.md, src/figma-export.ts, docs/xcconfig.md를 allow 목록에 넣어 회귀 테스트로 고정했고, jq·저정밀 두 모드 모두에서 돕니다.
Context

두 도구가 같은 파일명을 다투지 않게 됐습니다

이전
팩과 하네스가 auto-format.sh·pre-commit-check.sh·protect-files.sh 세 이름을 공유했습니다. skip-existing이라 먼저 깐 쪽만 남고, 설치 순서가 결과를 바꿉니다.
지금
팩 훅은 style-pack- 접두를 씁니다. 하네스는 아무것도 바꾸지 않아도 자기 이름을 그대로 유지합니다 — 이 릴리스에서 하네스가 팩을 아는 곳은 없습니다.
겹칠 때
protect-files는 둘 다 돌아 합집합입니다(더 안전해질 뿐입니다). pre-commit은 팩 쪽이 하네스 훅의 존재를 보고 겹치는 게이트를 넘깁니다 — 그 판단은 팩에만 있습니다.
