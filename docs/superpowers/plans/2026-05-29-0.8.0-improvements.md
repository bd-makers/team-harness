## P0 — 선언 → 강제 전환 (Enforcement Gap) 〔dogfooding 실증 · quick win〕

**Problem.** dogfooding이 입증했다: 하네스의 게이트·루프·리뷰·종결은 `CLAUDE.md` 산문 지시일 뿐 **강제 장치가 없어** 전부 skip된다. P1(SSOT master)·P5(측정)와 달리 **결정 없이 즉시 착수 가능한 작은 enforcement** 묶음이다. P5의 "채택률" 변수를 직접 끌어올린다.

**Approach (각 항목 독립, 작은 PR).**
1. **종결 가드** — `task done`이 커밋 0개·테스트 로그 부재·plan 미완(`- [ ]` 잔존) 시 경고/거부. `artifact.md` 미생성 시 done 차단. (`src/commands/task.mjs`)
2. **spec 경로 단일화** — spec/plan을 docs 루트·`superpowers/plans`에 만들면 게이트 템플릿(자가진단)이 우회된다. `task <name>` 생성 spec을 정본으로 하고 외부 본문은 링크가 아니라 흡수. `doctor`가 "포인터 껍데기 spec"(자가진단 섹션 없음) 감지·경고. (`src/commands/doctor.mjs`)

## P1 — SSOT master 재검토 (AGENTS.md 표준 정렬) 〔headline〕

**Problem.** 현재 하네스는 `CLAUDE.md`(벤더 고유)를 master 실파일로 두고 `AGENTS.md`·`GEMINI.md`·`.cursorrules`를 그 symlink로 만든다 ([doctor.mjs:6-9](../../../src/commands/doctor.mjs)). 그러나 **`AGENTS.md`는 Linux Foundation이 관리하는 오픈 표준**(6만+ 프로젝트, Codex·OpenCode·Gemini·Jules·Factory 채택)으로, 업계는 AGENTS.md를 **canonical 최상위**로, Claude 전용은 `.claude/` 하위로 두는 패턴을 권한다. 즉 현재 구조는 **표준과 방향이 역전**되어 있다.

**Why 0.7.0 범위 밖.** SSOT master 변경은 `doctor.mjs`/`harness.mjs`(setupSymlinks)/`CLAUDE.md.hbs`/`README`/`migrate`/`upgrade`를 동시에 건드리는 **breaking change**라, 기존 사용자 무중단 마이그레이션 경로가 함께 설계돼야 한다.

**핵심 제약 (drive 결정과의 연결).** symlink는 바이트가 동일해 **에이전트별 역할 분기를 표현할 수 없다.** "모든 에이전트가 운전한다"는 0.7.0 결정 + Codex(리뷰어) vs Claude(운전자) 역할차를 살리려면, 공유 코어 + 에이전트별 오버라이드가 가능한 구조가 필요하다 → P3와 직결.

**Approach (D1 결정에 따라 분기).**
- **(B) 역전:** `AGENTS.md`를 master 실파일로, `CLAUDE.md`/`GEMINI.md`/`.cursorrules`를 symlink/파생으로. 표준 정렬 최대. 단 Claude Code가 `CLAUDE.md`를 1순위로 읽는 동작과의 정합 확인 필요.
- **(C) 생성:** 단일 소스(예: `harness.config` 또는 `CLAUDE.md.hbs` 확장)에서 `AGENTS.md`(공유 코어) + 에이전트별 파일을 **렌더**. symlink 폐기. 표준의 "AGENTS.md canonical + `.claude/`에 Claude 전용 분리 + 디렉토리별 중첩" 패턴과 가장 잘 맞고 **에이전트별 분기 가능**. 하네스가 이미 Handlebars 렌더를 하므로 자연스러운 확장. 단 "한 번 쓰고 symlink" 단순성은 잃음.

**Affected.** `src/commands/doctor.mjs`(CHECKS), `src/harness.mjs`(setupSymlinks), `src/symlink.mjs`, `templates/CLAUDE.md.hbs`, `src/commands/migrate.mjs`·`upgrade.mjs`(마이그레이션 경로), `README.md`, overview 문서 Symlink 섹션.

**Acceptance(잠정).**
- [x] D1 결정 기록 — (C) 단일 소스→렌더, 위 "결정 확정" 표 + task `chad/ssot-agents-md`
- [x] 표준(AGENTS.md canonical) 정렬 근거 문서화 — D1 근거 칸
- [x] 기존 사용자가 한 명령으로 신구조로 이전 (무중단, 백업 보존) — `migrate`의 `migrateToAgentsMd` (CLAUDE.md.bak 백업, 사용자 텍스트 보존)
- [x] (C 선택) 에이전트별 오버라이드 검증 — Claude `@AGENTS.md`(docs 확정), Gemini/Cursor/OpenCode 소비 경로 artifact 기록

**Symlink 자체의 깨짐 취약성도 함께 고려:** Windows/CI 체크아웃/zip 배포 — 하네스가 이미 [Windows copy fallback](../../../src/symlink.mjs)을 둔 게 방증. (C) 생성 모델은 이 취약성도 해소.

## P2 — CLI observation / error 계약 (multi-agent drive 정합)

> **0.7.0 연계:** 최소 버전(신규 `retro`/`release` + `doctor`의 일관 status 라인 + 다음 행동 + 복구 힌트)은 [0.7.0 착수 전 보강 #9](./2026-05-28-consolidated-0.7.0.md)로 **선반영**. 본 P2는 이를 **전 커맨드 `--json` 구조화 엔벨로프**로 확장하는 후속.

**Problem.** drive 결정으로 Codex/OpenCode가 `harness-team` CLI를 Bash로 호출한다 → **CLI의 stdout이 곧 에이전트의 observation**이다. 그러나 현재 출력은 사람용 산문(`doctor`의 `✓/✗/-`, `release` 에러 메시지 등)이라 에이전트가 다음 행동을 파싱·결정하기 어렵다.

**업계 원칙 (harness-construction).**
- observation: `status`(success|warning|error) · `summary` · `next_actions` · `artifacts`
- error: `root cause hint` · `safe retry instruction` · `explicit stop condition`

**Approach.** 운전 대상 커맨드(`task`/`retro`/`release`/`doctor`)에 **구조화 출력 모드**(`--json`) 또는 최소한 일관된 status 라인 + 다음 행동 + 복구 힌트를 추가. 사람용 출력은 유지(기본), 에이전트용은 옵트인.

**Affected.** `src/commands/{task,retro,release,doctor}.mjs` 출력부, `bin/harness-team.mjs` HELP.

**Acceptance.** ✅ **완료** (2026-06-15, task `chad/cli-json-contract`, 머지됨 → `chad/ssot-agents-md`)
- [x] `harness-team <cmd> --json`이 통합 엔벨로프(`{schema, command, status, summary, next_actions, artifacts, error}`) 출력 — task/retro/release/doctor
- [x] 에러 경로마다 root_cause + safe_retry + stop_condition 포함 (task의 bad-name human 경로도 정합)
- [x] `doctor`가 per-check machine-readable(`checks:[{label,status,detail}]`) 출력 → 에이전트가 누락 도구/파일 판단 가능
- 스키마=통합(error nullable), 불변식 `status==='error' ⟺ error!=null` 전 커맨드 공통. 71→84 pass. 헬퍼 `src/observation.mjs` 제네릭 → 나머지 8커맨드 후속 opt-in 가능.

## P4 — 계약 컨텍스트 예산 (terse contract + on-demand 참조)

> **0.7.0 연계:** "계약을 터스하게 유지하고 상세는 on-demand 참조로 분리"라는 ② 지침은 [0.7.0 착수 전 보강 #7](./2026-05-28-consolidated-0.7.0.md)에 **이미 반영**(처음부터 부채를 안 만든다). 본 P4는 그 원칙을 **레퍼런스 구조 전면 정리**(페르소나/절차 파일화, 계약 길이 기준선 관리)로 확장하는 후속.

**Problem.** 0.7.0의 best-effort 결정은 spec/impl/debug 절차를 `CLAUDE.md`에 산문으로 흡수한다. 계약이 커질수록 **항상 로드되는 컨텍스트가 비대해져** "context overloading" 안티패턴에 가까워진다.

**업계 원칙 (Anthropic 컨텍스트 관리 / harness-construction 컨텍스트 예산).** "system prompt는 최소·불변", "큰 가이드는 on-demand 스킬/참조로", "긴 문서는 인라인 말고 파일 참조", "phase 경계에서 compaction".

**Approach.** `CLAUDE.md`에는 **터스한 게이트 룰·원칙만** 남기고, 상세 절차·페르소나 기법은 별도 참조 파일(기존 `.claude/rules` 패턴 또는 `references/`)로 분리해 필요 시 로드. 페르소나 슬래시 커맨드 본문도 참조 파일을 가리키게.

**Note.** 0.7.0 구현 시 인라인을 처음부터 최소화하면 이 부채를 줄일 수 있음 → 0.7.0 리뷰에서 "계약 터스 유지" 가이드를 함께 적용 권장.

**Acceptance(잠정).**
- [ ] `CLAUDE.md`(managed 섹션) 길이가 기준선 대비 증가폭 ≤ 목표치
- [ ] 상세 절차가 on-demand 참조로 분리되고 에이전트가 필요 시 로드함을 확인
