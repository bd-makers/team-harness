Fixed · #153

경로별 창 끝 상태로 판정

무엇
--name-status -M으로 경로마다 창 끝 상태를 접습니다. 삭제된 경로는 증거에서 빠지고, 창 이전부터 있던 테스트 파일이 창 끝에 삭제 상태면 기존 테스트 파일이 삭제됨: …으로 차단합니다 — 다른 테스트를 추가해도 차단입니다.
삭제가 아닌 것
이름 변경(git mv), 창 안에서 만들고 지운 파일. 앞 커밋에서 고치고 다음 커밋에서 지운 경우는 잡습니다.
의도한 삭제
done --force로 닫고 사유를 artifact에 남깁니다(meta forcedIssues가 감사 흔적).
Note · 한계

가드가 보지 못하는 것

짝지음
지운 테스트와 내용이 50% 이상 같은 새 파일은 이름 변경으로 짝지어집니다. 제자리 assert 약화와 같은 부류라 아래 루브릭 행이 맡습니다.
다른 PR
판정 창은 종전처럼 git log --since라, 창 안에 병합된 다른 PR의 테스트 삭제도 이 task를 막습니다(종전엔 증거를 늘리기만 했습니다). main에서 done할 때 드물게 걸리며, --force와 사유 기록으로 닫습니다.

testcritic — "기존 테스트 후퇴 없음" BLOCKER

Added · #153 · #154

T7 · C7 · I7

pass 조건
기존 테스트의 삭제, .skip·xit·xdescribe·@Disabled·@Ignore 등 비활성화, 기대값 완화·assert 제거가 diff에 없어야 합니다. 의도한 삭제는 spec 근거를 인용합니다.
번호
기존 1–6행 번호는 그대로이고 7행이 더해집니다. /harness-unittest·/harness-comptest·/harness-inttest 미러와 루브릭 가이드(#154)도 같습니다.
Why

가드와 루브릭의 분담

가드
파일 단위 삭제는 done 가드가 결정론적으로 막습니다.
루브릭
skip 표지·assert 약화·이름 변경으로 위장한 삭제는 문자열 판정이 어려워 리뷰어 판단에 둡니다.

/harness-loop — 테스트를 줄여 얻은 진전은 진전이 아니다

항목0.50.00.51.0
실패 집합이 줄었을 때진전그 Dev 턴이 기존 테스트를 지우거나 skip·assert 약화로 줄였으면 멈춤
판정 근거—그 턴의 git diff HEAD의 삭제된 테스트 파일·추가된 skip 표지·제거된 assert 줄
횟수 상한없음여전히 없음 — 멈춤 조건은 넷 그대로입니다
왜 "3회 재시도 상한"을 따르지 않나. 글은 재시도 횟수 상한을 권하지만, 하네스는 "진전 없음"을 멈춤 기준으로 둔 설계를 유지합니다. 횟수는 진전 중인 루프도 끊고 진전 없는 루프는 상한까지 돌립니다. 이번 변경은 그 기준에서 "가짜 진전"을 걸러 낼 뿐입니다.

block-dangerous-bash.sh — git 밖 위험 셸 명령 차단

Claude Code의 Bash deny 규칙은 명령 문자열 매칭이라 Bash(rm -rf *)가 rm -fr·rm -r -f·/bin/rm -rf를 막지 못했고, curl … | sh와 cp .env x에는 규칙이 없었습니다.

Added · #153

Bash PreToolUse 훅 (exit 2)

막는 것
재귀+강제 rm의 모든 철자, find -delete·-exec rm, curl|wget … | sh·bash -c "$(curl …)"·bash <(curl …), .env·.env.*를 피연산자로 받는 cp·mv·ln·rsync·scp·install. cp .env.example .env도 막힙니다.
배선
settings에 별도 PreToolUse group으로 겁니다. 기존 설치의 init 병합이 기존 Bash 훅을 중복시키지 않게 하기 위해서입니다. jq가 없을 때의 폴백 블록은 기존 훅과 공유합니다.
Note · 범위

보지 않는 것

cat .env
공식 문서상 Read(./.env) deny가 Bash의 cat·head·tail·sed·tee·리다이렉트에도 적용돼 다루지 않습니다.
휴리스틱
문자열 휴리스틱이라 bash -c '…' 안이나 스크립트 안의 파일 접근은 못 보고, 따옴표 안의 ;도 구분자로 봐 오탐(차단)합니다. git 훅과 같은 fail-closed 수용이며, 경계는 sandbox입니다.
