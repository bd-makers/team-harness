종결을 선언이 아니라
증거로 판정한다

0.18.1은 harness-team done에 증거 기반 가드 2종을 더하는 patch 릴리스입니다. task 기간에 소스만 바뀌고 테스트가 없으면 막고, spec이 리뷰를 요구한 task는 artifact에 남은 리뷰 마커를 요구합니다. 무엇을 막는지도 정직하게 적었습니다 — 이 가드가 막는 것은 악의가 아니라 망각입니다.

종결 가드 — 끝났다고 말하는 것과 끝난 것은 다르다

기존 4개 가드는 문서의 형태(plan 체크박스·handoff 갱신 등)를 봤습니다. 이번에 더한 두 가드는 task 기간에 실제로 남은 흔적을 봅니다.

Added

테스트 작성 체크 — 기본 ON

변경
git log --since=<switchedAt> --name-only로 task 기간의 변경 경로를 분류해, 소스는 바뀌었는데 테스트 파일 변경이 없으면 종결을 차단합니다. 분류는 언어 무관 확장자 화이트리스트 + 테스트 경로·파일명 패턴이며 테스트 판정이 우선합니다. 불필요한 task는 spec에 "tests": "skip"을 선언해 끕니다.
왜
plan을 전부 체크하고 handoff를 갱신해도 테스트를 잊은 채 닫히는 task가 남았습니다. 종결 시점은 "테스트를 썼는가"를 물을 마지막 지점인데, 그 질문을 사람의 기억에만 맡기고 있었습니다.
그래서
문서·설정만 바뀐 task에서는 source=false가 되어 아예 발동하지 않습니다. core.quotepath=false + C-quote 해제로 한글 경로 같은 non-ASCII 경로도 확장자가 정확히 읽힙니다.
Added

리뷰 마커 체크 — spec opt-in

변경
spec이 "review": "required"를 선언한 task는 artifact에 <!-- harness:review kind=… at=… --> 마커가 있어야 닫힙니다. at이 switchedAt보다 이르면(= 이전 task의 리뷰) 인정하지 않고, at은 ISO8601 형태만 받습니다.
왜
"기록하지 않은 리뷰는 안 한 것"이라는 팀 규범은 사람이 지켜야만 성립했습니다. 규범을 기계가 읽을 수 있는 한 줄로 바꾸면 종결 시점에 검사가 가능해집니다.
그래서
기본값은 optional입니다 — 전면 강제는 --force를 습관으로 만들어 가드 전체를 무력화합니다. 리뷰가 실제로 중요한 task만 spec에서 켜세요.

선언은 조용히 꺼지지 않는다

가드를 spec 선언으로 켜고 끄게 만들면, 선언이 깨졌을 때 어떻게 행동하는지가 가드의 실제 강도를 결정합니다.

Added

spec ## Done evidence JSON 선언

변경
{ "version": 1, "tests": "required|skip", "review": "required|optional" }. 미선언은 기본값(tests: required / review: optional)으로 동작하고, spec 템플릿에는 주석 처리된 선언 자리를 넣어 두었습니다 — 주석을 벗기면 켜집니다.
왜
모든 task에 같은 강도를 강제하면 예외가 --force로 흘러갑니다. task마다 무엇을 증거로 요구할지는 spec이 정하는 편이 맞습니다.
그래서
선언이 깨져 있으면 기본값으로 흘려보내지 않고 그 자체를 차단 사유로 봅니다 — boundary check의 not-configured 전례를 따라, "선언 안 함"과 "선언이 깨짐"을 구분합니다.
Fixed

fail-open 경로 3종 차단

변경
외부 리뷰(codex, read-only)가 잡은 P2 4건을 전건 조치했습니다. ① 미종결 ```json fence가 미선언으로 통과하던 경로 → 열린 fence 흔적이 있으면 invalid. ② rewiew 같은 오타 키를 무시하던 경로 → strict key 검증. ③ Date.parse('9999')가 먼 미래 시각으로 통과하던 경로 → ISO8601 형태 선검사. ④ C-quoted non-ASCII 경로의 확장자 오분류.
왜
세 경우 모두 사용자는 "선언했다"고 믿지만 가드는 꺼져 있습니다. 실패보다 나쁜 것은 켜져 있다고 착각하게 만드는 통과입니다.
그래서
조치 전건에 회귀 테스트를 붙였습니다(신규 16케이스 — 순수 함수 8 + 가드 통합 8). 상세 발견·조치는 docs/chad/done-guard-evidence/done-guard-evidence-artifact.md의 ## Reviews에 남아 있습니다.

마커는 리뷰 커맨드가 남긴다

검사할 흔적을 사람이 손으로 적어야 한다면 그 검사는 다시 기억력 시험이 됩니다.

Contract

리뷰 기록 5단계에 기계 판독용 한 줄

변경
/harness-review의 기록 단계가 사람이 읽는 요약과 함께 <!-- harness:review kind=… scope=… tip=… at=… --> 마커를 append 합니다. /harness-adversarial-review는 kind=<engine>-adversarial로 구분합니다. artifact 템플릿의 ## Reviews 안내문에도 형식을 명시했습니다.
왜
가드가 요구하는 증거는 리뷰를 실행한 커맨드가 만드는 것이 자연스럽습니다. 사람이 따로 적게 하면 잊히고, 잊히면 가드는 --force로 우회됩니다.
그래서
마커 파싱은 ## Reviews 섹션이 아니라 artifact 파일 전체를 스캔합니다 — 섹션 경계 파싱은 문서 편집에 취약합니다. 형식이 깨진 마커는 없는 것과 같이 취급합니다.

이번 릴리스가 택한 방향

전환 창 유지: 이 릴리스는 0.18.0이 선언한 전환 창(0.18.x) 안의 patch입니다. 옛 리뷰 이름 4개(/harness-codex-review·/harness-codex-adversarial-review의 커맨드·스킬)의 포워딩은 그대로 유지되며, 제거는 예정대로 0.19.0에서 수행합니다.

fail-open은 선언 기반 가드의 최대 적이다

미종결 fence, 오타 키, 관대한 Date.parse — 셋 다 "선언했다고 믿지만 실제로는 꺼진" 상태를 만듭니다. 선언한 흔적이 있는데 읽을 수 없다면 통과가 아니라 차단이 맞습니다. 가드가 조용히 열려 있는 것보다, 시끄럽게 막히는 편이 언제나 낫습니다.

가드의 강도는 정직하게 선언한다

이 두 가드는 "테스트를 잘 썼는가"나 "리뷰가 충실했는가"를 판정하지 않습니다. 변경 경로에 테스트 파일이 있었는지, task 기간 안의 리뷰 마커가 있는지를 볼 뿐입니다 — 막는 것은 악의가 아니라 망각이고, 기존 4개 가드와 같은 등급입니다. 이 한계를 문서에 적어 두는 것이, 가드를 실제보다 강하게 믿게 만드는 것보다 안전합니다.
