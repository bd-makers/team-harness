Added · #118

init이 적용 버전을 harnessVersion으로 남긴다

원인
render-state.json의 "version": 1은 이 파일의 스키마 버전입니다. 프로젝트 단위로 "마지막 init을 돌린 하네스 버전"을 기록하는 곳이 없었습니다.
지금
init이 Apply 뒤 render-state를 저장할 때 실행 중인 하네스의 package.json version을 harnessVersion으로 함께 씁니다. 읽을 때는 semver 형식만 받고, 없거나 형식이 틀리면 기록 이전 설치본으로 봅니다.
유지
타임스탬프는 넣지 않습니다 — 같은 버전으로 init을 다시 돌려도 diff가 생기지 않습니다. 이 파일은 계속 커밋 대상입니다.
Added · #118

doctor가 project·CLI·plugin 버전을 한 줄로

표시
harness version: project applied X · CLI Y · plugin Z. --json은 같은 내용을 versions: { project, cli, plugin }로 냅니다(모르면 null). 기록 없음은 unknown (기록 이전 설치), 플러그인 소스 저장소는 n/a.
경고
적용 버전 < 실행 중 CLI → 낡은 관리 절 경고 + next_actions에 harness-team init --yes. 적용 버전 > CLI → 구버전 CLI로 init하면 관리 절이 퇴행할 수 있다는 경고 + CLI 갱신 명령.
유지
경고만 냅니다 — init을 막지 않습니다. PATH CLI vs 설치 플러그인 불일치는 기존 global CLI version drift가 계속 담당합니다.
