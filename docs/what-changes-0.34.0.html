Release note · 2026-09-09

가드를 우회하고 닫은 task는
정상 종결과 구분되지 않았습니다

0.34.0은 harness-team done --force가 남기는 감사 흔적을 추가합니다. 지금까지 우회 종결은 무시한 issue를 stdout에 한 번 출력하고 휘발시켰고, meta.json·원장·doctor·SessionStart 재개 후보 어디에도 남지 않았습니다. 종결 이후에는 "이 task는 증거를 갖추고 닫혔는가"를 물을 기계 판독 경로가 없었습니다. 가드의 차단 판정과 --force 경로는 바뀌지 않습니다 — 막지 않고 기록만 합니다.

기록 조건은 --force 플래그가 아니라 실제로 무시된 issue입니다. 플래그만 붙고 무시한 것이 없으면 우회가 아니므로 흔적을 남기지 않습니다.

무엇

meta 유실
원장이 마지막 출처이므로 "우회가 있었다(시각 불명)"만 복구하고, forcedAt 시각은 지어내지 않습니다.

가드는 한 줄도 바뀌지 않았습니다

이 변경이 기존 결정과 충돌하지 않는 이유는 차단과 기록을 나눴기 때문입니다.

개념무엇이 릴리스
가드종결을 차단하는 판정(collectDoneIssues)불변
--force우회 경로계속 합법 — 제거·제한 없음
감사 흔적일어난 일이 사후에 기계 판독 가능한가이번에 추가

done-guard-window는 "harness 소유 meta 필드를 지우는 것은 고의이며, 망각을 잡는 가드의 구멍이 아니다"라며 관련 P1을 기각했습니다. 가드의 위협 모델은 망각이지 고의가 아니라는 결정은 그대로입니다 — 이 릴리스는 고의를 막지 않고 기록만 하므로 그 논거와 충돌하지 않습니다.

외부 검증 — 두 라운드, 그리고 절반짜리였던 첫 수정

Codex read-only 리뷰 2회. 두 번 다 Request changes. 각 발견을 재현·판별한 뒤 반영했습니다(D6: 검증자는 반박만, 수정은 작성 세션이).

라운드발견판별조치
1차원장 재생성이 우회 표시를 지움재현됨 — meta 유실 시 ✅ done ⚠️ → ✅ done반영 — 원장에서 복구
1차reopen 후 재우회가 이전 기록을 덮어씀사실이나 범위 밖 — 스키마가 답하는 질문은 "있었는가"이지 "몇 번인가"가 아님미수정 — 의미를 주석에 명시(2차 리뷰어도 기각 유지)
1차사용자 인덱스 표시가 테스트에 안 걸림재현됨 — 뮤테이션이 통과반영 — 테스트 추가
2차reopen이 복구한 흔적을 지움재현됨 — 열린 행(🔄 open)은 표시를 담을 자리가 없어, 열린 구간에 원장을 한 번만 재생성해도 유일한 출처가 사라짐반영 — 복구값을 meta에 굳힘
2차회귀 테스트가 또 이름만 봄재현됨 — 같은 종류의 결함이 고치는 과정에서 재생산됨반영 — 줄 전체를 기준선과 대조
2차 (P3)주석이 코드와 반대자기 수정이 만든 거짓 주석반영 — 교체

2차 리뷰가 잡은 것이 이 릴리스의 핵심입니다. 첫 수정은 task가 닫혀 있는 동안에만 성립했습니다. 원장은 열린 task의 우회를 표현할 자리가 없기 때문입니다.
리뷰어가 독립 확인한 것: 복구 플래그가 meta.json으로 새는 경로 없음 · summary --check가 진동하지 않고 고정점에 도달함 · 표시 제거 뮤테이션이 새 테스트에서 실패함.
리뷰어가 못 한 것: read-only 샌드박스가 fixture의 mkdtemp를 EPERM으로 막아 npm test 전체는 독립 실행하지 못했습니다.
