docs/<user>/<user>-handoff.md의 내용은 전부 gitignore된 .harness/active.json과 그 워크트리의 git log -1에서 나옵니다. 워크트리마다 달라야 정상인 값인데 git이 추적하고 있어서, post-commit 훅이 커밋마다 다시 쓴 이 파일 때문에 같은 사람이 연 병렬 PR은 머지할 때마다 충돌했고, 어느 쪽을 택해도 머지 직후 값은 이미 틀렸습니다. 이제 같은 경로에 두되 추적하지 않습니다.

왜 patch인가 — 잘못 동작하던 것을 고쳤다

병렬 PR마다 반드시 충돌하던 결함의 수정입니다. 파일 경로·형식·렌더러는 그대로이고, "세션 시작 시 이 파일을 읽어라"는 규범도 그대로 동작합니다. 바뀐 것은 이 파일을 커밋하지 않는다는 한 가지입니다.

표면경로도달 경로소비자 영향
CLI 동작src/ — task·doctor·migrate·.gitignore 관리 목록플러그인 갱신task 활성화 때 user handoff를 바로 씀, 전환 누락을 doctor가 경고
명령 문서commands/harness-task.md·harness-ship.md플러그인 갱신"handoff 2파일을 다음 커밋에 담는다" → task handoff 1파일
AGENTS.md 관리 절templates/AGENTS.md.hbsinit --yes만 — migrate는 관리 절을 렌더하지 않음같은 규범 정정, 컨텍스트 파일 표에 "워크트리 로컬·gitignore"
.gitignoredocs/*/*-handoff.md 한 줄init 또는 migrate (둘 다 추가)새로 만드는 user handoff가 추적되지 않음
git 인덱스이미 추적 중인 docs/<user>/<user>-handoff.md사람이 1회 — 도구는 인덱스를 건드리지 않음이걸 안 하면 무시 줄이 있어도 충돌은 계속됨

바뀐 것

Fixed · #115

user handoff를 워크트리 로컬 파일로

원인
이 파일은 활성 task·마지막 커밋·task handoff 경로를 렌더링한 값입니다. 정본(active.json)은 워크트리마다 다른데 렌더링만 공유되니, 같은 줄을 두 브랜치가 반드시 다르게 고쳤습니다(이 저장소 실측 3회).
지금
하네스 관리 .gitignore에 docs/*/*-handoff.md가 들어갑니다. docs/ 바로 아래 한 단계만 매치하므로 task handoff(docs/<user>/<task>/<task>-handoff.md, SSOT)는 계속 추적됩니다.
한계
gitignore 문법은 "파일명 = 디렉터리명" 조건을 표현하지 못해, 같은 깊이에 새로 만드는 다른 *-handoff.md도 무시됩니다. 이미 추적 중인 파일에는 영향이 없습니다.
Added · #115

task 활성화가 진입점을 바로 쓴다

원인
추적하지 않으면 새 워크트리·clone에는 이 파일이 없습니다. 첫 커밋까지 세션 진입점이 비게 됩니다.
지금
harness-team task <name>(생성·재활성)이 활성 형태를 한 번 씁니다. Last Commit 줄은 첫 커밋 전까지 (task 활성화 — 다음 커밋에서 갱신)입니다.
유지
post-commit 훅의 갱신, done의 종결 형태, sweep 커밋 침묵, done 가드의 handoff 제외는 그대로입니다.
Guard · #115

doctor 경고·migrate 안내

추적 중
⚠️ user handoff 가 아직 git 에 추적됨(병렬 PR 충돌 원인): docs/<user>/<user>-handoff.md — 기본 브랜치에서 `git rm --cached …` 후 커밋
무시 줄 없음
⚠️ .gitignore 에 `docs/*/*-handoff.md` 줄이 없어 user handoff 가 다시 커밋될 수 있음 — `harness-team migrate` 로 추가
migrate
.gitignore 줄을 보장하고, 추적 중인 사본이 있으면 git rm --cached 명령을 출력만 합니다. 인덱스 변경은 사용자의 커밋 경계라 도구가 하지 않습니다. 둘 다 warn-only라 doctor exit code에 영향이 없습니다.

소비자가 할 일

Do · 1

플러그인 갱신

왜
CLI 동작(src/)과 명령 문서(commands/)는 플러그인 채널로만 옵니다.
어떻게
/plugin marketplace update(또는 clone에서 git pull). harness-team --version이 0.44.4이면 됩니다.
Do · 2

각 프로젝트에서 harness-team init --yes

왜
AGENTS.md 관리 절의 규범 문구가 바뀌었고, 관리 절은 init만 렌더합니다 — migrate를 돌리면 이 절은 그대로 남습니다. init은 .gitignore 줄도 함께 넣습니다.
참고
.gitignore 줄만 필요하면 harness-team migrate로도 됩니다. docs/README.md의 트리 주석 변경은 기존 설치에 복사되지 않습니다(한 줄 주석이라 무해).
Do · 3

기본 브랜치에서 추적 해제 커밋 1회

무엇
이미 커밋돼 있는 user handoff는 무시 줄이 있어도 계속 추적됩니다. 한 사람이 기본 브랜치에서 한 번만 합니다(사용자가 여럿이면 경로를 모두 적습니다).
어떻게
git rm --cached docs/<user>/<user>-handoff.md
git commit -m "chore: user handoff 추적 해제 (harness 0.44.4)"
doctor의 경고 문구에 이 저장소의 정확한 경로가 나옵니다.
전환기 1회
그 전에 갈라진 브랜치를 머지하면 이 파일에서 modify/delete 충돌이 한 번 납니다 — 삭제 쪽을 택합니다(git rm --cached <경로>). 이 커밋을 pull한 다른 워크트리에서는 로컬 파일이 한 번 지워지고, 다음 task 활성화나 커밋에서 다시 생깁니다.
