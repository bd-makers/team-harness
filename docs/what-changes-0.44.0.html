바뀐 것

Changed · done 가드

체크박스만 켠 plan.md는 미커밋 작업이 아니다

이전
머지 뒤 plan의 마지막 단계를 - [x]로 켜면 그 변경이 미커밋 작업으로 잡혀 done이 막혔습니다. 그래서 "체크 커밋 → done → 종결 커밋 → 원장 커밋" 세 커밋이 관례가 됐습니다.
지금
활성 task의 plan.md 변경이 줄머리 - [ ] → - [x]뿐이면 면제합니다. 종결은 체크 → done → summary --write → 커밋 하나입니다.
막는 것
HEAD의 plan을 index·작업 트리 둘 다와 줄 단위로 대조하고, 양쪽 mode가 100644일 때만 면제합니다. 끄기·줄 추가·산문 수정·stage한 산문·chmod·symlink 교체는 종전대로 막습니다(codex 리뷰 2회에서 찾은 우회를 모두 회귀 테스트로 고정). CRLF plan도 면제됩니다.
한계
경로 대조는 targetDir가 저장소 루트라고 가정합니다(handoff 제외와 같은 기존 가정). 하위 디렉터리 설치본에서는 면제가 안 될 뿐, 막는 쪽으로 틀립니다.
Changed · 관리 절

protocol 절 압축 — eager 여유 5 B → 1,075 B

이전
프로젝트 eager 소계(AGENTS.md + CLAUDE.md)가 상한 17,500 B까지 5 B 남아, AGENTS.md에 한 줄도 더할 수 없었습니다.
지금
meta.json·다이어그램·plan.md 계약에서 명령 문서와 겹치던 근거·상세를 걷었습니다. 16,425 B(AGENTS 10,641 + CLAUDE 5,784). 규칙 문장은 남겼습니다 — Cursor는 commands/를 못 읽기 때문입니다.
바로잡음
다이어그램을 건너뛸 때 손으로 닫지 않고 harness-team diagram record --skipped "<사유>" 한 명령이 plan 단계와 artifact 기록을 함께 남긴다고 정본(harness-diagram)과 맞췄습니다.

소비자가 할 일

Do

플러그인 갱신 → doctor → init --yes

왜
done 가드는 플러그인 코드에, protocol 절은 템플릿에 있습니다. 관리 절은 init만 다시 렌더합니다 — migrate는 손대지 않습니다.
어떻게
/plugin marketplace update(또는 clone에서 git pull) 뒤 harness-team doctor — 관리 절 … 낡음: AGENTS.md#protocol이 뜨면 harness-team init --yes. 사용자가 편집한 절은 건너뜁니다.
Habit

종결 커밋을 하나로

무엇
PR/MR 머지를 확인한 뒤 기본 브랜치에서 마지막 단계를 체크박스만 켜고 done → summary --write → chore(task): <name> 종결 커밋 하나.
주의
같은 줄에 메모를 덧붙이면 산문 수정으로 보고 막습니다. 머지를 확인하기 전에 단계를 켜지 않는 판단은 여전히 에이전트 몫입니다.
