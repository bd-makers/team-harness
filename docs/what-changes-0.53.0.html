리뷰어 allow Bash(codex:*) 제거

Security · #171

codex의 모든 인수를 승인 없이 허용하던 항목

무엇
템플릿 settings의 Bash(codex:*)가 --sandbox danger-full-access·--dangerously-bypass-approvals-and-sandbox까지 승인 없이 허용했습니다. D2의 "리뷰어 read-only"와 어긋납니다.
왜 좁히지 않았나
Claude Code의 Bash 규칙은 명령 전체를 매칭하고 *가 어떤 텍스트든 대신합니다(공식 permissions 문서). Bash(codex exec --sandbox read-only *)로 좁혀도 뒤에 붙는 위험 플래그는 통과하므로, 빼는 것만 의미가 있습니다. 이 판단은 1차 문서 근거이고 라이브 실측은 아닙니다.
리뷰는 그대로
harness-team review codex는 node에서 codex를 직접 실행하므로 이 allow가 필요 없습니다. 에이전트가 codex를 Bash로 직접 부르면 이제 승인을 묻습니다.
Note · 도달

migrate가 정확히 그 문자열 하나만 지운다

왜 migrate
settings 배열은 합집합으로 병합돼(src/merge.mjs) 템플릿에서 빼도 기존 설치에서는 지워지지 않습니다.
무엇을
permissions.allow에 정확히 Bash(codex:*)가 있으면 확인 후 그 원소만 지웁니다. 다른 codex 규칙은 사용자 것이라 남깁니다. settings가 파싱되지 않으면 건너뜁니다.
역할 표
AGENTS.md 역할 표의 Codex 호출 방식이 Bash: codex exec --sandbox read-only에서 harness-team review codex로 바뀌었습니다(eager −11 B). init --yes로 받습니다.

/verify — 커밋 게이트 목록이 정본

Changed · #172

검증과 게이트가 같은 명령을 본다

종전
/verify는 AGENTS.md ## 명령의 typecheck·lint·test만 읽었습니다. 그 줄은 package.json 스크립트에서, 게이트는 프리셋 규칙에서 나와 갈렸습니다 — Python은 세 줄이 늘 (configure)라 /verify가 건너뛰는데 게이트는 pytest·ruff를 돌렸습니다.
이제
.harness/gates.json이 있으면 commit의 명령(객체 형식이면 모든 workspace 목록을 중복 없이)을 저장소 루트에서 전부 실행해 명령마다 ✅/❌로 보고합니다. 첫 실패에서 멈추지 않고, 실패가 있으면 installTrace를 먼저 보라고 안내합니다.
형식 오류
파일이 깨졌거나 형식이 틀리면 "설정 오류"로 보고하고 ## 명령으로 조용히 내려가지 않습니다(게이트와 같은 원칙). 파일이 없을 때만 종전처럼 동작합니다.
Decision · D-1

왜 gate commit을 그대로 부르지 않나

workspace 선택
객체 형식 게이트는 바뀐 파일이 있는 workspace만 고릅니다. 깨끗한 트리에서 /verify가 0건을 실행하게 됩니다.
첫 실패
게이트는 첫 실패에서 멈추므로 남은 항목을 보고하지 못합니다. 전체 검증인 /verify와 목적이 다릅니다.
도달
migrate의 템플릿 refresh가 갱신합니다. 직전 판을 stock으로 등록했으므로 손대지 않은 설치본만 바뀌고, 고친 설치본은 "looks customized" 경고만 받습니다.

게이트 실패 메시지의 환경 원인 단서

Added · #170

설치 흔적이 없으면 한 줄을 붙인다

무엇
게이트 명령이 실패했을 때 stack과 같은 판정(0.52.0 installTrace)이 absent면 차단 메시지 끝에 ℹ️ 환경 원인일 수 있습니다 — <lockfile>은 있는데 설치 흔적(<trace>)이 없습니다. 코드를 고치기 전에 <bootstrap>로 준비하세요.가 붙습니다.
왜
2026-10-11 heliosent-profile의 tsc 실패는 node_modules 부재가 원인이었지만 메시지는 커밋 게이트 실패: <cmd> (exit N)뿐이었습니다. "코드 탓 전에 installTrace" 안내는 lazy 스킬에만 있어 훅이 막는 순간 로드되지 않습니다.
범위
흔적이 있거나 규칙이 없으면 붙지 않고, 단서 계산이 실패해도 종전 메시지 그대로입니다. 판정·exit code는 그대로이고 127 설정 오류 분기는 대상이 아닙니다. 오탐 범위는 installTrace와 같습니다.
