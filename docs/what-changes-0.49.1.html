커밋 직후의 리뷰가
구현 diff를 다시 봅니다

--scope 없이 돌린 harness-team review는 트리가 dirty면 working tree를, 깨끗하면 base 대비 브랜치 diff를 리뷰합니다. 그런데 하네스 자신이 트리를 늘 더럽혔습니다. post-commit 훅은 커밋마다 활성 task의 handoff를 다시 쓰고, review는 성공할 때마다 artifact·meta에 기록을 남깁니다. 그래서 커밋 직후의 리뷰는 구현 대신 handoff 한 파일을, 커밋 없이 이어 돌린 두 번째 리뷰(R2 → R3)는 앞 리뷰의 기록을 리뷰했습니다 — 그 리뷰도 증거로 기록됐습니다. 0.49.1은 하네스가 스스로 쓴 기록 파일을 dirty로 세지 않습니다.

왜 patch인가 — 문서가 약속한 판정을 코드가 지키지 못했다

명령·플래그·출력 형식은 그대로입니다. "dirty면 worktree, clean이면 diff"라는 판정이 하네스 자신의 출력 때문에 늘 worktree로 기울던 결함을 고쳤습니다. 명시한 --scope는 동작이 같습니다.

표면경로도달 경로소비자 영향
CLI 동작src/commands/review.mjs resolveScope플러그인 갱신review(R2 --framing scenario·adversarial·testcritic 포함)와 harness-team scope의 자동 판정
슬래시 명령commands/harness-review.md 2단계 · commands/harness-task.md플러그인 갱신판정 규칙 정본에 제외 집합을 적었다

scope 판정 — 하네스 기록 파일은 dirty가 아니다

제외는 활성 task의 네 파일뿐입니다. 그 밖의 변경이 하나라도 있으면 0.49.0처럼 worktree입니다. 활성 task가 없으면 제외도 없습니다.

Fixed · #139

커밋 직후 — 훅이 쓴 handoff

원인
post-commit 훅(harness-team handoff)은 커밋 뒤에 <name>-handoff.md·<user>-handoff.md를 다시 씁니다. 그래서 커밋 직후의 트리는 늘 dirty였고, 자동 판정은 handoff만 보는 worktree였습니다(R2 시나리오 대조가 두 task에서 "무효 범위"로 기록됨).
지금
이 두 파일을 dirty에서 뺍니다. done 가드가 "훅 자신의 출력"으로 무시해 온 것과 같은 집합(handoffRelPaths)입니다.
바뀌는 것
기본 브랜치에서 handoff만 바뀐 상태는 이제 handoff를 리뷰하지 않고 "리뷰할 것 없음"으로 끝납니다.
Fixed · #139

이어 돌린 리뷰 — review가 쓴 기록

원인
review는 성공할 때마다 활성 task의 <name>-artifact.md·<name>-meta.json에 기록합니다. 커밋 없이 R2 다음 R3를 돌리면 두 번째 판정이 그 두 파일 때문에 다시 worktree였습니다.
지금
scope 판정은 이 두 파일도 dirty에서 뺍니다. done 가드는 빼지 않습니다 — 종결 커밋에 담겨야 하는 파일입니다.
트레이드오프
artifact는 사람이 쓰는 기록이기도 해서, artifact만 손으로 고친 상태도 diff로 갑니다. 그 편집은 리뷰에 안 잡히지만 diff는 커밋된 코드를 보므로 잃는 것이 작습니다.
