task-brief — Spec

목적 / 요구사항

  • 문제: 구현 전 사람 검토(A5 게이트 — 구현에 들어가기 전에 사용자가 spec을 한 번 검토)를 하려면 spec 전문을 읽어야 한다. spec은 템플릿 안내·주석· 자가진단이 섞인 긴 마크다운이라 "빠르고 확실한" 검토가 어렵고, 에이전트가 요약 슬라이드를 쓰면 spec에 없는 사실이 섞일 수 있다 (kc-platform 회고 A3, 설계 task team-harness-improvements).
  • 영향: 새 CLI brief와 그 표면(bin/harness-team.mjs router, src/cli-args.mjs), clean CLI, 문서(commands/harness-task.md, templates/docs/README.md, README 명령어, skills/harness-team/SKILL.md). 하네스를 쓰는 모든 소비자 프로젝트의 task 작성자(구현 전 자기 검토).
  • 기대 결과: harness-team brief [--stage spec]이 활성 task spec의 절(목적·범위·설계·Ontology·R1 발견)과 열린 항목, 선언돼 있으면 Done evidence scenarios를 그대로 슬라이드로 렌더해 <name>-brief.html을 쓴다. 렌더 결과의 텍스트는 모두 spec 원문의 부분 문자열이다 (새 사실 0 — 결정 A3-1). 슬라이드마다 출처 절 이름이 보인다.
  • 제약: 결정론 — 같은 spec이면 같은 바이트(시각·난수 없음). CSS scroll-snap·script 0·외부 자산 0·system font stack. probe → degrade 계약은 적용하지 않는다(A3-1 — probe할 외부 도구가 없다). 슬래시 명령을 새로 만들지 않는다(manifest-sync 표면을 늘리지 않음). doctor·AGENTS.md·templates/AGENTS.md.hbs·src/commands/task.mjs는 바꾸지 않는다. A5(human-review-gate)를 기다리지 않는다(사용자가 병렬 시작을 택함). push·PR·릴리스는 범위 밖.

원천 검토 (R1)

발견

  • Obsidian 열람(설계의 미검증 항목) — 실측할 수 있는지 먼저 확인했다. Obsidian 공식 지원 형식에 .html이 없다(Markdown·Bases·Canvas· Images·Audio·Video·PDF — 다른 형식은 커뮤니티 플러그인). 이 볼트의 커뮤니티 플러그인 21개에 HTML 뷰어는 없다. 즉 scroll-snap 이전에 Obsidian은 <name>-brief.html을 네이티브로 열지 않는다. 플러그인 열람을 실측하려면 플러그인 설치(사용자 볼트 변경)와 GUI 조작이 필요하다. → 결정(2026-11-18): 열람 정본은 로컬 브라우저다. Obsidian은 네이티브 미지원(문서 근거), HTML 플러그인 열람은 미검증으로 남긴다(## 참고). 결정 A3-1(결정론 HTML)은 그대로 두고 열람 경로만 좁힌다. 로컬 브라우저의 scroll-snap은 구현 뒤 내장 브라우저로 실측한다.
  • "새 사실 0"의 판정 방식 — 설계는 "렌더 결과의 텍스트가 모두 spec 원문의 부분 문자열"이다. 슬라이드 번호·"출처:" 라벨·생성 시각 같은 장식 글자도 spec에 없는 텍스트라 이 판정을 깬다. → 결정(2026-11-18): 장식 글자를 두지 않는다. 출처 절 이름은 spec 제목 글자 그대로(예: 설계 / 접근)가 슬라이드 제목·출처 표지를 겸하고, <title>은 H1이다. 생성 시각을 넣지 않아 같은 spec이면 같은 바이트다. 판정은 텍스트 노드마다 엔티티를 풀고 공백 연속을 한 칸으로 접은 뒤 (spec 쪽도 같이 접어) 부분 문자열인지 본다 — HTML은 공백을 접어 그리므로 줄 이음은 사실이 아니다. scenarios 값은 JSON을 푼 문자열이라 escape(\"·\u…)가 든 값은 원문의 부분 문자열이 아니다 — 이 저장소 spec 187개에 렌더해 보니 실패는 cmd의 \" 8건뿐이었다. JSON escape를 푸는 것은 엔티티를 푸는 것과 같은 표현 변환이라, 판정은 spec 원문과 그 spec의 Done evidence가 선언한 scenarios의 키·값(푼 문자열)을 원문으로 센다 (키까지 — codex 1차 P1: "\u0073cenarios"처럼 escape로 쓴 키). 걷어 낸 주석 자리는 빈 줄로 남긴다 — 앞뒤 줄이 한 문단으로 붙으면 원문에 없는 문자열이 된다(codex 1차 P1).
  • spec 안에 있지만 이 task의 사실이 아닌 글자 — 템플릿 안내 문단(제목 아래 기울임 문단)과 HTML 주석(Done evidence의 주석 처리된 예시 "review": "required")은 부분 문자열 검사를 통과하지만, 슬라이드에 나오면 선언되지 않은 요건이 선언된 것처럼 보인다. → 결정(2026-11-18): 코드 펜스 밖 줄머리 HTML 주석과 안내 문단(절 첫 블록이면서 단일 *로 시작하고 끝나는 문단 — ** 굵게는 아니다, 본문 중간의 기울임 문단은 작성자 글이라 남긴다 — codex 1차 P2)을 렌더 전에 걷어 낸다. scenarios는 parseDoneEvidenceDeclaration이 configured로 돌려준 것만 렌더한다 (done 가드와 같은 판정 — invalid면 CLI 출력에만 알린다). 그 파서가 주석·펜스 안의 ## Done evidence 예시를 선언으로 읽는 경우가 있어도 브리프는 따로 판정하지 않는다 (codex 1차 P1 기각) — 브리프가 가드와 다르게 읽으면 done·scenario check가 실제로 강제하는 시나리오를 숨기게 된다. 파서를 고치는 것은 done 가드 변경이라 이 task 밖이다.
  • 열린 항목의 문법 — 설계는 "(open)/(unresolved) 항목"이다. A4가 외부 질의 마커 세 상태를 더했고 셋 다 게이트를 통과하지 못한다. 이월 (open → <대상>)은 게이트를 통과하지만 답은 아직 없다. → 결정(2026-11-18, MAINTAINING "문법·형제 경로 전체"): 목록 항목에 맨 글자로 붙은 (open…)(이월 포함)·(unresolved)·(<출처>, unresolved)· (ask:…)·(asked:…)·(answered …)를 spec 어디서든 모아 한 슬라이드에 둔다. 백틱 안은 언급이라 세지 않는다(harness-interview 표기/언급 구분). (open 뒤는 ) 또는 →만 태그다 — (open 아님, …) 같은 산문은 세지 않는다. 외부 질의는 역할이 있어야 태그다 — (ask:)는 세지 않는다(codex 1차 P2). 두 (open)이 닫혔다처럼 산문에 맨 글자로 쓴 (open)은 harness-interview 규칙대로 표기로 센다(codex 1차 P2 기각 — 게이트와 같은 판정). 이월을 넣는 이유: 검토자는 "답 없이 넘긴 것"을 보고 승인해야 한다. 묶음마다 그 항목이 있던 절 제목을 출처 표지로 단다. 열린 항목이 없으면 슬라이드도 없다.
  • --stage ship — 설계는 "후순위, 첫 PR에서 빼도 됨"이다. → 결정(2026-11-18): 뺀다. --stage는 spec만 받는다 — 값 계약은 FLAG_CHOICES(MAINTAINING 규칙표)에 두고, 하는 일 없는 값을 광고하지 않는다. ship을 더하는 것은 하위 호환 변경이다(플래그 없음 = spec).
  • A5와의 순서 — 설계 PR 분할은 "②는 ① 뒤"인데 사용자가 병렬 시작을 택했다. brief는 게이트 단계에 기대지 않는다(spec만 읽는다). → 결정(2026-11-18): commands/harness-task.md에는 게이트와 독립된 짧은 절만 둔다. A5 머지 뒤 rebase 때 게이트 절이 이 절을 부르게 맞춘다. src/commands/task.mjs는 고치지 않는다(A5가 taskPlanTemplate을 고친다 — 충돌 최소화, readActive·parseDoneEvidenceDeclaration은 import만).
  • 생성물의 git 상태 — 브리프를 만들고 두면 미추적 파일이라 done의 미커밋 가드가 막는다(codex 1차 P2). gitignore는 init·migrate 표면(소비자 .gitignore)을 늘리고, 가드 면제는 task.mjs(A5와 충돌)를 고친다. → 결정(2026-11-18): 브리프는 검토한 시점의 스냅샷이라 task 문서와 함께 커밋한다(다이어그램과 같다). spec을 고쳐 다시 검토하면 다시 만들어 커밋한다. 커밋하지 않을 거면 지운다. 문서(commands/harness-task.md·templates/docs/README.md)에 적는다.

설계 / 접근

설계 task의 "A5 + A3" 절 중 슬라이드(A3) 항목을 옮겨 쓰고 위 R1 결정을 반영했다.

  • CLI(결정 A3-1): harness-team brief [--stage spec] — 활성 task(.harness/active.json)의 <name>-spec.md를 읽어 같은 폴더에 <name>-brief.html을 쓴다. 매번 덮어쓴다(생성물). LLM이 쓰지 않으므로 "새 사실 0"이 구조로 보장되고, probe할 외부 도구가 없어 probe → degrade 계약은 적용하지 않는다. 위치 인자는 받지 않는다. --json은 command: 'brief' envelope(artifacts, slides·sections·missing). 오류(활성 task 없음·spec 없음·렌더할 절 없음)는 exit 1, error 패킷, 아무것도 쓰지 않음.
  • 절 선택(spec 문서 순서): ## 목적…·## 범위…·## 원천 검토…의 ### 발견만·## 설계…·## Ontology — 제목 머리 글자로 찾는다. ### 하위 절이 있으면 하위 절마다 한 슬라이드(위 절 제목을 출처 표지로), 하위 절 앞 본문도 한 슬라이드. 그 뒤 열린 항목 슬라이드(있을 때만), Done evidence scenarios(선언됐을 때만 — 시나리오마다 id·given·when·then·test·cmd 표). 맨 앞은 H1 표지(H1이 있을 때).
  • 렌더러(작은 마크다운 부분집합): 문단, 목록(-·*·+·1. — 들여쓰기 중첩, 이어지는 줄), 굵게 **, 인라인 코드, 표(| 헤더 + 구분 줄), 코드 펜스, 슬라이드 안 #### 이하 제목. 링크·이미지·기울임·인용은 글자 그대로. spec 글자는 모두 HTML escape(&·<·>·") — spec의 <script>는 글자다.
  • 산출물: <!doctype html> 한 파일. 인라인 <style> 하나(고정 문자열 — spec과 무관), script 0, src·href·url(·@import 0, system font stack, html { scroll-snap-type: y mandatory }·.slide { scroll-snap-align: start; min-height: 100vh }, 다크 모드, 인쇄(break-after: page).
  • 명령 표면: CLI 서브커맨드 brief(bin/harness-team.mjs router·taskCmds, cli-args.mjs COMMANDS·VALUE_FLAGS·FLAG_CHOICES.stage). 슬래시 명령은 새로 만들지 않는다 — commands/harness-task.md의 절이 harness-team brief를 부른다.
  • 형제 경로: clean.mjs TASK_FILE kind에 brief(확장자 그룹은 이미 html), task-paths.mjs kind 주석, templates/docs/README.md 트리 (생성물·비-SSOT — docs seed는 migrate refresh 대상이 아니라 sha 등록 없음, A1·A2 선례).
  • 문서 정본: commands/harness-task.md "검토용 슬라이드" 절(게이트와 독립 — A5 머지 뒤 게이트 절과 연결). README 명령어 블록, Codex skills/harness-team/SKILL.md 한 줄.
  • 테스트: tests/brief-command.test.mjs — 새 사실 0(텍스트 노드 ⊂ spec — 표본과 이 저장소의 모든 task spec, 음성 대조: 남의 문자열 하나를 넣으면 판정이 실패), 외부 참조 0(태그·속성·style만 본다 — 본문 텍스트의 URL 언급은 허용), escape(<script>·링크 문법), 주석·안내 문단 제외, 열린 항목(맨 글자/백틱, 마커 종류), scenarios(configured만), 결정론(두 번 실행 바이트 동일), 없는 절 생략·전부 없으면 exit 1·쓰지 않음, 활성 task 없음. tests/cli-args.test.mjs(--stage 값·--json 목록), tests/clean.test.mjs(brief 보호).

Ontology

  • 브리프(brief): spec의 정해진 절만 그대로 옮긴 검토용 슬라이드 HTML <name>-brief.html. 생성물·비-SSOT — 사실의 정본은 spec이고, spec이 바뀌면 다시 만든다. 검토한 시점의 스냅샷으로 task 문서와 함께 커밋한다.
  • 새 사실 0: 브리프의 모든 텍스트 노드가 (엔티티를 풀고 공백을 접은 뒤) spec 원문 — 또는 그 spec이 선언한 scenarios JSON의 푼 키·값 — 의 부분 문자열인 상태. 장식 글자를 두지 않아서 성립한다.
  • 열린 항목: 목록 항목에 맨 글자로 붙은 열린 질문·충돌 표기 — (open…)(이월 포함)·(unresolved)·외부 질의 마커 세 상태.
  • 출처 표지: 슬라이드가 옮긴 spec 절의 제목 글자 그대로.
  • 게이트 근거(2026-11-18): 설계 결정 A3-1 확정(PR #184), 판정 방식·제외 글자·열린 항목 문법·--stage ship 제외·A5 순서·없는 절을 R1 결정으로 닫음, Obsidian 열람은 네이티브 미지원·플러그인 미검증으로 명시. 목표·제약·완료 기준·영향 파일이 모두 식별됨.
