# th-release-0-12 — Spec

## 목적 / 요구사항

- `v0.11.0..main`의 실제 변경 범위를 검토해 파괴적 변경이 없는지 확인하고 0.12.0 minor 릴리스를 준비한다.
- Keep a Changelog 형식으로 `CHANGELOG.md`에 사용자 체감 변화를 기록한다.
- 생성된 최신 개요와 현재 워크플로 문서에서 0.12.0 스냅샷을 만든다.
- `docs/what-changes-latest-version.html`에 변경·이유·효과를 성격별로 설명한다.
- 필수 검증과 release dry-run을 통과한 뒤 네 매니페스트를 0.12.0으로 맞추고 커밋한다.

## 설계 / 접근

- 릴리스 절차는 `MAINTAINING.md`를 정본으로 따른다.
- 문서 인벤토리는 복제하지 않고 기존 정본을 가리키며, 최신 개요는 생성기를 먼저 실행한 뒤 스냅샷으로 복사한다.
- 실제 태그 범위에는 PR #1–#12 외 직접 커밋 네 개가 있으므로 총 16개를 검토하고 누락 없이 릴리스 노트에 반영한다.
- 태그와 기본 브랜치 푸시는 firstmate 병합 이후 별도 단계로 남긴다.

## Ontology
*이 task가 다루는 핵심 개념의 정의. "X가 정확히 뭔가?"에 답한다.*

- **릴리스 범위**: `v0.11.0` 태그가 가리키는 커밋 이후 현재 `main`까지의 모든 변경.
- **스냅샷**: 특정 버전 시점의 현재 HTML 산출물을 보존한 버전명 파일. 생성 문서는 생성 후 복사한다.
- **변경 설명**: 변경 목록뿐 아니라 각 항목의 원인과 사용자·메인테이너가 체감하는 효과를 함께 기록한 문서.
