### fixture를 고쳐야 했던 이유 (검토 포인트)

`makeEvidenceFixture`와 HEAD-less 테스트의 fixture에 `demo-meta.json`을 추가했다.
판정 창의 **입력이 바뀌었으므로**, 창을 선언하지 않는 fixture는 "구 task"가 되어 시각 기반
가드가 아예 돌지 않는다. 기본값을 기존 `switchedAt`과 같은 시각(`now-60s`)으로 둬서
**기존 27개 테스트의 판정은 하나도 변하지 않는다.** assertion은 손대지 않았다.

한 줄 요약: `done` 가드가 증거를 찾는 창이 `[switchedAt, now]`인데, `switchedAt`은
**마지막 활성화 시각**이라 재활성화하면 이미 만족된 증거가 창 밖으로 밀려난다.
있어야 할 것은 `[task 작업 시작, now]`다.

**주의:** 이 task의 핵심 난점은 "오탐을 없애는 것"이 아니라 **"오탐만 없애는 것"** 이다.
창을 넓히면 오탐은 사라지지만 가드가 막던 망각도 함께 통과한다 — spec 요구사항 2가 금지한다.

## 조사 기록 (2026-08-25)

### 어떻게 드러났나

`boundary-perf-invariant`(plan 14/14, PR #44 머지 완료)를 종결하려 하자 가드 2건이 걸렸다:

```
cause: spec이 `review: required`인데 이 task 기간의 리뷰 마커가 artifact에 없음
cause: task 활성화 이후 커밋이 0개임
```

둘 다 오탐이었다. `done`은 활성 task만 대상이므로 끝난 task를 종결하려면 **재활성화**해야 하는데,
그것이 `switchedAt`을 `04:25:13Z` → `09:19:47Z`로 갱신했다.

| 가드 | 실제 증거 | 새 창 기준 판정 |
|---|---|---|
| 리뷰 마커 | `at=05:35:00Z` (codex 리뷰) | 창 밖 → "없음" |
| 커밋 | 6건 `9414faf`…`f704672` (PR #44로 머지) | 창 밖 → "0개" |

`--force`로 우회했고, **그 우회 자체가 이 task를 만든 이유다.**

### 왜 구조적인가

`runTask`는 생성(`:204`)과 **재활성화(`:231`) 모두** `switchedAt`을 현재 시각으로 덮어쓴다.
따라서:
- 끝난 task를 닫을 때마다 **반드시** 이 오탐이 난다 — 종결에는 재활성화가 선행되므로.
- 종결만의 문제도 아니다. **task를 전환했다가 되돌아오는 것만으로도** 창이 초기화되어
  그 전 작업 증거가 통째로 사라진다.

즉 "가끔 나는 버그"가 아니라 **정상 경로에서 항상 재현되는 구조**다.
이대로면 `--force`가 종결의 표준 절차가 되고, 가드는 이름만 남는다.

### 설계 긴장 (이 task의 진짜 어려움)

기존 테스트가 반대 방향을 못박아 두고 있다 —
`tests/done-guard.test.mjs:461` *"이전 task 기간의 마커(at < switchedAt)는 무효 → 차단"*.
**옛 리뷰 마커를 재사용해 통과하는 것을 막는 것이 의도**다.

그러므로 수정은 "옛 마커를 허용"하는 방향이면 안 된다. 되살려야 하는 것은
**같은 task의 이전 활성 구간**뿐이고, 다른 task 기간의 마커는 계속 막아야 한다.
이 구분이 되지 않으면 오탐은 사라져도 가드는 무력해진다.

### 후보 요약

(A) `firstActivatedAt` 신규 필드 — **유력**. 의미가 정확하고 재활성화가 건드리지 않는다.
(B) `meta.created` 재사용 — **부적합**. `slice(0,10)`이라 날짜만이라 창이 과도하게 넓다.
(C) 활성 구간 누적 — 가장 정확하나 상태·복잡도 증가.
(D) task 디렉터리 첫 커밋에서 유도 — 새 상태 불필요, (A)와 조합 검토 가치.
(E) 종결 시에만 완화 — 증상만 가림, 전환 케이스 미해결.

상세·평가는 spec의 "후보" 표가 정본이다.

## 발견 — 범위 밖 (후속 과제)

1. **`<name>-spec.md`가 테스트 파일로 오분류된다.** `isTestPath()`의 basename 규칙
   `/(^|[._-])(test|spec)s?\.[^.]+$/i`에 `demo-spec.md`의 `-spec.md`가 걸린다.
   모든 task는 자기 spec.md를 커밋하므로, **소스만 바꾸고 테스트를 안 써도 테스트 가드가
   통과한다.** 이 task의 창 문제와 독립된 별개 결함이라 여기서 고치지 않았고,
   대신 요구사항 2 그물 테스트가 이 quirk에 의존하지 않도록 spec 파일 없이 구성했다.
   → 가드 힘에 직접 영향이 크므로 별도 task로 다룰 값어치가 있다.
2. **기존 task의 `firstActivatedAt` 백필.** git 이력에서 유도하는 것은 가드 실행 경로가 아니라
   `migrate`의 일이다. 지금은 degrade로 흡수된다.
3. **이 task 자신도 구 task다.** `done-guard-window`의 meta는 구 하네스가 만들어
   `firstActivatedAt`이 없다 — 종결 시 degrade 경로를 탄다(설계대로).

## Learnings

- **오탐은 가드를 죽인다.** 이 건은 "가드가 틀렸다"보다 **"가드를 우회하는 것이 정상 절차가 된다"**
  가 진짜 위험이다. 실제로 이번에 `--force`를 썼고, 같은 구조가 남아 있는 한 다음에도 쓰게 된다.
  오탐률은 정확도 문제가 아니라 **신뢰 문제**다.
- **"마지막 X 시각"을 "X 구간의 시작"으로 쓰면 안 된다.** 두 개념이 대부분의 경우 우연히
  일치해서 오래 버그가 드러나지 않는다 — 재활성화처럼 갈라지는 순간에만 터진다.
- **가드를 고칠 때의 판정 기준은 "통과하는가"가 아니라 "여전히 막는가"** 다.
  이 task의 성공 조건에 기존 차단 테스트(`:461`) 통과를 명시적으로 넣은 이유다.
