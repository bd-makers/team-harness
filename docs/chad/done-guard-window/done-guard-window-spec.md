# done-guard-window — Spec

## 목적 / 요구사항

`harness-team done`의 증거 기반 가드가 **구조적으로 오탐을 낸다.** 판정 창의 기준이
`active.json`의 `switchedAt`인데, 이 값은 "**마지막 활성화 시각**"이지 "**이 task의 작업 구간**"이
아니다. task를 다시 활성화하면 창이 초기화되어, 이미 만족된 증거가 사라진 것처럼 보인다.

**2026-08-25 실제 발생.** `boundary-perf-invariant`(plan 14/14, PR #44 머지 완료)를 종결하려는데
가드 2건이 걸렸다:

```
cause: spec이 `review: required`인데 이 task 기간의 리뷰 마커가 artifact에 없음
cause: task 활성화 이후 커밋이 0개임
```

둘 다 **오탐**이었다. `done`은 활성 task만 대상이라 끝난 task를 종결하려면 재활성화해야 하는데,
그 재활성화가 `switchedAt`을 `04:25:13Z` → `09:19:47Z`로 밀어 버렸다. 실제 증거는 원래 창 안에 있었다:

| 가드 | 실제 증거 | 새 창(09:19) 기준 |
|---|---|---|
| 리뷰 마커 | `at=05:35:00Z` (codex 리뷰 기록) | 창 **밖** → 없다고 판정 |
| 커밋 | 6건 (`9414faf`…`f704672`, 전부 PR #44로 머지) | 창 **밖** → 0개로 판정 |

결국 `--force`로 우회했다. **이것이 이 task가 막으려는 결과다** —
가드를 우회하는 것이 정상 절차가 되면 가드는 더 이상 아무것도 막지 못한다.

요구사항:
1. 재활성화가 증거를 무효화하지 않게 한다.
2. **가드의 원래 힘을 약화시키지 않는다.** 창을 넓히는 것만으로 "green"을 사면 안 된다 —
   이 가드가 막으려던 "망각"을 계속 잡아야 한다.
3. 기존 의도(옛 리뷰 마커 재사용 방지)를 보존한다.

## 설계 / 접근

### 영향 범위 — `switchedAt`에 의존하는 가드 3종

`src/commands/task.mjs`의 `collectDoneIssues()`:

| 위치 | 가드 | 사용 방식 |
|---|---|---|
| `:442-446` | 리뷰 마커 신선도 | `m.at >= Date.parse(switchedAt)` |
| `:474-480` | 활성화 이후 커밋 0개 | `git log --since=<switchedAt>` |
| `:486-497` | 테스트 미작성 | `git log --since=<switchedAt> --name-only` |

`switchedAt`은 `runTask`에서 **생성 시(`:204`)와 재활성화 시(`:231`) 모두 현재 시각으로 덮어쓴다.**

### 문제는 종결보다 넓다

"끝난 task를 닫을 때"만의 문제가 아니다. **task를 전환했다가 되돌아오는 것만으로도** 창이
초기화되어 이전 작업 증거가 통째로 사라진다. 여러 task를 오가는 작업 방식에서는
항상 발생한다.

### 설계 긴장 — 그냥 넓히면 안 된다

기존 테스트가 의도를 명시적으로 고정해 두고 있다:
`tests/done-guard.test.mjs:461` — *"이전 task 기간의 마커(at < switchedAt)는 무효 → 차단"*.
즉 **옛 리뷰 마커를 재사용해 통과하는 것을 막는 것이 설계 의도**다.
수정은 이 의도를 유지하면서 "**같은 task의 이전 활성 구간**"만 되살려야 한다.
"옛 마커 전부 허용"으로 가면 가드가 무력해진다 — 요구사항 2 위반.

### 후보

| 후보 | 내용 | 평가 |
|---|---|---|
| **(A) `firstActivatedAt` 도입** | 최초 활성화 시각을 meta에 기록하고 창의 시작으로 쓴다. 재활성화는 이 값을 **건드리지 않는다** | **유력.** 의미가 정확("task 작업 구간의 시작"). 새 필드 1개 |
| (B) `meta.created` 사용 | 이미 있는 필드 | ⚠️ **날짜만**(`slice(0,10)`)이라 그날 00:00로 뭉개진다. 오래된 task는 창이 과도하게 넓어져 가드가 약해짐 |
| (C) 활성 구간 누적 | `[{from,to}...]`를 기록해 합집합으로 판정 | 가장 정확하지만 상태·복잡도가 크게 증가 |
| (D) task 디렉터리 이력에서 유도 | `docs/<user>/<task>/`를 처음 건드린 커밋을 창 시작으로 | 새 상태 불필요. 단 커밋 전 task는 창이 없음 |
| (E) 종결 시에만 창 완화 | `done` 경로에서만 넓게 본다 | 증상만 가림 · 전환 케이스는 그대로 |

**(A)가 유력**하나 확정하지 않았다 — 마이그레이션(기존 `active.json`·`meta.json`에 필드 없음)과
하위 호환 처리를 함께 설계해야 하고, (D)와의 조합도 검토 가치가 있다.

### 하위 호환

`switchedAt`이 없는 구 `active.json`은 이미 "시각 비교 포기, 마커 존재만 확인"으로
degrade한다(`:444` 주석). 새 필드도 **없으면 degrade**하는 같은 원칙을 따라야 한다 —
없다고 차단하면 기존 task가 전부 막힌다.

## Ontology

- **`switchedAt`**: 마지막 활성화 시각. **task 작업 구간의 시작이 아니다** — 이 혼동이 버그의 원인.
- **판정 창(evidence window)**: 가드가 "이 task 기간의 증거"를 찾는 시간 범위.
  현재 `[switchedAt, now]`이며, 있어야 할 것은 `[task 작업 시작, now]`.
- **오탐(false positive)**: 증거가 실제로 존재하는데 창 밖이라 없다고 판정되는 것.
  **가드 무력화의 전형적 경로** — 오탐이 반복되면 `--force`가 습관이 된다.
- **가드 약화**: 창을 넓혀 오탐을 없앴지만 진짜 누락도 함께 통과시키는 것. 요구사항 2가 금지한다.

- [x] **Constraint 명확도** (30%) — 기존 의도(옛 마커 재사용 차단) 보존 · 하위 호환 degrade ·
      가드 완화 금지. `tests/done-guard.test.mjs`(27 test)가 회귀 그물이다.
- [x] **Success 기준** (30%) — 재활성화 후에도 원래 창의 마커·커밋이 인정되고,
      **옛 마커 재사용 차단 테스트는 계속 통과**한다. 재현 테스트를 먼저 추가한다.
- [x] **Context 명확도** — `src/commands/task.mjs`(`collectDoneIssues` · `runTask`) ·
      `tests/done-guard.test.mjs`. 영향 범위가 좁고 특정됐다.
- [ ] **Ambiguity ≤ 0.2** — **가중합 1.0이나 구현 설계(A~D 중 선택 + 마이그레이션)가
