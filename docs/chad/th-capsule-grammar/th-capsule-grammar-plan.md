# th-capsule-grammar — Plan

## 목표

Failure capsule의 하위 제목/실질 본문 문법을 정합하게 확정해 예산 누수와 과다 계수를 함께 막는다.

## 단계
- [x] 현재 구현의 두 오판을 독립 회귀 테스트로 재현하고 빨간불 증거를 남긴다.
- [x] 종결자와 실질 본문 판정을 함께 수정하고 네 필수 사례를 테스트로 고정한다.
- [x] 기존 context card 전수의 변경 전후 판정을 비교하고 문법을 제품 문서에 기록한다.
- [x] 관련 테스트, 전체 테스트, `pre-commit-check.sh`를 통과한다.
- [x] 결과·리뷰를 task 문서에 기록하고 feature branch에 커밋한다.

## Ontology 변경 로그
*개념이 새로 정의되거나 의미가 바뀌면 한 줄로 기록. spec.md의 Ontology 섹션을 갱신할 트리거가 된다.*

- `####` 이하 ATX 제목을 capsule 본문 범위로 정의하되 제목 줄 자체는 실질 본문에서 제외한다.
- ATX 제목은 CommonMark의 0~3칸 들여쓰기만 인정하며, 4칸 이상 들여쓴 heading 유사 줄은 코드 본문으로 센다.
