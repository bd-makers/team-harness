# eager-tier-slimming — Spec

## 목적 / 요구사항

**오늘 무엇이 안 되는가.** eager 계층 예산(24 KiB) 여유가 **275 B**뿐이다. `AGENTS.md`에 한 문단만
더해도 다시 초과한다 — 실제로 v0.32.2가 `### plan.md 계약`(+1,397 B)으로 64 B를 넘겨 **태그까지 나갔고**,
발행 뒤 `doctor`로 드러나 산문을 339 B 깎아 되돌렸다. 즉 지금 구조는 **규칙을 추가할 때마다 예산과
협상해야 하는 상태**이고, 협상의 결과가 "규칙을 덜 쓰는 것"이면 문서가 아니라 계약이 손해를 본다.

**누가 영향받는가.** (1) 이 저장소에 규칙을 추가하려는 메인테이너 — 매번 축약 압박을 받는다.
(2) 소비자 프로젝트의 모든 에이전트 세션 — eager는 매 세션 무조건 로드되므로 비대는 전 세션 비용이다.

**기대 결과.** 프로젝트 eager 소계(`AGENTS.md` 13,215 + `CLAUDE.md` 6,112 = **19,327 B**)를
**17,500 B 이하**로 줄인다(약 1.8 KB 감축). 줄이는 방법은 삭제가 아니라 **이전**이다 —
절차 본문을 lazy 정본으로 옮기고 eager에는 트리거 한 줄만 남긴다. 구조 개편(절 통째 재설계)은
이번 범위가 아니다: 산문 압축과 명백한 이전만으로 목표에 닿고, 소비자 전파 범위가 좁아 되돌리기 쉽다.

**제약.**
- **정보 소실 0.** 옮긴 절차는 lazy 정본에 그대로 존재해야 한다. 이전 후 "어디에도 없는 규칙"이 생기면 실패다.
- **에이전트 중립.** Codex·Cursor는 플러그인 `commands/`를 읽지 못한다. 그들에게 도달하는 lazy 표면은
  `skills/<name>/SKILL.md` 미러와 `templates/**`뿐이다. `commands/`만 정본으로 삼는 이전은
  **Claude에게만 유효**하므로, 도구 중립이 필요한 규칙은 eager에 요약을 남긴다.
- **상황 인식형 규칙은 eager에 남긴다.** 트리거를 명령·파일·훅·가드로 표현할 수 없는 규칙
  (예: CLAUDE.md §5-A 복잡도 게이트 — "막혔다고 느낄 때")은 이전 대상이 아니다.
- **마커 동일성.** 수정 기점은 `templates/*.hbs`이고 루트 파일의 마커 절을 동일하게 갱신한다
  (`agent-files.test.mjs`가 강제).
- **목표는 프로젝트 소계로만 잰다.** 전역 `~/.claude/CLAUDE.md`(이 머신 4,974 B)는 사용자 소유이고
  머신마다 다르다 — 목표를 거기 의존시키면 다른 머신에서 무의미해진다. `doctor`의 경고는 종전대로
  네 파일 합계 기준을 유지하며, 이 task가 그 검사를 바꾸지 않는다.

## 설계 / 접근

선행 task `instruction-structure`의 판별 기준을 **재적용**한다(새 기준을 만들지 않는다):

> **트리거를 컨텍스트 없이 인지할 수 있는가.** 트리거가 명령·파일·훅·가드로 표현되면
> 절차는 lazy 정본으로, 트리거 문장만 eager에 남긴다.

측정된 절별 바이트(2026-09-07, `AGENTS.md` 13,215 B · `CLAUDE.md` 6,112 B):

| 절 | 바이트 | 트리거 | 후보 판단 |
|---|---|---|---|
| `### task 단위 관리` | 2,433 | `harness-team task`/`done` 실행 | meta.json 판정 창·완료 만료 상세는 **lazy 후보**(정본: `commands/harness-task.md` + `done` 가드 메시지) |
| `### task 워크플로우` | 2,106 | 각 하위명령 | 다이어그램 옵트인 문단이 여전히 큼 — 선행 P1이 남긴 "도구 중립 요약"이 요약보다 길다 |
| `## AI 팀 역할 분담` | 2,042 | 상시(역할) | 역할표는 eager 유지. D2·D4~D7 요약은 `docs/decisions.md`가 정본이므로 **추가 압축 후보** |
| `### Task Context Card (TCC)` | 1,105 | `context check` | 한도 수치는 이미 검사에 위임됨 — 잔여 산문 압축 후보 |
| `### JIT retrieval 프로토콜` | 1,071 | 세션 재개·검색 | **상황 인식형 — eager 유지 유력** |
| `### plan.md 계약` | 1,057 | plan 작성 시 | 색인 성격이라 유지. 단 항목별 상세는 이미 정본을 가리킴 |
| `### 코드 리뷰 기준` | 701 | 중요한 변경 완료 후 | 도구 중립 필요(Codex 리뷰어가 읽음) — 유지 유력 |
| CLAUDE.md `### 5-A. 복잡도 게이트` | 1,909 | 상황 인식 | **이전 대상 아님**(트리거가 상황) — 단 escalation 패킷 5항목은 압축 여지 |
| CLAUDE.md `### 2. 서브에이전트 전략` | 1,075 | 위임 판단 시 | `/delegation-router` 스킬과 중복 여부 확인 필요 |

접근 순서: (1) 표별 후보를 확정하고 **이전 대상과 유지 대상을 먼저 가른다**,
(2) 대상별로 lazy 정본을 지정한다(기존 문서 우선, 새 파일은 최후), (3) 옮기고 eager에 트리거만 남긴다,
(4) 이전 전후 바이트와 **정보 소실 0**을 대조한다.

## Ontology

선행 task `instruction-structure`의 어휘를 그대로 쓴다. 재정의하지 않는다.

- **eager 지시** — 매 세션 무조건 로드(`AGENTS.md`·`CLAUDE.md`·프로젝트 `.claude/CLAUDE.md`·전역 `CLAUDE.md`).
- **lazy 정본** — 특정 순간에만 로드되는 절차의 단일 소스(커맨드 문서·스킬·훅 주입·가드 메시지·문서 템플릿).
- **트리거/절차 분해** — 규칙 = 트리거(eager 1줄) + 절차(lazy 정본).
- **표면(surface)** — 같은 규칙이 서술된 파일 위치. 표면 수 > 1이면 드리프트 위험.
- **에이전트 중립 표면** — Codex·Cursor가 실제로 읽는 표면(`AGENTS.md`·`skills/*/SKILL.md`·`templates/**`).
  `commands/*.md`는 Claude 전용이므로 이곳으로만 옮긴 규칙은 다른 에이전트에게 **사라진다**.
- **예산 여유(headroom)** — `EAGER_TIER_MAX_BYTES`(24 KiB) − 네 파일 UTF-8 합계. 2026-09-07 기준 **275 B**.

게이트 통과 근거: 미정이던 두 축(목표 감축량 · 전역 파일 취급)을 2026-09-07 사용자 답변으로 확정 —
소계 17,500 B 이하, 전역 파일은 목표 계산에서 제외. 이로써 Constraint·Success가 측정 가능해졌다.

## Ambiguity 자가진단

- [x] **Goal 명확도** (40%) — 문제(예산 여유 275 B, 규칙 추가마다 축약 압박)와 기대 결과(소계 17,500 B 이하)가 각각 한 문장으로 있다.
- [x] **Constraint 명확도** (30%) — 제약 다섯: 정보 소실 0 · 에이전트 중립(commands/는 Claude 전용) · 상황 인식형 규칙 유지 · 마커 동일성 · 목표는 프로젝트 소계 기준.
- [x] **Success 기준** (30%) — ① 프로젝트 eager 소계 ≤ 17,500 B ② 이전 항목마다 lazy 정본 위치가 확인됨(정보 소실 0) ③ `npm test` green + `doctor` 무경고.
- [x] **Context 명확도** (brownfield) — 영향 파일이 특정됐다: `templates/AGENTS.md.hbs`·`templates/CLAUDE.md.hbs`·루트 두 파일·이전 대상 lazy 정본들·`agent-files.test.mjs`.
- [x] **Ambiguity ≤ 0.2** — 가중합 1.0. 두 (open)이 사용자 답변으로 닫혔다.
