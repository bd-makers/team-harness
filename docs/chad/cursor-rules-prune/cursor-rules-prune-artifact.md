## 결과

미러가 더 이상 생산하지 않는 `.cursor/rules/**/*.mdc`를 제거한다.

- `CURSOR_MIRROR_MARKER`(`<!-- harness:mirror -->`) — 생성 `.mdc`에 provenance 스탬프
- `.harness/cursor-mirror.json` — **직전 실행이 쓴 경로 기록**. 삭제 권한은 파일 내용이 아니라
  이 기록에서 나온다. 경로는 신뢰하지 않는 입력으로 다뤄 `..`·절대경로·역슬래시를 거른다.
- `pruneCursorMirrors` — 기록에 있고 / 이번 실행이 쓰지 않았고 / 스탬프가 아직 남아 있는 것만 삭제.
  비게 된 디렉터리는 깊은 것부터 `rmdir`(비어 있지 않으면 자연히 실패)
- `.claude/rules`가 통째로 사라져도 기록이 있으면 prune 한다 — early return이면 전부 고아로 남는다
- `sync`가 prune 건수를 별도 라인으로 보고

검증: 테스트 14건(미러 7 + prune 6 + 파서 1), `npm test` 240 pass / 0 fail, `docs:check` clean.
실제 템플릿으로 확인 — `styling.md`를 `frontend/`로 이동 + `testing.md` 삭제 → 옛 `.mdc` 2개 prune,
`frontend/styling.mdc` 생성.

## Learnings

- **"지운다"는 기능은 소유권 증명이 내용이 아니라 기록이어야 한다.** 파일 안의 마커는 누구나
  복제할 수 있고, 실제로 사용자가 생성물을 복사해 새 규칙을 시작하는 경로가 존재한다. 하네스가
  "내가 썼다"고 **기록한** 경로만 지우는 편이 한 단계 더 안전하다.
- **뮤테이션 검증은 코드가 아니라 테스트의 결함도 잡는다.** 통과하는 테스트를 믿지 말고, 가드를
  꺼서 그 테스트가 실제로 실패하는지 확인해야 한다 — 이번엔 그 절차만이 무의미한 경로를 쓴
  테스트를 드러냈다.
- **generated 파일도 사용자 디렉터리에 산다.** `.cursor/rules`는 하네스와 사용자가 공유하는
  공간이므로, 하네스는 자기 산출물만 소유하고 나머지는 읽기 전용으로 취급해야 한다.
