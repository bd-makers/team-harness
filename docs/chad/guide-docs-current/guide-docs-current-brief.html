  • done tests 기본값 — 0.52.0부터 optional(src/commands/task.mjs:746 DONE_EVIDENCE_DEFAULT)인데 required로 적음: docs/harness-cheatsheet.html:160, docs/harness-task-guide.html:510, docs/harness-onboarding-checklist.html:212, docs/harness-operations-playground.html(초기 상태 tests:'required', 허용값 안내 required|skip에 optional 누락).
  • 훅 목록의 block-dangerous-bash.sh(0.51.0) 누락 — docs/prerequisites.md:51("훅 네 개" — 실제 jq 셸 훅은 5개. boundary-checkpoint.sh는 JSON 파싱을 Node CLI에 맡겨 목록 대상이 아니다), docs/harness-task-guide.html:728, docs/harness-operations-playground.html:418, docs/harness-workflow-diagrams.html:263(PreToolUse 목록).
  • spec 골격 — docs/harness-task-guide.html:490–494가 scaffold 섹션을 나열하며 0.51.0 ## 범위 (In / Out) 절을 빠뜨림(src/commands/task.mjs:127).

영향: 문서를 따라 하는 팀원이 테스트 증거 미선언 task가 막힌다고 오해하고, 위험 셸 차단 훅의 존재를 모른다. 기대 결과: 위 문서가 현재 소스와 같은 사실을 적고, tests 기본값의 옛 문구는 회귀 테스트가 잡는다.

범위 (In / Out)

  • In: 위 6개 문서의 해당 문장·표·시뮬레이터 초기값, tests/docs-retired-phrases.json에 tests 기본값 옛 문구 등록.
  • Out: src/·templates/·commands/ 동작 변경(소스가 정본이다), 표지 라벨 "기준 v0.50.0" 재작성(가이드 전체 재검토는 범위 밖), 감사가 "허용 가능"으로 본 누락(cheatsheet·kickoff 덱의 clean·brief·reopen), 이력 문서(*-0.*.html·what-changes-*).

설계 / 접근

  1. 각 문장을 소스 정본에 맞춰 최소 수정한다(tests: 기본 optional, required면 소스 변경 시 테스트 변경 요구, skip 허용).
  2. playground 시뮬레이터: 초기 tests를 optional로, 허용값 안내에 optional을 넣고 가드 로직이 optional을 비차단으로 다루는지 확인한다.
  3. 훅 목록: PreToolUse Bash에 block-dangerous-bash.sh를 더하고, prerequisites는 실제 jq 셸 훅 목록과 개수로 고친다.
  4. 회귀: tests/docs-retired-phrases.json에 tests-default-required 항목(현행 문서 3곳의 옛 문구)을 등록한다.
  5. 같은 사실의 다른 자리를 전수 검색한다(MAINTAINING 규칙표).

Ontology

  • 가이드 문서: 표지 대조 가드가 없는 현행 소비자 문서(MAINTAINING 결합 강도 최하위).
  • tests 증거 기본값: spec Done evidence 미선언 시 done 가드가 쓰는 값 — optional.
  • 게이트 근거: 목표·제약(문서만)·성공 기준(아래 명령)·영향 파일 6개가 모두 정해졌다.
