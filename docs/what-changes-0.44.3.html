init --stack으로 고른 스택이
이제 다음 렌더에서도 유지됩니다

감지와 다른 스택을 init --stack X로 강제해도 그 선택이 어디에도 저장되지 않았습니다. 그래서 doctor가 감지 스택으로 다시 렌더해 stack 관리 절을 stale로 잘못 경고했고, 그 처방(harness-team init)을 따르면 강제한 스택이 감지 스택으로 조용히 되돌아갔습니다. 이제 강제한 스택은 .harness/render-state.json에 고정되고, harness-team stack이 그 고정을 보여 줍니다.

Fixed · #111

강제한 스택을 render-state에 고정한다

원인
관리 절 렌더 입력 중 강제 스택만 디스크에서 다시 얻을 수 없는 값인데 저장되지 않았습니다. doctor의 stale 검사·migrate의 관리 절 백업 diff·플래그 없는 init이 모두 감지 스택으로 렌더했습니다.
지금
감지와 다른 --stack은 .harness/render-state.json의 stack 필드에 저장되고, 세 경로가 같은 유효 스택으로 렌더합니다. 플래그 없는 init은 — pinned by an earlier --stack을 함께 출력합니다.
해제
감지된 id를 다시 주면(--stack node 등) 고정이 풀립니다. 모르는 id(손 편집·오타)는 무시합니다. 필드가 없는 기존 설치본은 동작 불변입니다.
Added · #113

harness-team stack이 고정 스택을 보여 준다

원인
관리 절은 고정 스택으로 렌더되는데 stack 출력은 감지 스택만 말해, 사람이 둘의 차이를 볼 방법이 없었습니다.
지금
고정이 있으면 text에 pin: <고정> (detected: <감지> → effective: <고정>) — unpin: <해제 명령> 줄이, --json에 stackPin({ pinned, detected, effective, unpin }, 고정 없으면 null)이 나옵니다.
유지
기존 필드와 고정 없는 설치본의 출력은 그대로입니다.
Guard · #114

overview 배지·🆕 배너·footer, what-changes footer, 문서 허브 목록에 가드가 없어 overview 배지가 두 세대, 시뮬레이션 footer가 17릴리스 밀린 채 발행된 적이 있습니다.
지금
docs/ 최상위 HTML을 스냅샷·"기준" 라벨·현행·무버전으로 결정론적으로 분류하고, 현행 문서의 표지를 package.json 버전과 대조합니다. 등록도 명시 제외도 없는 새 현행 문서는 실패합니다.

표지의 번호만 봅니다 — 배너 산문이 릴리스를 제대로 설명하는지는 사람이 봅니다. harness-workflow-simulation.html은 본문 현행화가 먼저라 사유와 함께 제외했습니다.
