모든 현행 문서가
같은 종결 흐름을 가르칩니다

0.58.0에서 종결은 계산값이 됐습니다. ship 뒤 같은 브랜치에서 done을 돌리고, 머지가 곧 종결입니다. 그런데 task 가이드를 비롯한 현행 문서 9개는 여전히 "머지 뒤 기본 브랜치에서 done + 종결 커밋"을 가르치고 있었습니다. 0.58.2는 그 문서들을 모두 새 흐름으로 고치고 옛 문구를 회귀 테스트에 등록합니다. 팀 온보딩 덱도 새로 싣습니다.

왜 patch인가 — ② 문서가 틀린 사실을 말했다

사람이 그 문서대로 하면 종결 커밋을 하나 더 만들거나, 머지 뒤에 done을 돌리려다 이미 종결된 task를 다시 열 수 있습니다. MAINTAINING.md의 기준에서 "② 소비자 문서가 틀린 사실을 말함"은 patch로 바로 발행합니다.

문서 정정 — 종결은 머지 전에 준비한다

Fixed · #200

9개 현행 문서의 종결 순서

전
PR이 머지된 뒤 기본 브랜치에서 done을 돌리고 종결 커밋을 하나 만든다.
후
ship 뒤 같은 브랜치에서 plan 마지막 단계 "ship 완료"를 체크 → done(가드만, 추적 파일 안 씀) → 커밋 → push → PR → 머지 = 종결. 머지 뒤 종결 커밋은 없습니다.
Fixed · #200

task 가이드의 빠진 단계

무엇
0.57.0의 구현 전 사람 검토 게이트(plan 첫 단계 [사람] spec 검토 승인, harness-team brief)와 0.58.0의 reopen을 가이드에 넣었습니다.
재발 방지. "머지 후 done"·"종결 커밋 하나" 같은 문구 14개를 tests/docs-retired-phrases.json에 등록했습니다. 현행 문서에 다시 나타나면 npm test가 파일과 대체 표현을 알려 주며 실패합니다. 이력 문서와 릴리스 배너는 제외합니다.
