Added · #203

설계 슬라이드 뒤의 그림 슬라이드

무엇
활성 task에 <name>-diagram-<view>.svg가 있고 diagram record --view와 같은 자립성 검사를 통과하면, sequence → module 순서로 그림 슬라이드를 만들어 ## 설계 절의 마지막 슬라이드 뒤에 넣습니다. 설계 절이 없으면 마지막 spec 절 뒤입니다. 슬라이드는 data URI <img> 하나이고, 보이는 글자는 붙이지 않습니다. 경로는 alt에만 둡니다.
왜
구현 전 사람 검토 게이트에서 검토자가 슬라이드와 SVG를 따로 열어야 했습니다. <img>로 실으면 SVG 안의 스크립트가 돌지 않고 <style>·id·텍스트가 문서로 새지 않습니다. 그래서 brief의 "새 사실 0·script 0·외부 자산 0·결정론" 계약이 그대로 유지됩니다.
보고
콘솔에 뷰 SVG: sequence 실림 · module 없음 같은 한 줄을, --json에 diagrams(view·path·status embedded|missing|rejected·violations)를 냅니다. 파일이 없거나, 위반이거나, 읽을 수 없으면 그 뷰만 빼고 brief는 성공합니다.
호환 · #203

인자 하나 renderBrief(spec)는 0.58.4와 같은 바이트

무엇
뷰는 선택 두 번째 인자 { diagrams: [{ view, rel, svg }] }로만 받습니다. 그림용 CSS도 뷰가 실릴 때만 <style> 끝에 덧붙입니다. 파일 읽기와 자립성 판정은 runBrief가 맡고, renderBrief는 순수 함수로 남습니다.
왜
renderBrief를 직접 import하는 다운스트림 래퍼는 module 뷰를 이미 <img>로 넣고 있습니다. 인자 하나 호출의 출력이 바뀌면 그림이 두 번 실립니다.
확인
저장소의 spec 198개를 옛·새 모듈로 렌더해 cmp로 바이트가 같음을 확인했습니다. 테스트는 fixture 출력의 sha256을 고정합니다.
제외
레거시 <name>-diagram.html은 script가 있을 수 있는 HTML이라 싣지 않습니다. spec 절이 하나도 없으면 뷰가 있어도 "렌더할 절이 없음" 오류입니다 — 슬라이드의 사실은 spec에서 옵니다.

더 엄격한 뷰 SVG 검사

아래 두 변경은 모두 svgSelfContainmentViolations 한 함수에 들어갔습니다. 호출부 코드는 그대로이고 세 호출부가 함께 엄격해집니다 — diagram record --view는 exit 1로 거부하고, brief는 그 뷰를 rejected로 빼며, pr-check는 PR 본문 링크 안내 대신 "자립형이 아님"을 알립니다.

Changed · #205

태그 짝이 어긋난 SVG를 거부한다

무엇
요소 태그의 여닫이 짝 어긋남(<g><rect></g></rect>), 닫히지 않은 요소, 루트 </svg> 뒤의 내용, 태그로 읽히지 않는 맨 <를 위반 하나(태그 구조: …)로 냅니다. 주석·CDATA·PI는 건너뛰고, 이름은 대소문자를 그대로 비교합니다(XML).
왜
짝이 어긋난 SVG는 이미지로 그려지지 않는데도 검사를 통과했습니다. diagram record --view는 생성으로 기록했고, brief는 깨진 그림을 embedded로 실었습니다(#203 codex 리뷰 P2). 그때 brief 범위 밖이라 후속으로 남긴 것을 이번에 닫았습니다.
한계
완전한 XML 검사는 아닙니다. 속성 따옴표·중복 속성·엔티티 유효성·맨 &·따옴표 속성값 안의 <는 보지 않습니다. 파서 없는 문자열 검사라 결정론이고 의존성이 없습니다. >를 빠뜨린 태그가 다음 태그를 속성으로 삼키지 않도록, 속성 이름과 따옴표 없는 값에서 <를 받지 않습니다.
Changed · #205

스크립트 우회 세 갈래를 막는다

무엇
지금까지 통과하던 세 표본이 위반이 됩니다. ① DOCTYPE 내부 subset 선언(<!ENTITY·<!ATTLIST·<!ELEMENT·<!NOTATION). ② _나 ASCII 밖 글자로 시작하는 요소의 이벤트 속성(<_x onclick=…>). ③ SMIL <set>·<animate>의 attributeName이 on…이나 href인 것(xlink:href·xlink:href:x·문자 참조 포함).
왜
①의 <!ATTLIST rect onclick CDATA "x()"> 기본값은 Blink·WebKit에서 실제 속성으로 붙어 핸들러가 돌았습니다(Gecko는 소스로 확인). ②는 알 수 없는 요소도 SVG 이름공간이면 핸들러를 가지는데, 규칙이 이름 첫 글자를 [a-z]로 묶어 놓쳤습니다. ③의 on… 애니메이션은 지금 엔진에서 돌지 않습니다. 하지만 href 애니메이션은 실제로 값을 바꿔 javascript:로 이동하고, href=가 없어 외부 href 규칙을 비켜 갔습니다.
범위
<img>로 싣는 brief에서는 스크립트가 돌지 않으므로, 실제 위험은 SVG를 브라우저 탭이나 raw 링크로 직접 연 경우였습니다. opacity·fill 같은 SMIL과 PUBLIC DOCTYPE은 그대로 통과합니다.
문구
옛 DTD 엔티티 선언 규칙을 흡수해, 위반 문구가 DTD 내부 subset 선언: <!…로 바뀝니다.

Fixed · #205

긴 공백에서 멈추던 검사

무엇
루트가 닫혔는지 보려고 끝의 공백·주석을 걷던 정규식 (?:\s+|<!--…-->)*$가 공백 덩어리마다 지수로 되짚었습니다. 공백 26칸 한 덩어리에 약 0.5초, 30칸이면 수 초가 걸려, 들여쓰기 깊은 정상 SVG에서 세 명령이 멈출 수 있었습니다. 뒤에서부터 걷는 루프로 바꿔 선형 시간이 됐습니다.
함께
같은 정규식이 루트 안 주석부터 </svg> 뒤 주석까지를 한 주석으로 걷어서, 둘 다 있는 정상 SVG를 "루트 닫히지 않음"으로 거부했습니다. 이것도 함께 고쳐졌습니다.
같은 부류
새 SMIL attributeName 규칙도 리뷰에서 2차 되짚기가 나와 머지 전에 고쳤습니다. 긴 공백과 공백 없이 이어 쓴 attributeName= 모두 선형 시간 테스트가 있습니다.
Fixed · #205

문자 참조 뒤의 이벤트 핸들러

무엇
이벤트 핸들러 속성을 문자 참조를 풀기 전 원문에서 찾습니다.
왜
XML은 속성 이름과 따옴표 구조의 문자 참조를 풀지 않는데, 이 규칙만 푼 글에서 찾았습니다. 그래서 aria-label="say &#34;hi&#34;" onclick="x()"의 진짜 핸들러를 놓쳤고, title="&#34; onclick=&#34;x()"의 글자를 핸들러로 잘못 거부했습니다.
그대로
외부 참조·@import 규칙은 계속 푼 글에서 찾습니다. 속성 값과 텍스트에서는 XML도 문자 참조를 풀기 때문입니다. 스크립트 요소·foreignObject 규칙도 푼 글을 보는데, 이쪽은 보수적으로 더 거부하는 방향입니다(<text>&#60;script&#62;</text>도 거부).
