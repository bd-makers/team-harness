BREAKING · #179

훅은 gitignore된 user handoff만 렌더한다

무엇
훅이 <name>-handoff.md에 append하지 않습니다. 쓰는 것은 gitignore된 <user>-handoff.md 하나이고, 그 파일이 추적 중이거나 무시 줄이 없는 저장소에서는 그것도 쓰지 않습니다.
왜
커밋마다 추적 파일이 바뀌면 트리가 늘 더럽고, done·scope 판정과 handoff 단독 커밋 규범이 그 부산물을 처리하느라 복잡해졌습니다. 부산물을 규범으로 관리하는 대신 만들지 않는 쪽을 택했습니다.
효과
커밋 직후 트리가 깨끗합니다. task handoff는 task가 계속 만들지만 이제 다음 세션에 남길 말을 직접 쓰는 선택 메모입니다.
BREAKING · D11 정정

필수 문서는 spec·plan·artifact

pr-check
PR이 건드린 task마다 spec·plan·artifact만 요구합니다. handoff가 없거나 템플릿 그대로여도 막지 않습니다.
done
handoff에 완료 마커를 쓰지 않습니다. 완료 표지는 meta.json의 status·closedAt입니다. meta 없는 옛 task의 마커는 계속 읽습니다.
임시 유지
미커밋 task handoff는 done과 scope 판정에서 계속 뺍니다. 옛 CLI의 훅이 아직 쓰는 설치에서 막으면 handoff 단독 커밋을 강요하기 때문입니다. 제거 조건: 옛 훅을 쓰는 설치가 없다고 판단되는 릴리스.

done 보장 범위 줄에 정보 항목

Added · #181

리뷰 증거·커밋 게이트 유무를 보인다

이제
줄 끝에 정보: 리뷰 증거 있음|없음 · 커밋 게이트 .harness/gates.json 있음|없음이 붙습니다. 차단하지 않습니다.
왜
리뷰를 선언하지 않은 task가 증거 없이 닫히는 것과, 커밋 게이트가 없어 테스트가 어디서도 돌지 않는 것을 종결 시점에 보이기 위해서입니다.

무엇
