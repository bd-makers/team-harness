왜 minor인가 — CLI에 새 명령이 생겼다

MAINTAINING.md의 크기 기준에서 ① 표면(CLI·명령 문서)에 기능이 더해지면 minor입니다. 기존 명령의 동작은 바뀌지 않았고, task가 새로 만드는 meta에 키 하나가 늘었을 뿐입니다.

표면경로도달 경로소비자 영향
CLIsrc/commands/clean.mjs·cli-args.mjs·bin/harness-team.mjs플러그인 갱신 + PATH CLI(clone) 갱신harness-team clean 추가, task clean은 예약 이름
task metasrc/commands/task.mjs·summary.mjs같음새로 만드는 task의 meta에 baseSha
명령 문서commands/harness-task.md플러그인 갱신/harness-task clean 절과 에이전트 --yes 규칙
관리 절·템플릿templates/**—바뀌지 않음 — init --yes 불필요

harness-team clean [<name>] [--base <ref>] [--yes]

기본은 dry-run

무엇
인자 없이 부르면 활성 task를 대상으로 시작점·버릴 커밋·버릴 미커밋·untracked 목록만 보여 주고 아무것도 쓰지 않습니다. --yes일 때만 실행합니다.
왜
reset --hard를 포함하는 조작이라, 지울 범위를 사람이 먼저 보는 것이 기본이어야 합니다. 에이전트는 dry-run 목록을 사용자에게 보여 주고 그 목록에 대한 명시적 승인 뒤에만 --yes를 붙입니다. 일반적인 "진행해"는 승인이 아닙니다.
Added · #183

백업 ref를 남기고 되돌린다

백업
실행 직전 상태를 stash 모양 커밋(첫 부모 HEAD, 둘째 부모 실제 인덱스, 트리 = untracked 포함·ignored 제외 작업 트리)으로 refs/harness/trash/<user>/<task>/<ts>에 남기고 복구 명령을 출력합니다.
되돌리기
reset --hard <시작점> 뒤 백업 시점의 untracked 목록만 지웁니다. git clean을 쓰지 않으므로 .gitignore가 되돌아가도 ignored 였던 파일은 남습니다. 활성 포인터가 이 task를 가리키면 비웁니다.
원격
쓰지 않습니다. upstream이 있으면 브랜치 삭제나 --force-with-lease 명령을 안내만 합니다.

거부 가드 — 남의 것과 끝난 것은 건드리지 않는다

상황결과
기본 브랜치·detached HEAD·git 아님·unborn HEADexit 1, 아무것도 쓰지 않음
done된 task(meta 없는 옛 task 포함)거부 — 머지된 변경은 git revert
reopen된 task에 --base 없음거부 — 시작점이 모호합니다
baseSha가 HEAD의 조상이 아님(rebase 등)거부 — --base를 안내
범위가 다른 task 폴더를 건드림거부 — rename·index flag(assume-unchanged·skip-worktree)에 숨은 경로도 저장소 전역에서 찾습니다

task meta에 baseSha

Added · #183

시작점은 생성 시점 HEAD

무엇
task <name>이 새 task를 만들 때 그 시점 HEAD를 meta의 baseSha에 한 번 기록합니다. 재활성화·reopen은 바꾸지 않습니다.
시작점 순서
--base <ref>(그 ref와의 merge-base) → baseSha → 둘 다 없는 옛 task는 기본 브랜치와의 merge-base.
효과
0.56.0 전에 만든 task도 clean할 수 있습니다 — merge-base로 대신합니다.

바뀌지 않은 것

항목0.56.0
task 상태(open/done)와 원장그대로 — clean은 상태도 원장 행도 남기지 않습니다
기존 명령의 동작·exit 코드그대로
백업 ref 만료자동 정리 없음 — git update-ref -d로 직접 지웁니다
