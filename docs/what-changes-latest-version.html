구현 전 사람 검토 게이트

Changed default · #191

새 plan의 첫 단계는 [사람] spec 검토 승인

무엇
harness-team task <새 이름>이 ## 단계 맨 위에 - [ ] [사람] spec 검토 승인 — <user>를 넣고 review gate: 줄을 출력합니다. --no-review-gate를 주면 넣지 않습니다. 기존 task는 바뀌지 않습니다.
왜
에이전트가 spec을 쓰자마자 구현으로 넘어가면, 사람이 의도와 다른 점을 발견하는 시점이 PR 리뷰로 밀립니다. 사이클 S2의 "개발자 확인"을 plan 체크박스로 남겨, 승인이 있었는지가 기록에 남습니다.
강제
커밋·쓰기 차단은 없습니다. 에이전트는 명시적 승인 뒤에만 [x]를 켜고 artifact에 - 검토 승인: <날짜> · 슬라이드 <경로|없음>을 남깁니다. 켜지 않으면 done 가드가 미완 체크박스로 막습니다(늦은 안전망).
Changed · #191

루프도 게이트에서 멈춘다

loop
/harness-loop는 다음 미완 단계가 [사람] 단계면 진입하지 않고, 진행 중에 그 단계를 만나면 "승인 필요"로 멈춥니다. Dev와 오케스트레이터 모두 그 단계를 켜지 않습니다.
질문
생성 직후 질문 하나(multiSelect)로 다이어그램 뷰와 "게이트 빼기"를 함께 묻습니다.
pr-check
게이트 줄을 빼고 "비어 있음"·"템플릿 그대로"를 판정하므로, 손대지 않은 plan이 게이트 줄 하나 때문에 통과하지 않습니다.

harness-team brief — spec에서만 뽑는 검토 슬라이드

Added · #193

새 사실 0인 결정론 렌더러

무엇
활성 task spec의 목적·범위·원천 검토 발견·설계·Ontology, 열린 항목, Done evidence scenarios를 그대로 렌더해 <name>-brief.html을 씁니다. script와 외부 자산이 없는 한 파일이며, 실행할 때마다 덮어씁니다.
왜
검토하는 사람이 마크다운 원문을 처음부터 끝까지 읽지 않아도 빠르게 훑을 수 있어야 합니다. 에이전트가 요약하면 spec에 없는 내용이 섞이므로, 렌더 결과의 모든 텍스트가 spec 원문의 부분 문자열이 되도록 했습니다.
쓰임
게이트 절이 spec을 보여 줄 때 부르고, 그 경로를 artifact 검토 승인 줄의 슬라이드 칸에 적습니다. 브리프는 검토 시점의 스냅샷으로 커밋합니다.

리뷰 엔진과 모델을 나눈다

Added · #186

review --model <id>와 프로필

무엇
review codex|claude --model <id>는 모델 id를 엔진 CLI에 넘깁니다(codex에는 -m, claude에는 --model). .harness/reviewers.json에 profiles와 default를 둘 수 있고, 엔진은 위치 인자 > task 프로필 > default > probe 체인 순으로 정합니다.
왜
지금까지는 엔진만 고를 수 있어 같은 엔진의 더 강한 모델로 리뷰를 돌릴 방법이 없었습니다. 팀 기본 리뷰어를 저장소 설정으로 고정하는 방법도 없었습니다.
기록
새로 쌓이는 meta.reviews[] 항목에 model이 붙고, artifact engine 줄에는 · model: <id|default>가 붙습니다. 리뷰 마커, kind, verify 판정은 바뀌지 않습니다.
호환 주의

spec에 reviewer를 쓰면 팀 전원 0.57.0+

무엇
task <새 이름> --reviewer <profile>은 spec Done evidence에 "reviewer" 키를 씁니다.
왜
옛 CLI의 Done evidence 파서는 모르는 키를 거부합니다. 그래서 옛 CLI로 done을 하면 알 수 없는 키: reviewer(invalid)로 막힙니다.

뷰별 다이어그램은 단독 SVG

Added · #188

뷰마다 파일 하나, plan 단계 하나

무엇
sequence(시간 순 상호작용)와 module(구성요소·의존)을 각각 <name>-diagram-<view>.svg로 그립니다. diagram record --view는 그 뷰의 파일, plan 단계, artifact 줄만 다룹니다.
왜
한 장에 시간 흐름과 구조를 같이 넣으면 둘 다 읽기 어렵습니다.
호환
레거시 <name>-diagram.html과 --view 없는 record는 예전 그대로 동작합니다. 뷰 단계를 쓰는 plan은 팀 전원이 0.57.0 이상이어야 합니다. 옛 CLI의 record는 뷰 단계를 레거시 단계로 닫아 버립니다.
Added · #190

PR 리뷰어가 이미지로 본다

무엇
record --view가 SVG의 자립성을 결정론적으로 검사합니다. script, 이벤트 속성, foreignObject, 외부 href·url(), @import, DTD 엔티티가 있으면 exit 1이고 아무것도 쓰지 않습니다.
왜
HTML 다이어그램은 PR/MR 화면에서 바로 보이지 않습니다. 자립형 SVG는 이미지로 렌더되지만, 외부 자산이나 스크립트가 섞이면 깨지거나 차단됩니다.
pr-check
뷰 SVG마다 · PR 본문에 링크: <path>.svg를 안내합니다. 막지는 않습니다.

spec 외부 질의 마커

Changed · #185

(ask:<역할>) → (asked:…) → (answered …) → 삭제

무엇
다른 역할(기획·디자인·백엔드 등)에게 물어야 하는 질문의 상태를 spec에 적습니다. 세 상태 모두 /harness-interview 게이트를 통과하지 못하고, 답을 spec에 반영하면 마커를 지웁니다.
왜
지금까지는 남에게 물어야 하는 질문도 (open)으로만 적었습니다. 그래서 누구에게 물었는지, 답을 기다리는 중인지 spec만 봐서는 알 수 없었습니다.
범위
하네스는 이 질문을 어디에도 게시하지 않습니다. /harness-spec이 남은 마커를 역할별로 묶어 보여 줄 뿐입니다.
