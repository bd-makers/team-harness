0.49.3 릴리스 노트는 알려진 한계 두 가지를 남겼습니다 — diff-failed의 원인 문장이 git의 실패 사유 대신 실행한 명령줄을 싣는다는 것, 그리고 pre-push 훅이 기본 브랜치와 무관한 히스토리의 브랜치를 push하면 오류 패킷 없이 스택 트레이스로 막힌다는 것. 0.49.4는 그 둘을 닫습니다. 후자에 쓰던 git push --no-verify 우회는 더 필요하지 않습니다.

Fixed · #146 · 후속 22번

원인 문장이 사유를 잃고 절대경로를 실었다

이전
원인을 오류 메시지 첫 줄로 만들었는데, 그 줄은 Command failed: git -C <절대경로> diff --stat <base>...HEAD입니다. git의 사유는 둘째 줄 이후라 잘렸고, 저장소 절대경로가 envelope에 실렸습니다.
지금
git이 stderr에 남긴 마지막 fatal:·error: 줄을 싣습니다(예: diff 계산 실패: fatal: <base>...HEAD: no merge base). 그런 줄이 없으면 마지막 비어 있지 않은 줄, stderr가 비면 종전 첫 줄로 떨어집니다.
왜 "마지막"
커밋 없는 HEAD처럼 사유 뒤에 사용법 안내가 붙는 경우가 있어, 단순히 마지막 줄을 쓰면 사용법 안내가 실립니다.
Note

로케일은 그 호출에만 C로 고정

무엇
fatal: 접두로 사유 줄을 고르므로, git 메시지가 번역되면 찾지 못합니다. 그래서 diff 계산과 pre-push의 공통 조상 판정 호출만 LC_ALL=C로 부릅니다.
범위
다른 git 호출의 환경은 그대로입니다. 접두 diff 계산 실패:·retry: 안내·exit code·envelope 형태도 그대로입니다.

pre-push — PR을 열 수 없는 브랜치는 검사하지 않는다

기본 브랜치와 공통 조상이 없는 브랜치는 그 기본 브랜치로 PR을 열 수 없습니다(GitHub이 비교를 거부합니다). 그래서 D11(PR 필수 task 문서)의 대상이 아니고, 기본 브랜치 push처럼 건너뜁니다. 갈래는 무엇을 체크아웃했느냐로 나뉩니다.

상황0.49.30.49.4
관련 브랜치를 체크아웃한 채 gh-pages 같은 무관한 브랜치를 push오류 패킷 없이 스택 트레이스 · exit 1 (--json도 envelope 없음)검사하지 않고 통과
같은 push에 관련 브랜치도 함께위와 같이 죽음관련 브랜치는 그대로 검사 — 문서가 빠졌으면 막힘
무관한 브랜치를 체크아웃한 채 pushdiff-failed 패킷 — 공통 조상이 있는 브랜치를 체크아웃한 뒤 다시 push 안내그대로(원인 문장만 git의 사유로 바뀜). 훅은 체크아웃된 HEAD로 base를 판정하기 때문이며, 의도한 범위입니다
수동 harness-team pr-check—그대로
건너뛰는 조건은 좁습니다. git merge-base가 exit 1(공통 조상 없음)을 돌려줄 때만 건너뜁니다. 그 밖의 실패(exit 128 등)는 삼키지 않고 종전대로 실패로 남습니다 — 판정하지 못한 브랜치를 조용히 통과시키지 않기 위해서입니다.
