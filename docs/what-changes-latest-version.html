scope 오류가
원인에 맞는 다음 행동을 알려 줍니다

harness-team review·scope·pr-check는 base·scope를 판정하지 못하면 오류 패킷의 retry:(와 alternatives:)로 다음 행동을 안내합니다. 그런데 그 안내는 원인과 무관한 한 문장이었습니다 — --scope worktree --base <없는 ref>에 이미 준 --scope worktree를 다시 권하고, 없는 --base·git 저장소 아님·merge-base 없음에도 git remote set-head origin -a를 권했습니다. 따라 해도 같은 오류가 납니다. 0.49.3은 안내를 원인 종류로 고릅니다.

왜 patch인가 — 안내를 따르면 같은 오류가 났다

명령·플래그·판정 규칙은 그대로입니다. 바뀐 것은 오류일 때 내는 안내 문장뿐입니다. 하지만 이 안내는 사람만 읽는 문장이 아니라 에이전트가 그대로 실행하는 다음 행동이라, 틀린 안내는 같은 실패를 되풀이시킵니다.

Fixed · #144

scope의 대안 줄은 기본 base 실패에만

원인
harness-team scope는 모든 오류에 git remote -v·git symbolic-ref refs/remotes/origin/HEAD 확인을 대안으로 냈습니다. 원격 설정과 무관한 원인에도 나왔습니다.
지금
default-base에만 남고, 나머지 세 종류는 alternatives가 빈 배열이라 text 출력에서 alternatives: 줄이 나오지 않습니다.
Fixed · #144

pre-push 훅은 --base를 줄 수 없다

default-base
종전대로 git remote set-head origin -a 후 다시 push.
diff-failed
gh-pages 같은 orphan 브랜치를 체크아웃한 채 push하면 닿습니다. 훅은 체크아웃된 HEAD로 base를 판정하므로 기본 브랜치와 공통 조상이 있는 브랜치를 체크아웃한 뒤 다시 push하라고 안내합니다.
우회
git push --no-verify 대안 줄은 그대로입니다.

바뀌지 않은 것과 알려진 한계

항목0.49.3
원인 문자열(root_cause)그대로
exit code · pr-check 차단 여부그대로 — 판정하지 못한 base로는 여전히 통과시키지 않습니다(D11)
--json envelope 형태그대로 — errorKind는 출력에 싣지 않습니다
알려진 한계 두 가지는 후속 후보로 남겼습니다(docs/followups.md 22·23번). diff-failed의 원인 문자열은 git의 실패 사유 대신 실행한 명령줄을 싣습니다(22번). pre-push의 diff-failed 안내는 HEAD가 기본 브랜치와 무관할 때만 덮습니다 — HEAD는 관련 있는 채 무관한 히스토리의 브랜치를 push하면 오류 패킷 없이 스택 트레이스와 exit 1로 막힙니다(23번). 그때는 git push --no-verify로 우회합니다.
