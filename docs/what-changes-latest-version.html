왜 minor인가 wiki sources --all 활성 task 없음 안내 바뀌지 않은 것 소비자가 할 일
Release note · 2026-10-12 · minor

이미 done 된 task 중
무엇을 소급 컴파일할지 한 번에 봅니다

위키 컴파일(/harness-wiki)은 머지 후 종결에서 done 다음에 도는 선택 단계라, 건너뛴 task가 쌓입니다. 그런데 그것들을 나중에 찾을 길이 없었습니다 — 기본 브랜치에는 활성 task가 없어 인수 없는 wiki sources는 "활성 task 없음"으로 끝났고, list는 done·컴파일 여부를 보이지 않아 task를 하나씩 지정해 봐야 했습니다. 0.50.0은 harness-team wiki sources --all을 더해 task 전체를 한 번에 훑고, task마다 컴파일 가능·이미 컴파일됨·막힘을 보입니다.

왜 minor인가 — CLI 표면에 플래그가 하나 늘었다

wiki sources에 --all이라는 새 입력과 새 출력 형태(tasks 배열)가 생겼습니다. 기존 형태(wiki sources [<user>/<task>] [--pr <N>])의 동작·출력은 그대로이고, 제거된 명령·플래그는 없습니다. 기능 추가라 minor입니다.

wiki sources --all — 소급 컴파일 후보 목록

task 전체(list와 같은 집합 — spec이 있는 task)를 라벨순으로 훑습니다. 판정은 단일 task 조회와 같은 함수(wikiSources)라 목록과 개별 조회가 갈라지지 않습니다.

Added · #148 · 후속 24번

task마다 세 상태 중 하나

상태
막힘(사유: not-done·no-commit·shallow-history) > 이미 컴파일됨(위키 파일 경로) > 컴파일 가능 순으로 하나를 고릅니다. 이 우선순위는 /harness-wiki 절차 순서(막힘 확인 → 중복 확인)와 같습니다.
출력
텍스트는 요약 한 줄(N개 task — 컴파일 가능 a · 이미 컴파일됨 b · 막힘 c)과 task별 한 줄. --json은 envelope의 tasks 배열에 { task, task_status, state, compiled, blockers }를 담습니다.
왜 출처는 없나
provenance·marker는 싣지 않습니다. 후보를 고른 뒤 wiki sources <user>/<task>로 다시 불러 그 task의 출처·마커를 받습니다.
exit
목록은 막힌 행이 있어도, 대상이 0건이어도 exit 0입니다 — 막힘은 행의 속성이지 명령의 실패가 아닙니다. 대상(<user>/<task>)·--pr과 함께 쓰면 usage 오류(exit 2)입니다.
Note

읽기 전용, wiki/는 한 번만 걷는다

무엇
파일을 쓰지 않습니다. 저장소 단위 값(얕은 클론 여부·컴파일 색인·wiki/90_system/ 규칙)은 한 번만 만들어 task마다 넘기므로, task 수만큼 wiki/를 다시 걷지 않습니다.
왜 wiki에
list에 붙이지 않았습니다 — list는 --json 계약이 없고, 위키 스캔·git 이력 읽기를 모든 task 목록에 결합하게 되며, wiki.mjs→task.mjs import와 순환합니다.

"활성 task 없음" 안내 — done task를 다시 열라고 권하지 않는다

항목0.49.40.50.0
retry:대상 지정 또는 harness-team task <name>으로 활성화대상 지정(wiki sources <user>/<task>)만
alternatives:없음wiki sources --all로 후보를 찾는다
exit code · 원인 문장exit 1그대로
왜 활성화 안내를 지웠나. 위키 컴파일 대상은 이미 done 된 task입니다. 그 task를 task <name>으로 활성화하면 reopen이 되어 meta·원장이 바뀌고, 다음 wiki sources 실행이 not-done으로 막힙니다 — 안내를 따르면 오히려 컴파일을 못 하게 되던 문장입니다.
