왜 patch로 끊었나 — 이월분의 발행

이 건은 0.40.0 시점에 이월 결정이 내려졌던 항목입니다. 그 판단을 뒤집는 것이 아니라, 예고한 대로 다음 릴리스에 실어 보내는 것입니다.

시점상태판단
0.40.0 발행 직후 harness-workflow-simulation.html이 ship의 base 사다리를 --base → origin/main → main으로 서술 — 0.40.0이 없앤 하드코딩 이월. 가른 것은 문서의 중요도가 아니라 ① 에이전트 행동 표면의 무결성이었다 — commands/·skills/·templates/에는 옛 규칙이 한 줄도 없었고, 틀린 문장은 사람이 읽는 워크스루 한 곳에만 있었다
수정 커밋 사다리를 다시 열거하지 않고 판정의 소유자(harness-team scope)를 가리키도록 교체 규칙을 가드 없는 곳에 복제하면 0.40.0이 방금 없앤 드리프트가 그대로 재발한다
0.40.1 (지금) [Unreleased]에 쌓여 있던 그 한 건 발행. 크기 기준표의 "② 문서만 — 사실이 틀린 것을 고침 = patch"

이 선례를 인용할 때 같이 확인할 것: 0.40.0에서 grep -rn 'origin/main' commands/ skills/ templates/가 ①에도 옛 규칙을 잡아냈다면 그때 바로 patch였습니다. "② 문서 수정은 언제나 미뤄도 된다"로 읽지 마세요.

고친 것

Fixed · docs

ship의 base 사다리를 산문이 하드코딩하던 것

무엇
ship 단계 설명이 base 결정을 --base → origin/main → main으로 적고 있었다. 0.40.0이 review의 같은 하드코딩을 고쳐 origin/HEAD → origin/main → origin/master 중 실재하는 것만 쓰도록 바꿨으므로, 이 문장은 발행 4시간 만에 거짓이 됐다.
어떻게
새 사다리를 산문에 다시 열거하지 않았다. harness-team scope를 판정의 소유자로 가리키게 했다 — 사다리가 또 바뀌어도 이 문서는 낡지 않는다.
함께
다이어그램 기록 한 줄도 harness-team diagram record --skipped <사유> 소유로 고쳤다(0.40.0이 추가한 명령, 사유 필수).
Fixed · docs

같은 파일의 footer가 17개 릴리스 밀려 있던 것

무엇
footer가 v0.23.0 (2026-08-30)에 머물러 있었다. 직전 현행화가 hero 배지와 🆕 배너 두 표면만 세고 footer를 빠뜨린 결과다.
교훈
이 파일의 버전 표면은 셋이다 — hero 배지 · 🆕 배너 · footer. harness-overview.template.html도 같은 셋이고, 둘 다 docs:check가 green이어도 낡는다. 결합 강도 순서를 기억할 것: what-changes-*(3방향 강제) > harness-overview(생성+pin, 산문은 무방비) > prerequisites.md(doctor 양방향) > index.html·simulation·guide류(가드 0).
스냅샷
hero 배지를 v0.40.0으로 올리고 🆕 배너에 0.40.0 그룹을 추가한 뒤, 관례대로 docs/harness-workflow-simulation-0.40.0.html을 만들고 docs/index.html에 등재했다. -0.39.1.html 스냅샷은 그 시점의 사실 기록이라 수정하지 않았다.

소비자가 할 일

Do

아무것도 하지 않아도 됩니다

왜
코드·커맨드 문서·templates/가 전부 그대로다. 바뀐 것은 docs/ 아래 사람이 읽는 HTML 한 건과 그 스냅샷뿐이며, init은 이 파일들을 프로젝트에 쓰지 않는다.
굳이 한다면
플러그인 갱신. 그러면 docs/harness-workflow-simulation.html을 열었을 때 ship 절이 harness-team scope를 가리킨다.
